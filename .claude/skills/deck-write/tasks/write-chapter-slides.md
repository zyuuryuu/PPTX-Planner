## 手順

### 工程7 スライド仕様の前文(`docs/stages/07-slide-spec.md`)

[目次に戻る](../../../../docs/README.md)

スライドごとに、載せる内容を確定する。章ごと(長い章は節ごと)に1ファイルに分け、それぞれ別の執筆のセッションが書く。進め方は[体制とセッション](../../../../docs/organization.md)に定める。

上流の工程で、題、要点、役割、限定、出どころ、主張の種類、見せるもの、注目させる点、使う事実、型、見本が決まっている。この工程で書くのは、型のデータ、説明、ノートである。文の書き方と検査は、[文章の書き方](../../../../docs/writing.md)に定める。

### 成果物(`docs/stages/07-slide-spec.md`)

`07-slides/ch2.yaml`(章ごとのスライド仕様):

```yaml
- id: ch2-s1
  status: done               # done(書き終えた) / blocked(保留。Issueの番号を添える)
  title: △△領域の年ごとの市場規模               # 題
  point: △△の領域の市場規模は、5年続けて前の年を上回った   # 要点
  qualifiers: [国内]         # 限定
  provenance: cited          # 出どころ。ストーリーラインにある場合
  body:
    type: line-chart
    data: {...}
    highlight: series-target  # 強調する要素。立証設計の注目させる点に対応する
  text: 国内市場の{F040}を占めるまでに拡大した。集計の方法は「{ch2-s2}」に示す   # 数値は事実のID、別のスライドはスライドのIDで参照する
  sources: [F015, F016, F040]
  notes: 口頭で補う説明
```

`title`、`point`、`point_from`、`role`、`qualifiers`、`provenance` は、ストーリーラインの通りに写す。

`text`、`body.data`、`notes` の数値は直接書かず、事実のIDで参照する。ビルドの際に台帳の値に置き換える。`point` は、ストーリーラインを人が読めるように数値を直接書いてよい。その数値は、そのスライドの `sources` の事実と一致させる。別のスライドへの言及は、スライドのIDで書く。ビルドの際に、そのスライドの題に置き換える([文章の書き方](../../../../docs/writing.md))。

要点は、ビルドが、資料の表現規約が型ごとに定める位置に1回だけ描く。`qualifiers` と `provenance` は、ビルドが、資料の型の定義の `annotation` が定める場所に描く。執筆のセッションは、これらを `text` や `body` に書き写さない。

画像の型のスライドでは、画像の素材と、注釈を付ける `regions` を参照する。位置は書かない。

```yaml
- id: ch5-s2
  status: done
  title: 納期の入力と保存
  point: 納期が空のまま保存すると、発注が止まる
  body:
    type: annotated-image-steps
    asset: A003
    crop: [due-date-field, save-button]   # この範囲が入るように切り抜く
    scenario: S-order-entry               # 番号は、場面の順から決まる
    captions:                             # 注釈の説明。スライドのノート(`notes`)とは別の項目
      due-date-field: 納期を入力する
      save-button: 保存を押す
  sources: [A003, F120]
```

### 2. スライド仕様を書く(`docs/stages/07-slide-spec.md`)

担当: 執筆のセッション。

1. 章の作業票と、型の見本を読む。作業票には、その章の前提と到達点が含まれる。前提にある語と主張は、説明済みとして使ってよい。到達点にある語と主張は、この章の中で説明し、示す。
2. スライドごとに、型のデータ、説明、ノートを書く。素材台帳にある事実のうち、立証設計がそのスライドに割り当てたものだけを使う。
3. 字数の上限に収まらないときは、[文章の書き方](../../../../docs/writing.md)の「収まらないときの順序」に従う。
4. 上流の成果物の問題に気づいたら、推測で埋めない。[体制とセッション](../../../../docs/organization.md)の「上流の問題の戻し方」に従う。
5. 書き終えたら、検査のコマンドを実行し、完了の報告を返す。

## 検査

### 満たす合格条件

成果物は、次の条件を満たす。括弧の中は、判定者である。「警告」とある条件は、合否にしない。

- `K07-02` `title`、`point`、`point_from`、`role`、`qualifiers`、`provenance` が、ストーリーラインと一致する(機械)。
- `K07-03` `body.type` が、表現の対応表が定める型と一致する(機械)。 [定義](../../../../docs/visual-grammar.md#c-一貫性)
- `K07-04` `sources` が立証設計の `facts` に含まれる(機械)。
- `K07-05` ストーリーラインで `contradiction` を持つスライドの `sources` が、その事実を含み、中身の文がその事実を述べている(機械と検査セッション)。
- `K07-06` 立証設計の `real` が true のスライドが、立証設計の `view` にある要素、つながり、場面だけを使う(機械)。
- `K07-07` 図や表を載せるスライドに、強調する要素(`highlight`)の指定がある(機械)。
- `K07-08` 強調が、1枚に1か所までである。数え方は[形が伝える意味](../../../../docs/visual-grammar.md)による(機械)。 [定義](../../../../docs/visual-grammar.md#e-注目)
- `K07-09` 強調する要素が、立証設計の注目させる点に対応する(検査セッション)。 [定義](../../../../docs/visual-grammar.md#e-注目)
- `K07-10` 章のブランチが、その章のスライド仕様以外のファイルを変えていない(機械)。
- `K07-11` `text`、`body.data`、`notes` に、事実のIDによらない数値がない(機械)。
- `K07-12` `point` の数値が、`sources` の事実の値と一致する(機械。単位と表記を正規化して照合する)。
- `K07-13` 裏付けのない文がない(検査セッション。重大な検査)。 [定義](../../../../docs/writing.md#検査セッションが判断するもの)
- `K07-14` 限定の残存の検査を通る(検査セッション。重大な検査)。 [定義](../../../../docs/writing.md#検査セッションが判断するもの)
- `K07-15` 読み戻しの検査を通る。対象のスライドに限る(検査セッション)。 [定義](../../../../docs/writing.md#検査セッションが判断するもの)
- `K07-16` 画像の型のスライドが参照する `regions` が、全て画像の素材にある(機械)。
- `K07-18` 注釈の印と説明が、指す対象に重なっていない(機械。`regions` の位置から判定する)。 [定義](../../../../docs/visual-grammar.md#d-知覚の限界)
- `K07-21` [文章の書き方](../../../../docs/writing.md)の機械で測る検査を通る(機械)。
- `K07-22` [使う語彙](../../../../docs/terms.md)の検査を通る(機械)。
- `K07-23` 型の項目ごとの収容量に収まる(機械)。 [定義](../../../../docs/visual-grammar.md#d-知覚の限界)
- `K07-24` `{}` で囲んだ参照が、全て、実在する事実かスライドを指す(機械)。
- `K07-25` 削る検査、重複の検査、主体の検査を通る(検査セッション)。 [定義](../../../../docs/writing.md#検査セッションが判断するもの)
- `K07-26` 言い直しの検査で挙がったスライドの全てに、前後のスライドに統合するか、残すかの判断がある(検査セッションが挙げ、設計セッションが決める)。統合する場合は、工程4に戻す。 [定義](../../../../docs/writing.md#検査セッションが判断するもの)
- `K07-27` ブリーフに「読み手が既に知っている」と書かれた内容の説明を含まない(検査セッション)。
- `K07-28` 型の `implies` が成り立つ中身になっている。立証設計の `holds` と食い違う中身を書いていない(検査セッション)。
- `K07-30` 複数のスライドに出る対象が、資料の表現規約の色の割り当ての通りに、同じ色と同じ名前で指定されている。図や表のデータは、対象を語彙表または仕組みの定義のIDで参照する(機械)。 [定義](../../../../docs/visual-grammar.md#c-一貫性)
- `K07-31` 色の割り当てのある色を、別の対象に使っていない。強調の色を、対象の色に使っていない(機械)。 [定義](../../../../docs/visual-grammar.md#c-一貫性)
- `K07-32` 並べて比べる、同じ種類の量を表す複数のグラフが、同じ軸の範囲を使う(機械)。 [定義](../../../../docs/visual-grammar.md#f-量の歪み)
- `K07-33` 棒グラフの量の軸が0から始まる。軸を2本持つグラフに理由がある。構成比の合計が100%になる(機械)。 [定義](../../../../docs/visual-grammar.md#f-量の歪み)
- `K07-34` 立体のグラフを使わない(機械。型の定義に置かない)。 [定義](../../../../docs/visual-grammar.md#f-量の歪み)
- `K07-35` 構成比を円で表すのは、項目が少ない場合に限る。項目の数の上限は型の収容量で定める(機械)。 [定義](../../../../docs/visual-grammar.md#f-量の歪み)
- `K07-36` アイコンが、仕組みの定義の要素に対応するものだけである(機械)。 [定義](../../../../docs/visual-grammar.md#g-飾り)
- `K07-37` 図の要素とつながりの数が型の収容量を超える場合は、警告とする(機械。警告)。 [定義](../../../../docs/visual-grammar.md#d-知覚の限界)
- `K07-38` 保留のスライドの全てに、Issueの番号がある(機械)。
- `KX-01` 1文の字数が、項目の種類ごとに定める上限以下である(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-02` 1文の読点の数が、上限以下である(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-03` 「の」の連続と、同じ助詞の重なりが、連続する回数の上限以下である(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-04` 漢字の連なりが、連続する字数の上限以下である(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-05` 辞書にある冗長な言い回しを含まない(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-06` 辞書にある、中身のない形容と強調を含まない(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-07` 辞書にある書き出しの決まり文句(「一言で言うと」「結論から言うと」「要するに」「端的に言えば」など)を含まない(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-08` 辞書にある、LLMに多い語を含まない(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-09` ぼかし(「など」「等」「といった」)の数が、上限以下である(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-10` 「また」「さらに」「加えて」で始まる文の割合が、上限以下である(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-11` 近い位置での同じ語の繰り返しの回数が、上限以下である(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-12` です・ます調と、である調が混在していない(機械)。 [定義](../../../../docs/writing.md#機械で測るもの)
- `KX-13` 題が名詞で終わる。句点がない。字数が上限以下である(機械)。 [定義](../../../../docs/writing.md#項目ごとの書き方)
- `KX-14` 要点が1文である。文末が「がわかる」「について」「すべき」でない。字数が、2行に収まる上限以下である(機械)。 [定義](../../../../docs/writing.md#項目ごとの書き方)
- `KX-15` 読み手に見せる文に、内部のIDがない。IDの書式に合う文字列が、`{}` で囲んだ参照のほかにない(機械)。 [定義](../../../../docs/writing.md#内部のid)
- `KX-16` 全角の数字と英字、半角の括弧と句読点、「表記」の決まりに合わない句点がない(機械)。 [定義](../../../../docs/writing.md#表記)
- `KX-17` 全ての文から、名詞と動作を指す語を機械的に抜き出し、語彙表、`allowed` と照合する。扱いは、上の「厳しさの段階」の表による(機械)。 [定義](../../../../docs/terms.md#厳しさの段階)
- `KX-18` `banned` の語を含まない(機械)。 [定義](../../../../docs/terms.md#厳しさの段階)
- `KX-19` 表記の揺れ(長音の有無、送り仮名、全角と半角)を、正規化して語彙表と照合する(機械)。 [定義](../../../../docs/terms.md)
