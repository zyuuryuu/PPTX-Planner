### 引き継ぎの検査(`docs/organization.md`)

製造の時期に入る前に行う。新しいセッションに成果物だけを読ませ、次を書かせる。置き場と書式は、検査の「独立に書く」による。

- 資料の結論、章の構成、各章の要点の、自分の言葉での説明。
- 作業を始めるうえで分からない点。

別の検査セッションが、書かれた説明を成果物と比べ、次を確かめる。設計セッションは比べない。

- 説明が、主張の骨子の `answer`、章構成の章の順と要点に合う。
- 設計の判断の記録にある却下した案を、再び提案していない。
- 分からない点が挙がっていない。

食い違いか、分からない点があれば、設計セッションが成果物を直す。

### 独立に書く(`docs/checks.md`)

担当: 検査セッション。

検査の中には、入力を限ったセッションに独立に書かせ、その答えを元の成果物と比べるものがある。書く作業と比べる作業は、別のセッションが行う。比べるのは、検査セッションである。元の成果物を書いたセッションは、どちらも行わない。

書く作業は、次の通りに行う。

1. 作業票の入力だけを読む。
2. 検査の条件の文が書かせるとしているものを書く。入力から分からないことは、分からないと書く。推測で埋めない。
3. 答えを `work/answers/<作業のid>.yaml` に置く。章ごとに行う作業では、`work/answers/<作業のid>-<章のID>.yaml` とする。
4. 合否を判定しない。検査の記録を書かない。合否は、比べる作業が判定する。

```yaml
- target: ch2-s1      # 何について書いたか。スライド、型などのID。対象が1つだけの作業では書かない
  answer: △△の領域の市場規模は、5年続けて前の年を上回った   # 書いた答え
```
