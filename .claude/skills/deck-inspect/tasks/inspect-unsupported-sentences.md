# `inspect-unsupported-sentences` 裏付けのない文がないかを検査する

道具 `tools/build_skills.py` が作ったファイルである。直接は直さない。正本は、工程表 `docs/tasks.yaml`、検査の台帳 `docs/checks.yaml`、`docs/` の文書である。直すときは、正本を直して、道具を実行する。

担当は検査セッション、工程は7である。

## 入力

- `07-slides/`
- `01-sources.yaml` の「そのスライドが使う事実」だけ

## 読まないもの

入力に挙げたもの以外を読まない。このファイルと、スキルの「守ること」は読む。正本の文書(`docs/`)は開かない。要る箇所は、このファイルに写してある。

ファイルをまるごと渡す入力は、次の定めによる。

### 検査セッションが判断するもの(`docs/writing.md`)

| 検査 | 方法 |
|---|---|
| 裏付けのない文 | スライド仕様と、そのスライドが使う事実だけを渡す。文を1つずつ、事実に裏付けられているかを判定する。「多くの企業が」「近年」のような根拠のない一般化も対象とする |
| 限定の残存 | スライドが使う事実の `qualifiers` が、全て、文かスライドの `qualifiers` に残っているかを照合する |
| 削る検査 | 文ごとに、消しても意味が変わらない語を全て挙げる。挙がった語のそれぞれについて、消すと主張が事実より強く、広く、または曖昧になるかを確かめる。ならないものだけを消す。消した後も、文として読めること |
| 重複の検査 | 同じスライドの中で、題、要点、説明、中身が同じことを繰り返していないか |
| 言い直しの検査 | 中身(型のデータと説明)が、題と要点の言い直しだけで、新しい情報を足していないスライドを挙げる。挙がったスライドは、前後のスライドに統合する候補として、設計セッションに渡す |
| 主体の検査 | 仕組みを述べる文で、動作の主体が書かれているか |
| 読み戻し | 経緯を知らない検査セッションにスライドの文だけを読ませ、意味を完全な文で書き直させる。素材台帳の事実と比べ、条件の脱落や主体の違いがないかを確かめる。対象は、仕組みの記述のスライドと、`qualifiers` を持つ事実を使うスライドとする |

検査に落ちた後の手順と、往復の上限は、不合格と修正の手順による。

## 手順

この作業では、「守ること」の表より、入力の制限が優先する。

### 重大な検査(`docs/checks.md`)

検査セッションの判定には見逃しがある。見逃したものが外に出ると実害が大きい検査を、重大な検査として指定し、2段で行う。

重大な検査は、台帳の `critical` で指定する。


| 工程 | 重大な検査 | ID |
|---|---|---|
| 1 | `fact` の `quote` が出典に実在する。`quote` の切り取り方が、出典の前後にある条件、範囲、主体を落としていない。落としている場合は、`quote` を広げる | `K01-08` |
| 1 | `fact` の `statement` が、`quote` の述べていることと合う。`qualifiers` が、`quote` にある条件、範囲、数量の幅、不確かさを漏れなく挙げている | `K01-10` |
| 1 | 写り込みの検査を通る。検査セッションには、ブリーフの「外に出せない情報」を渡す。個人の名前、顧客の情報、認証の情報、社外に出せない名称が、隠されずに写っていない | `K01-22` |
| 1 | 要素の1件ごとに、その要素が出典にあり、名前と種類が出典の記述と合う | `K01-25` |
| 1 | つながりの1件ごとに、向きと条件が出典の記述と合う | `K01-26` |
| 1 | 場面の1件ごとに、順序が出典の記述と合う | `K01-27` |
| 2 | 問いごとの答えが、根拠の事実の限定(`qualifiers`)を落としていない | `K02-04` |
| 2 | 各主張が、根拠の事実の限定を落としていない | `K02-11` |
| 2 | `summary` が、`answer` と主張より強いこと、広いことを述べていない。主張の限定を落としていない | `K02-22` |
| 3 | 章の要点が、割り当てた主張より強いこと、広いことを述べていない。`qualifiers` と合わせて、主張の限定を落としていない | `K03-08` |
| 3 | 節の要点が、`from` の答えより強いこと、広いことを述べていない。`qualifiers` と合わせて、答えの限定を落としていない | `K03-09` |
| 4 | 要点が、`qualifiers` と合わせて、根拠の事実の限定を落としていない | `K04-19` |
| 5 | `real` の申告が正しい。図が実在のものを写しているのに、false としていない | `K05-05` |
| 7 | 裏付けのない文がない | `K07-13` |
| 7 | 限定の残存の検査を通る | `K07-14` |
| 9 | 最終の出力に載っている全ての画像について、写り込みの検査をもう一度行う。ブリーフの「外に出せない情報」を渡す | `K09-02` |


- 重大な検査は、別のセッションで2回行う。2回目は、1回目と別のモデルで行う。モデルが違うと、見落とす箇所が違うためである。
- 2回の結果が食い違ったものは、設計の時期はユーザーが、製造の時期は設計セッションが見て決める。設計セッションが決められないものと、設計セッションが書いた成果物についてのものは、ユーザーに上げる。
- 工程9の抜き取りで誤りが見つかった場合は、その誤りを拾うはずだった重大な検査を、同じ章の全てのスライドでやり直す。見つかった割合が高い場合は、全ての章に広げる。割合の目安は、資料の表現規約に置く。
