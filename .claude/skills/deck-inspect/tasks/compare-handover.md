## 手順

### 検査セッションの手順(`docs/checks.md`)

担当: 検査セッション。

全ての検査に共通の手順である。

1. 作業票が挙げる検査の条件の文を、対象に1件ずつ当てる。条件ごと、対象ごとに判定し、まとめて判定しない。
2. 条件を満たすと言い切れなければ、不合格とする。
3. 合格にも、判定の根拠にした箇所を引用する。不合格に添えるものは、[不合格と修正の手順](../../../../docs/rework.md)の「不合格のときの手順」の1による。
4. 直し方を提案しない。対象を直さないことは、[体制とセッション](../../../../docs/organization.md)の「セッションの分離」と、[不合格と修正の手順](../../../../docs/rework.md)の「原則」による。
5. 結果を、検査の記録に書く。書式は、[不合格と修正の手順](../../../../docs/rework.md)の「検査の記録」に定める。

### 比べる(`docs/checks.md`)

担当: 検査セッション。

独立に書いたセッションとは別の検査セッションが行う。何と何を比べ、何を食い違いとするかは、各工程の文書の「検査の手順」に定める。

1. 独立に書いた答えと、元の成果物の該当する項目を、対象ごとに並べて読む。
2. 食い違いごとに、答えと元の両方を引用する。
3. どちらが正しいかを決めない。
4. 食い違いを示す相手は、検査の条件の文と、各工程の定めによる。定めがなければ、食い違いを不合格として扱う。

### 引き継ぎの検査(`docs/organization.md`)

製造の時期に入る前に行う。新しく起こしたPMに成果物だけを読ませ、次を確かめる。

- 資料の結論、章の構成、各章の要点を、自分の言葉で説明できる。
- 設計の判断の記録にある却下した案を、再び提案しない。
- 作業を始めるうえで分からない点がない。

### 説明を設計の成果物と比べる(`docs/organization.md`)

担当: 検査セッション。

PMの説明を、主張の骨子、章構成、設計の判断の記録と比べる。

- 結論、章の構成、章の要点が、成果物と違う場合を、食い違いとする。
- 変えたい点が、設計の判断の記録にある却下した案に当たる場合を、食い違いとする。
- 食い違いと、PMが挙げた分からない点を、設計セッションに示す。

## 成果物

- `checks/`(書式は、このファイルの「検査の記録」に定める)

### 検査の記録(`docs/rework.md`)

検査1回につき、1つのファイルを `checks/` に置く。ファイル名は「作業のid--対象--回.yaml」とする。

- 対象は、章ごとに行う検査では章のID、そのほかでは `all` と書く。
- 回は、同じ作業と対象について検査した回数で、1から数える。再検査は新しいファイルに書く。前の回のファイルは書き換えない。

```yaml
# checks/inspect-sources--all--1.yaml
task: inspect-sources        # 工程表の作業
target: 01-sources.yaml      # 対象
commit: 3f2a9c1              # 対象の版
round: 1                     # 何回目か
model: claude-sonnet-5-5     # 判定したモデル
results:
  - check: K01-14            # 検査の台帳のID
    item: F015               # 対象の中のどれか
    verdict: fail            # pass / fail
    quote: "市場規模は約1.5倍"
    reason: 出典は「2019年比で1.4倍」とあり、値が合わない
  - check: K01-14
    item: F016
    verdict: pass
    quote: "継続率は業界平均より15ポイント高い"
```

- 条件ごと、対象の中の1件ごとに、1行を書く。対象の全体に当てる条件では、`item` を書かない。
- `quote` は、判定の根拠にした箇所の引用である。合格の行にも書く。
- `reason` は、不合格の行に書く。条件のどの部分に反するかを書く。
- 警告の検査(台帳の `level` が `warning`)も、同じ形で書く。条件を満たさなければ `fail` と書く。合否にしないことは、台帳が決める。
- 比べる作業は、`quote` に元の成果物の箇所を引用し、`reason` に、独立に書いた答えの箇所と、食い違いを書く。
- 機械的な検査の記録は、`model` を持たない。
