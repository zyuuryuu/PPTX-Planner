入力に挙げたもの以外を読まない。このファイルと、スキルの「守ること」は読む。正本の文書(`docs/`)は開かない。要る箇所は、このファイルに写してある。
`restricted/derive-answer-independently/views/` にある入力は、機械が元のファイルから作った写しである。元のファイルを開かない。
入力にないファイルを、Gitの履歴からも、スクリプトからも取り出さない。
読めないファイルに当たったら、回避しない。作業票の入力で足りないと報告して終える。
人の許可を待つ表示が出る命令を使わない。人が見ていないので、表示が出ると止まる。ファイルの読み書きには、シェルの命令ではなく、ファイルを読む道具と書く道具を使う。

## 手順

この作業では、「守ること」の表より、入力の制限が優先する。

### 独立に書く(`docs/checks.md`)

担当: 検査セッション。

検査の中には、入力を限ったセッションに独立に書かせ、その答えを元の成果物と比べるものがある。書く作業と比べる作業は、別の検査セッションが行う。元の成果物を書いたセッションは、どちらも行わない。

書く作業は、次の通りに行う。

1. 作業票の入力だけを読む。
2. 検査の条件の文が書かせるとしているものを書く。入力から分からないことは、分からないと書く。推測で埋めない。
3. 答えを `work/answers/<作業のid>.yaml` に置く。章ごとに行う作業では、`work/answers/<作業のid>-<章のID>.yaml` とする。
4. 合否を判定しない。検査の記録を書かない。合否は、比べる作業が判定する。

```yaml
- target: ch2-s1      # 何について書いたか。スライド、型などのID。対象が1つだけの作業では書かない
  answer: △△の領域の市場規模は、5年続けて前の年を上回った   # 書いた答え
```
