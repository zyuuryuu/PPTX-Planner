### 成果物(`docs/model.md`)

`01-model.yaml`。工程1で作る。

```yaml
elements:
  - id: E-order
    kind: component          # component(部品) / actor(主体) / data(データ) / state(状態) など
    name: 注文サービス
    evidence: [F101]         # 素材台帳の事実
relations:
  - id: R-order-stock
    kind: call               # call(呼び出し) / send(送信) / contain(包含) / depend(依存) / transition(遷移) など
    from: E-order
    to: E-stock
    label: 在庫の確認
    mode: unknown            # 出典に書かれていない属性は unknown とする
    evidence: [F102]
  - id: R-web-db
    kind: call
    from: E-web
    to: E-db
    summarizes: [R-web-order, R-order-db]   # 間を省略したつながり。元のつながりを記録する
scenarios:
  - id: S-purchase
    name: 購入の処理
    steps: [R-web-order, R-order-stock, R-order-db]   # つながりを順に並べる
    evidence: [F110]         # 順序の出典
  - id: S-order-entry
    name: 注文の入力
    steps: [R-user-due-date, R-user-save]   # 画面の操作の手順
    evidence: [F120]
```

要素、つながり、場面の1件ごとに、素材台帳の事実を紐づける。事実の種類と確認の条件は、工程1の定めに従う。

### 抜き出し(`docs/model.md`)

信頼の順位を次の通りとする。

| 順位 | 出どころ |
|---|---|
| 1 | 機械で読める出典(データベースの定義、APIの定義、構成の定義など)からの機械的な抜き出し |
| 2 | 文書からLLMが抜き出し、検査セッションが確認したもの |
| 3 | ユーザーの証言 |
| 不可 | LLMの推測 |

- 機械で読める出典がある場合は、LLMを使わずに抜き出す。
- 出典に書かれていないことは、`unknown` として登録する。よくある構成であることを理由に、書かれていない要素やつながりを足さない。`unknown` の項目は、ユーザーに聞くか、図の上で未確定と示す。
- 間の要素を省いたつながりは、実在しないつながりである。`summarizes` に元のつながりを記録したものだけを認める。
- 出典の日付または版を、素材台帳の事実の `as_of` に記録する。
