## 手順

### 検査セッションの手順(`docs/checks.md`)

担当: 検査セッション。

全ての検査に共通の手順である。

1. 作業票が挙げる検査の条件の文を、対象に1件ずつ当てる。条件ごと、対象ごとに判定し、まとめて判定しない。
2. 条件を満たすと言い切れなければ、不合格とする。
3. 合格にも、判定の根拠にした箇所を引用する。不合格に添えるものは、[不合格と修正の手順](../../../../docs/rework.md)の「不合格のときの手順」の1による。
4. 直し方を提案しない。対象を直さないことと、記録を書くことは、[体制とセッション](../../../../docs/organization.md)の「セッションの分離」と、[不合格と修正の手順](../../../../docs/rework.md)の「原則」による。

### 比べる(`docs/checks.md`)

担当: 検査セッション。

独立に書いたセッションとは別の検査セッションが行う。何と何を比べ、何を食い違いとするかは、各工程の文書の「検査の手順」に定める。

1. 独立に書いた答えと、元の成果物の該当する項目を、対象ごとに並べて読む。
2. 食い違いごとに、答えと元の両方を引用する。
3. どちらが正しいかを決めない。
4. 食い違いを示す相手は、検査の条件の文と、各工程の定めによる。定めがなければ、食い違いを不合格として扱う。

### 読み戻しとの比較(`docs/stages/07-slide-spec.md`)

担当: 検査セッション。

スライドの文だけから書き直された意味を、スライドごとに、そのスライドの `sources` の事実(`statement`、`qualifiers`、`source`)と比べる。

- 事実にある条件、範囲、数量の幅、不確かさが、書き直された意味にない場合を、食い違いとする。スライドの `qualifiers` にある限定は、落としたものとしない。
- 動作の主体が、事実と違う場合を、食い違いとする。
- 事実が述べていないことを、書き直された意味が述べている場合を、食い違いとする。出典が述べたことを、書き手の主張として読める場合を含む。

### スライドの文(`docs/stages/07-slide-spec.md`)

読み戻しの検査で、検査セッションに渡す写し。スライドごとに、読み手が目にする文面の項目だけを持つ。

| 含めるもの | 項目 |
|---|---|
| 題 | `title` |
| 要点 | `point` |
| 説明 | `text` |
| 中身の文 | `body`。型の名前(`type`)と、要素や素材を指す項目(`highlight`、`asset`、`crop`、`scenario`)は除く |

- スライドを見分けるために、`id` を残す。
- 限定(`qualifiers`)、出どころ(`provenance`)、根拠の一覧(`sources`)、ノート(`notes`)、状態(`status`)、役割(`role`)は含めない。節の要点を引くスライドでは、要点を含めない。
- 文の中の参照は、ビルドと同じく置き換える。事実への参照は台帳の値に、別のスライドへの言及はそのスライドの題にする。
