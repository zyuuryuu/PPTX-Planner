## 守ること

### 設計セッション(`docs/organization.md`)

設計の時期を通して、ユーザーの相手をする1つのセッション。工程0から6の成果物のうち、素材台帳、画像の素材、仕組みの定義を除くものを書く。この3つは収集セッションが書く。事実の収集と検査は、別のセッションに任せる。

設計の途中の判断は、設計の判断の記録 `decisions.md` に残す。ソフトウェア開発の設計判断の記録(ADR)と同じ形をとる。

- 状況(何を決める必要があったか。関係する事実)
- 決めたこと
- 却下した案と、その理由
- 受け入れた影響(証拠との食い違い、残る危険など)
- 決めた人と日付

記録するのは、案を却下したとき、証拠と食い違う結論を維持したとき、表現規約の規則の矛盾をユーザーが裁いたとき、および各工程の定義が記録を求めるときである。

製造の時期に入っても終了させず、設計担当として残す。製造中に設計の疑問や見直しが出たら、PMとユーザーはこのセッションに戻る。発表の後の反応は、ユーザーが伝え、このセッションが記録する([工程9](../../../docs/stages/09-finish.md))。

### ユーザーとのやり取り(`docs/organization.md`)

ユーザーの負担を抑えるため、次を守る。

- 一度に求める判断は1つにする。
- 白紙の質問ではなく、推奨と代案を示して選んでもらう。
- 全体の流れを先に見せ、その後は章ごとに進める。
- 検査に通ったものは見せず、判断が要るものだけを出す。
- 承認済みのものを再び聞かない。上流の変更で見直しが要るときは、変わった箇所だけを見せる。

### 原則(`docs/principles.md`)

1. **正本は仕様で、PPTXは生成物である。** 修正は仕様に対して行い、PPTXは作り直す。LLMはPPTXの中身を読まない。PPTXから文字だけを機械的に抜き出して使うことは、これに含まない。
2. **全体で設計し、章ごとに書き、全体で検査する。** 1枚あたり数行で済む成果物は、資料全体を1つのセッションで扱う。分量の多いスライド仕様だけを章に分ける。
3. **下流の作業は、承認済みの成果物だけで進められるようにする。** 会話の履歴にしかない情報を残さない。
4. **収集、執筆、検査は別のセッションで行う。** 詳細は[体制とセッション](../../../docs/organization.md)。
5. **執筆は素材台帳にある事実だけを使う。** 台帳にない事実が必要になったら、書かずに調査依頼を出す。
6. **人はスライドの形で確認する。** 章立て設計以降は、未完成でもビルドして見られるようにする。
7. **合格条件を満たせないときは上流に戻る。** 合格条件のほうを書き換えて通すことはしない。
8. **機械で検査できるものは機械で検査する。**

### 原則(`docs/rework.md`)

1. 直すのは、その成果物を書いたセッションである。検査した側は直さない。
2. 原因が上流にある場合は、その場で辻褄を合わせない。上流に戻す。
3. 検査の指摘に、異を唱える経路を持つ。検査セッションの指摘には誤検出がある。
4. 検査し直すのは、落ちた条件と、直した箇所に依存する条件に限る。
5. 往復に上限を持つ。超えたら人が決める。
6. 合格も不合格も、記録に残す。記録は、検査した側が書く。

##### 素材台帳 `01-sources.yaml`(`docs/stages/01-exploration.md`)

全工程を通じて唯一の事実の置き場とする。スライド上の数値と出典の表記は、台帳から生成する。

```yaml
- id: F012
  statement: 2025年の国内市場規模は1.2兆円
  value: 1.2            # 本文から参照する数値。数値でない事実では省く
  unit: 兆円
  kind: fact
  source: 〇〇白書 2025年版
  locator: p.34 図表2-1  # ページ、URL、節など
  as_of: 2025-03        # 出典の日付または版
  metric: T-domestic-market-size   # 何の指標か。数値を持つ事実で必須。語彙表の語で書く。同じ指標の事実を見つけるために使う
  superseded_by: null    # 同じ指標の別の事実を使うと決めた場合に、使う事実のID。値があるものは、根拠に使えない
  quote: "国内市場は1兆2,000億円に達した"
  qualifiers: [2025年, 国内]   # この事実に付いている限定(条件、範囲、数量の幅、不確かさなど)
  origin: 〇〇省の統計    # 元をたどった情報源。別の資料が同じ情報源を引いている場合に、同じ値になる
  answers: [Q1.1]        # 探索の計画のどの問いに答えるか
  stance: {H1: supports, H2: contradicts}   # 仮説ごとに、supports(支持) / contradicts(否定) / neutral(どちらでもない)
  verified: true
```

事実の種類(`kind`)は次の通り。

| 種類 | 内容 | `verified: true` にする条件 | 根拠に使えるか |
|---|---|---|---|
| `fact` | 出典のある事実。ユーザーが提出した社内の資料にある事実を含む | `quote` が出典に実在し、`statement`、`value`、`unit`、`qualifiers` が `quote` と合っている | 使える |
| `derived` | 合計や比率などの計算値。`formula` に元の事実と計算式を書く | 元の事実が全て `verified: true` で、再計算の結果が一致する | 使える |
| `testimony` | ユーザーの証言。現場での経験、聞いた話など。誰の、何に基づく証言かを `source` に書く | ユーザーが内容を確認した | 使える。証言だけに頼る主張は、工程2でユーザーに示す |
| `image` | 画像の素材。下の「画像の素材」の節に定める | 同じ節に定める | 使える |
| `inference` | 推測 | 対象外 | 使えない |
| `opinion` | 意見 | 対象外 | 使えない |

`inference` と `opinion` をスライドに載せる場合は、推測または意見であることを文面に明示する。

出典のない事実を台帳に入れられるのは、`testimony` だけである。「広く知られている」ことを理由に、LLMが出典なしで事実を加えることは認めない。

使われない事実が台帳に残ることは問題としない。

##### 終了の判断(`docs/stages/01-exploration.md`)

担当: 設計セッション。

収集のたびに、末端の問いごとの結果を次の4つのいずれかで記録する。

| 結果 | 意味 |
|---|---|
| `answered` | 答えが出た |
| `partial` | 一部だけ出た |
| `not-found` | 見つからない |
| `disputed` | 見解が割れている |

`answered` とする条件は、重要度による。

| 重要度 | 条件 |
|---|---|
| `high` | 独立した `origin` が2つ以上ある、または一次情報が1つある |
| `low` | 情報源が1つある |

次のいずれかで探索を終える。

- 重要度が `high` の問いの全てが `answered` または `disputed` になった。
- 追加の収集を2回続けても、新しい事実が出なかった。
- ユーザーが決めた上限(回数や期限)に達した。

2つ目と3つ目で終えた場合は、`answered` にならなかった問いを限界としてユーザーに示す。ユーザーの判断は、設計の判断の記録に残す。

`disputed` は結果として認める。見解が割れていることを、工程2で主張に反映する。
