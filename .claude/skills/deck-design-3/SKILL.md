## 守ること

### 設計セッション(`docs/organization.md`)

設計の時期を通して、ユーザーの相手をする1つのセッション。工程0から6の成果物のうち、素材台帳、画像の素材、仕組みの定義を除くものを書く。この3つは収集セッションが書く。事実の収集と検査は、別のセッションに任せる。

設計の途中の判断は、設計の判断の記録 `decisions.md` に残す。ソフトウェア開発の設計判断の記録(ADR)と同じ形をとる。

- 状況(何を決める必要があったか。関係する事実)
- 決めたこと
- 却下した案と、その理由
- 受け入れた影響(証拠との食い違い、残る危険など)
- 決めた人と日付

記録するのは、案を却下したとき、証拠と食い違う結論を維持したとき、表現規約の規則の矛盾をユーザーが裁いたとき、および各工程の定義が記録を求めるときである。

製造の時期に入っても終了させず、設計担当として残す。製造中に設計の疑問や見直しが出たら、PMとユーザーはこのセッションに戻る。発表の後の反応は、ユーザーが伝え、このセッションが記録する([工程9](../../../docs/stages/09-finish.md))。

### ユーザーとのやり取り(`docs/organization.md`)

ユーザーの負担を抑えるため、次を守る。

- 一度に求める判断は1つにする。
- 白紙の質問ではなく、推奨と代案を示して選んでもらう。
- 全体の流れを先に見せ、その後は章ごとに進める。
- 検査に通ったものは見せず、判断が要るものだけを出す。
- 承認済みのものを再び聞かない。上流の変更で見直しが要るときは、変わった箇所だけを見せる。

### 原則(`docs/principles.md`)

1. **正本は仕様で、PPTXは生成物である。** 修正は仕様に対して行い、PPTXは作り直す。LLMはPPTXの中身を読まない。PPTXから文字だけを機械的に抜き出して使うことは、これに含まない。
2. **全体で設計し、章ごとに書き、全体で検査する。** 1枚あたり数行で済む成果物は、資料全体を1つのセッションで扱う。分量の多いスライド仕様だけを章に分ける。
3. **下流の作業は、承認済みの成果物だけで進められるようにする。** 会話の履歴にしかない情報を残さない。
4. **収集、執筆、検査は別のセッションで行う。** 詳細は[体制とセッション](../../../docs/organization.md)。
5. **執筆は素材台帳にある事実だけを使う。** 台帳にない事実が必要になったら、書かずに調査依頼を出す。
6. **人はスライドの形で確認する。** 章立て設計以降は、未完成でもビルドして見られるようにする。
7. **合格条件を満たせないときは上流に戻る。** 合格条件のほうを書き換えて通すことはしない。
8. **機械で検査できるものは機械で検査する。**

### 原則(`docs/rework.md`)

1. 直すのは、その成果物を書いたセッションである。検査した側は直さない。
2. 原因が上流にある場合は、その場で辻褄を合わせない。上流に戻す。
3. 検査の指摘に、異を唱える経路を持つ。検査セッションの指摘には誤検出がある。
4. 検査し直すのは、落ちた条件と、直した箇所に依存する条件に限る。
5. 往復に上限を持つ。超えたら人が決める。
6. 合格も不合格も、記録に残す。記録は、検査した側が書く。

#### 手順

##### 工程3 章立て設計の前文(`docs/stages/03-chapters.md`)

[目次に戻る](../../../docs/README.md)

主張の骨子を章に割り当て、章を節に分け、読み手に伝える順序に並べ替える。主張の骨子は調べた順に並んでおり、そのままでは伝わりにくい。章は話題の区分ではなく、主張の区分とする。章、節、項の3段の決まりは、[語彙と区分](../../../docs/vocabulary.md)に定める。

##### 成果物(`docs/stages/03-chapters.md`)

`03-chapters.yaml`(章構成):

```yaml
order:
  conclusion: first          # first(結論を先に述べる) / last(証拠を積んで結論に至る)
  basis: importance          # 章の並べ方の基準。time(時間の順) / structure(構造の順) / importance(重要度の順)
chapters:
  - id: ch1
    kind: intro              # intro(導入) / body(本論) / closing(結び)
    title: この提案の結論        # 題
    question: 〇〇事業を続けるべきか   # この章で答える問い。章扉に載せる
    point: 〇〇事業は、△△に絞って継続すべきである   # 要点
    sections:
      - id: ch1-1
        title: 結論と理由
        point_from: chapter  # 節が1つだけの章では、章の要点を引く
    slides: 2                # 本編の中身のあるスライドの数
    slides_reason: 結論だけを先に示すため、少なく充てる
  - id: ch2
    kind: body
    title: 市場の現状
    question: 市場に伸びる余地はあるのか
    point: 市場全体は縮小するが、△△の領域だけは伸びている
    qualifiers: [国内, 過去5年の実績]   # 要点の文に入れきれない限定
    claims: [C1]             # 本論の章で必須
    sections:
      - id: ch2-1
        title: 市場全体の規模
        point: 市場全体の規模は、過去5年で縮小した
        qualifiers: [国内]
        from: [Q1.4]         # 要点の素材にした、問いごとの答え
      - id: ch2-2
        title: △△領域の伸び
        point: △△の領域の市場規模は、過去5年で1.5倍になった
        qualifiers: [国内]
        from: [Q1.1]
      - id: ch2-3
        title: 伸びの地域差
        point: 伸びは都市部に限られ、地方では年率2%にとどまる
        from: [Q1.3]
    slides: 6
    slides_reason: 読み手が最も疑う点であるため、多く充てる
omitted:                     # どの章にも入れない答えと、その行き先
  - question: Q3.2
    to: appendix             # appendix(付録) / drop(載せない)
    reason: 読み手が既に知っている
contradictions:              # 結論を否定する事実に、どの章で触れるか
  - fact: F033
    chapter: ch2
objections:                  # 主張の骨子の反論の置き場
  - claim: C1
    index: 0
    to: appendix             # body(本論で答える) / appendix(付録の想定問答)
```

##### 1. 結論の位置を決める(`docs/stages/03-chapters.md`)

担当: 設計セッション。

ブリーフの「読み手の立場と懸念」で決める。

| 読み手の立場 | 結論の位置 |
|---|---|
| 賛成、中立 | 先に述べ、理由を続ける |
| 反対 | 共有できる問題意識から始め、証拠を積んで結論に至る |

##### 2. 章を並べる(`docs/stages/03-chapters.md`)

担当: 設計セッション。

読み手が次に抱く問いの順に並べる。結論を聞いた読み手は、なぜか、どうやるのか、うまくいかなかったらどうするか、と順に考える。

並べ方の基準を、時間の順、構造の順、重要度の順から1つ選び、`order.basis` に書く。

出発点として、[資料の型](../../../docs/deck-types.md)の定義が定める章の並びの定型(`chapter_order`)を使う。合わなければ変えてよい。

##### 3. 節を決める(`docs/stages/03-chapters.md`)

担当: 設計セッション。

章ごとに、その章で答える問いを `question` に書く。導入と結びの章にも書く。

章を節に分け、節ごとに題と要点を書く。本論の章では、章に割り当てた主張の問いの、子の問いへの答えを、節の要点の素材にする。素材にした答えを `from` に書く。主張の問いに子の問いがない章は、節を1つとし、章の要点を引く。節は、問いの木の順のままにせず、読み手に伝える順に並べ替えてよい。節の分け方には、分類の軸を定める。

要点の文に入れきれない限定は、`qualifiers` に書く([文章の書き方](../../../docs/writing.md))。

##### 4. 枚数を配分する(`docs/stages/03-chapters.md`)

担当: 設計セッション。

集まった素材の量ではなく、読み手の必要で配分する。読み手が疑いそうな主張に多く、既に知っている内容に少なく充てる。配分の理由を、章ごとに `slides_reason` に1行で書く。

##### 5. 載せないものを決める(`docs/stages/03-chapters.md`)

担当: 設計セッション。

問いごとの答えのうち、どの章にも入れないものを `omitted` に書き、付録に回すか、載せないかを決める。主張の骨子の反論を、本論で答えるか、付録の想定問答に回すかを `objections` に書く。

#### 検査

##### 満たす合格条件

成果物は、次の条件を満たす。括弧の中は、判定者である。「警告」とある条件は、合否にしない。

- `K03-01` 全ての主張が、いずれかの本論の章に割り当てられている(機械)。
- `K03-02` 本論の章の全てに `claims` がある。導入と結びの章には `claims` がない(機械)。
- `K03-03` `omitted` の全てに、行き先と理由がある(機械)。
- `K03-04` 全ての章に、題、問い、要点、1つ以上の節がある。全ての節に、題と要点がある。節が1つだけの章の節は、章の要点を引いている(機械)。
- `K03-05` 本論の章のうち、割り当てた主張の問いに子の問いがある章では、全ての節に `from` がある。その答えは、主張の問いの下にある。子の問いがない章の節は、章の要点を引いている(機械)。
- `K03-06` 章の要点の中の数値が、割り当てた主張の数値と一致する。節の要点の中の数値が、`from` の答えの数値と一致する(機械。単位と表記を正規化して照合する)。
- `K03-07` 章の問いに、章の要点が答えている(検査セッション)。
- `K03-08` 章の要点が、割り当てた主張より強いこと、広いことを述べていない。`qualifiers` と合わせて、主張の限定を落としていない(検査セッション。重大な検査)。
- `K03-09` 節の要点が、`from` の答えより強いこと、広いことを述べていない。`qualifiers` と合わせて、答えの限定を落としていない(検査セッション。重大な検査)。
- `K03-10` 主張の骨子の `contradictions` のうち、扱いが反駁または条件付きのものの全てに、どの章で触れるかが決まっている(機械)。
- `K03-11` 章と節の題と要点が、[文章の書き方](../../../docs/writing.md)の機械で測る検査と、[使う語彙](../../../docs/terms.md)の検査を通る(機械)。
- `K03-12` 主張の骨子の全ての反論が、`objections` にある(機械)。
- `K03-13` 枚数の合計がブリーフの制約に収まる(機械)。
- `K03-14` 全ての章に `slides_reason` がある(機械)。
- `K03-15` 結びの章の要点が、読み手に求めることを、誰が、何を、いつまでにするかの形で述べている。決まっていない項目は、未定として記録する(検査セッション)。
- `K03-16` `order.conclusion` が、ブリーフの読み手の立場と上の表に合う。合わない場合は、理由が設計の判断の記録にある(検査セッション)。 [定義](../../../docs/stages/03-chapters.md#1-結論の位置を決める)
- `K03-17` [題と要点の通読](../../../docs/checks.md)の1段目と2段目を通る(検査セッション)。
- `K03-18` 章と節の要点が、否定の検査と具体性の検査を通る(検査セッション)。 [定義](../../../docs/checks.md#意味の検査)
- `K03-19` 全ての章と節が除去の検査を通る(検査セッション)。 [定義](../../../docs/checks.md#意味の検査)
- `K03-20` 章の分け方と、章ごとの節の分け方が、分類の軸の検査を通る(検査セッション)。 [定義](../../../docs/checks.md#意味の検査)
- `KX-01` 1文の字数が、項目の種類ごとに定める上限以下である(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-02` 1文の読点の数が、上限以下である(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-03` 「の」の連続と、同じ助詞の重なりが、連続する回数の上限以下である(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-04` 漢字の連なりが、連続する字数の上限以下である(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-05` 辞書にある冗長な言い回しを含まない(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-06` 辞書にある、中身のない形容と強調を含まない(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-07` 辞書にある書き出しの決まり文句(「一言で言うと」「結論から言うと」「要するに」「端的に言えば」など)を含まない(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-08` 辞書にある、LLMに多い語を含まない(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-09` ぼかし(「など」「等」「といった」)の数が、上限以下である(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-10` 「また」「さらに」「加えて」で始まる文の割合が、上限以下である(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-11` 近い位置での同じ語の繰り返しの回数が、上限以下である(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-12` です・ます調と、である調が混在していない(機械)。 [定義](../../../docs/writing.md#機械で測るもの)
- `KX-13` 題が名詞で終わる。句点がない。字数が上限以下である(機械)。 [定義](../../../docs/writing.md#項目ごとの書き方)
- `KX-14` 要点が1文である。文末が「がわかる」「について」「すべき」でない。字数が、2行に収まる上限以下である(機械)。 [定義](../../../docs/writing.md#項目ごとの書き方)
- `KX-15` 読み手に見せる文に、内部のIDがない。IDの書式に合う文字列が、`{}` で囲んだ参照のほかにない(機械)。 [定義](../../../docs/writing.md#内部のid)
- `KX-16` 全角の数字と英字、半角の括弧と句読点、「表記」の決まりに合わない句点がない(機械)。 [定義](../../../docs/writing.md#表記)
- `KX-17` 全ての文から、名詞と動作を指す語を機械的に抜き出し、語彙表、`allowed` と照合する。扱いは、上の「厳しさの段階」の表による(機械)。 [定義](../../../docs/terms.md#厳しさの段階)
- `KX-18` `banned` の語を含まない(機械)。 [定義](../../../docs/terms.md#厳しさの段階)
- `KX-19` 表記の揺れ(長音の有無、送り仮名、全角と半角)を、正規化して語彙表と照合する(機械)。 [定義](../../../docs/terms.md)
