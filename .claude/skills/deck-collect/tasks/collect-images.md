## 手順

### 画像の素材(`docs/stages/01-exploration.md`)

スクリーンショット、写真、文書の抜粋、他の資料から引用した図は、画像の素材として素材台帳に登録する。画像をLLMに生成させて、実物として載せることは認めない。

```yaml
- id: A003
  kind: image
  file: assets/order-screen.png
  statement: 注文の入力画面
  source: 受注管理システム          # 何を写したものか。引用した図では、引用元
  version: "4.2"                    # 対象の版
  captured_at: 2026-11-10           # 取得した日
  environment: 検証環境             # 取得した環境
  regions:                          # 画像の中の要素と、その位置
    - id: due-date-field
      element: E-ui-due-date
      label: 納期の欄
      box: [0.30, 0.42, 0.25, 0.05]
      box_origin: recorded
    - id: save-button
      element: E-ui-save            # 仕組みの定義の要素。対応するものがある場合
      label: 保存ボタン
      box: [0.82, 0.90, 0.10, 0.05] # 画像の幅と高さに対する割合(左、上、幅、高さ)
      box_origin: recorded          # recorded(取得と同時に機械的に記録) / user(ユーザーが指定) / estimated(LLMが推定)
  masked: [顧客名の列]               # 隠した箇所
  verified: true
```

隠す作業は、収集セッションが画像そのものを加工して行う。加工する前の画像は、資料のリポジトリに置かない。画像を差し替えた場合にやり直す検査は、[不合格と修正の手順](../../../../docs/rework.md)の表による。

画像の中の位置は、レイアウトではなく、画像に付属する事実として扱う。位置を書くのは画像の素材の `regions` だけである。スライド仕様は、位置ではなく `regions` の `id` を参照する。

位置の出どころの信頼の順位は、`recorded`、`user`、`estimated` の順とする。`estimated` の位置は、注釈を描いた後に確かめる([工程7](../../../../docs/stages/07-slide-spec.md))。

`verified: true` にする条件は、下の合格条件の「画像の素材」の全てである。

## 検査

### 満たす合格条件

成果物は、次の条件を満たす。括弧の中は、判定者である。「警告」とある条件は、合否にしない。

- `K01-19` `source`、`version` または `captured_at` がある(機械)。
- `K01-20` 画像が `statement` の通りのものを写している(検査セッション)。
- `K01-21` `regions` の全てについて、位置が `label` の対象を囲んでいる。位置の出どころによらず確かめる(検査セッション)。
- `K01-22` 写り込みの検査を通る。検査セッションには、ブリーフの「外に出せない情報」を渡す。個人の名前、顧客の情報、認証の情報、社外に出せない名称が、隠されずに写っていない(検査セッション。重大な検査)。例外を認めない。
- `K01-23` 引用した図では、引用元の表記に必要な情報がある(機械)。
