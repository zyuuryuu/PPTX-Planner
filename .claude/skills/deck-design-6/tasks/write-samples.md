### 5. 型の見本のスライド仕様を書く(`docs/stages/06-patterns.md`)

担当: 設計セッション。

資料で使う型ごとに、見本のスライドを1枚作る。その型を使うスライドのうち、量が最も多いものを選ぶ。文字が小さくなる、詰まるといった問題を、最も厳しい条件で確かめるためである。

見本の分だけ、スライド仕様を先に書く。見本にしたスライドの仕様は、工程7でそのまま使う([体制とセッション](../../../../docs/organization.md))。

### 成果物(`docs/stages/07-slide-spec.md`)

`07-slides/ch2.yaml`(章ごとのスライド仕様):

```yaml
- id: ch2-s1
  status: done               # done(書き終えた) / blocked(保留。Issueの番号を添える)
  title: △△領域の年ごとの市場規模               # 題
  point: △△の領域の市場規模は、5年続けて前の年を上回った   # 要点
  qualifiers: [国内]         # 限定
  provenance: cited          # 出どころ。ストーリーラインにある場合
  body:
    type: line-chart
    data: {...}
    highlight: series-target  # 強調する要素。立証設計の注目させる点に対応する
  text: 国内市場の{F040}を占めるまでに拡大した。集計の方法は「{ch2-s2}」に示す   # 数値は事実のID、別のスライドはスライドのIDで参照する
  sources: [F015, F016, F040]
  notes: 口頭で補う説明
```

`title`、`point`、`point_from`、`role`、`qualifiers`、`provenance` は、ストーリーラインの通りに写す。

`text`、`body.data`、`notes` の数値は直接書かず、事実のIDで参照する。ビルドの際に台帳の値に置き換える。`point` は、ストーリーラインを人が読めるように数値を直接書いてよい。その数値は、そのスライドの `sources` の事実と一致させる。別のスライドへの言及は、スライドのIDで書く。ビルドの際に、そのスライドの題に置き換える([文章の書き方](../../../../docs/writing.md))。

要点は、ビルドが、資料の表現規約が型ごとに定める位置に1回だけ描く。`qualifiers` と `provenance` は、ビルドが、資料の型の定義の `annotation` が定める場所に描く。執筆のセッションは、これらを `text` や `body` に書き写さない。

画像の型のスライドでは、画像の素材と、注釈を付ける `regions` を参照する。位置は書かない。

```yaml
- id: ch5-s2
  status: done
  title: 納期の入力と保存
  point: 納期が空のまま保存すると、発注が止まる
  body:
    type: annotated-image-steps
    asset: A003
    crop: [due-date-field, save-button]   # この範囲が入るように切り抜く
    scenario: S-order-entry               # 番号は、場面の順から決まる
    captions:                             # 注釈の説明。スライドのノート(`notes`)とは別の項目
      due-date-field: 納期を入力する
      save-button: 保存を押す
  sources: [A003, F120]
```

## 検査

### 満たす合格条件

成果物は、次の条件を満たす。括弧の中は、判定者である。「警告」とある条件は、合否にしない。

- `K06-10` 資料で使う全ての型に、見本がある(機械)。
- `K06-11` 見本の描画上の診断が0件である。文字の大きさが下限以上である。色の差と、1枚で使う色相の数が、基準を満たす(機械)。 [定義](../../../../docs/visual-grammar.md#d-知覚の限界)
- `K06-12` 形からの読み取り: 検査セッションに見本の画像だけを見せ、項目の間に読み取れる関係を含意の語彙で答えさせる。答えが型の `implies` と合う(検査セッション)。 [定義](../../../../docs/visual-grammar.md#形からの読み取り)
- `K06-13` 見本の画像で最初に目が行く場所が、立証設計の `focus` と合う(検査セッション)。 [定義](../../../../docs/visual-grammar.md#e-注目)
- `K06-14` 見本の画像に、消しても情報が失われない要素がない(検査セッション)。 [定義](../../../../docs/visual-grammar.md#g-飾り)
- `K06-15` 見本で、要点が決めた位置にある。同じ文が、1枚の中に2回出ていない(検査セッション)。
- `K06-16` 見本を見て、型の選び方と見た目に同意する(ユーザー)。
