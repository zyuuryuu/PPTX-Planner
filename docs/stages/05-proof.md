# 工程5 立証設計

[目次に戻る](../README.md)

スライドごとに、見出しを読み手に納得させるために何を見せるかを決める。中身を書く前に行う。全体を1つのセッションで扱う。

## 成果物

`05-proof.yaml`(スライドごとの立証の設計):

```yaml
- id: ch2-s1
  relation: trend                 # 主張の種類
  show: 全体と△△領域の売上を5年分並べる   # 見せるもの
  focus: 2023年以降の差の広がり          # 注目させる点
  facts: [F015, F016, F040]       # 使う事実
  axis: null                      # 項目をまとめるスライドでは、分類の軸を書く
  base: none                      # 土台。none(なし) / image(画像の素材の上に描く)
  holds: [ordered, proportional]  # 項目の間に実際に成り立つ関係。含意の語彙で書く。先頭を、主な関係とする
- id: ch4-s3
  relation: interaction
  show: 購入の処理での、部品の間のやり取り
  focus: 在庫の確認で処理が待たされる箇所
  real: true                      # 実在の仕組み、業務、組織、画面を写す場合に true とする
  view:                           # real が true のスライドでは、仕組みの定義から選ぶ
    scenario: S-purchase
    elements: [E-web, E-order, E-stock, E-db]
  facts: [F110]
  holds: [ordered, connected]
```

`facts` が足りなければ、調査依頼を出して工程1に戻る。

この時点で仮置きの資料をビルドする。各スライドには見出しと、図の型の仮置き(「ここに5年分の推移」など)が載る。

## 作り方

### 1. 主張の種類を判定する

見出しが何を述べているかで判定する。種類の一覧は[語彙と区分](../vocabulary.md)にある。

| 見出しが述べていること | 主張の種類 |
|---|---|
| 時間とともに増えた、減った、変わった | 推移 |
| AはBより大きい、最も多いのはA | 項目の比較 |
| 全体のうちAが何割を占める | 構成比 |
| AするとBになる、Aが原因でB | 因果 |
| まずA、次にB | 手順 |
| AとBのどちらを選ぶか | 2案の対比 |
| 前はAだったが、後はBになる | 前後の対比 |
| AはBとCに分かれる、AはBの一部である | 構造・階層 |
| AはBとCの部品からなり、BはCにつながる | 構成 |
| AがBに頼み、BがCに問い合わせる | やり取り |
| Aの状態からBの状態に移る | 状態の遷移 |

この表は主な種類だけを挙げている。全ての種類は[語彙と区分](../vocabulary.md)にある。

判定が割れる見出しは、主張が2つ混じっているか、曖昧である。ストーリーラインに戻す。

「言い切り」と「並列の列挙」は、どの見出しにも当てはめられる。この2つを選ぶ場合は、ほかの種類に当てはまらない理由を書く。

### 2. 見せるものを決める

見せ方の候補を2つか3つ出し、「見出しを読まなくても、見出しの内容が伝わるか」で1つに絞る。最初に思いついた見せ方をそのまま採らない。選ばなかった候補は記録しない。

### 3. 注目させる点を決める

読み手に、図や表のどこを見てほしいかを1つ書く。複雑な図ほど必要になる。見出しは図の説明(「注文処理の流れ」)ではなく、図から読み取ってほしいこと(「在庫の確認で処理が待たされる」)になっているかを、ここで確かめる。なっていなければ、ストーリーラインに戻す。

### 4. 実在の仕組みを写す図では、仕組みの定義から選ぶ

実在の仕組み、業務、組織、画面を写すスライドでは、`real` を true とし、[仕組みの定義](../model.md)から、図に使う要素とつながり、または場面を選び、`view` に書く。主張の種類の区分は問わない。画面の操作の手順のように、区分が「仕組みの記述」でないスライドも含む。定義にないものが必要になったら、描かずに調査依頼を出す。

### 5. 成り立つ関係を申告する

スライドに載せる項目の間に実際に成り立つ関係を、[形が伝える意味](../visual-grammar.md)の含意の語彙で `holds` に書く。工程6で、型が伝える含意と照合する。成り立たない関係を書かない。型に合わせて後から書き足さない。

### 6. 表現の偏りを見る

全スライドの主張の種類を集計する。同じ種類が続く箇所、特定の種類への偏り、「言い切り」と「並列の列挙」が占める割合を、ユーザーが仮置きの資料を見るときに示す。偏りは違反としない。割合が資料の表現規約の目安を超える場合は警告とし、理由を添えて示す。

## 合格条件

- `relation` が[主張の種類の語彙](../vocabulary.md)にある(機械)。
- `facts` が全て素材台帳にあり、`verified: true` で、`superseded_by` が空である。画像の素材も `facts` に含める(機械)。
- `facts` が、ストーリーラインの `evidence` を全て含む(機械)。
- `real` が true のスライドに `view` があり、その要素、つながり、場面が全て仕組みの定義にある(機械)。主張の種類の区分は問わない。
- `real` の申告が正しい。図が実在のものを写しているのに、false としていない(検査セッション。重大な検査)。
- 見出しが「全体」を述べるスライドの `view` が、該当する種類の要素を全て含む(機械)。
- 全てのスライドの `show` と `focus` が空でない(機械)。
- 「言い切り」と「並列の列挙」のスライドに、ほかの種類に当てはまらない理由がある(機械)。
- 同じ事実を複数のスライドが使う場合は、警告とする(機械)。意図した再掲かどうかは、工程5の承認のときに、警告の扱いとして決める。
- やり取りや状態の遷移の図に出る要素が、構成または要素の関係の図のいずれかにも出る。出ない場合は警告とする(機械)。
- 全てのスライドに `holds` の項目がある。項目の間に関係がないスライド(並列の列挙、言い切り)では、空とする(機械)。
- `holds` の申告が正しい。[形が伝える意味](../visual-grammar.md)が含意ごとに定める問いで確かめる(検査セッション)。
- 主張の種類が、見出しの述べていることと合う(検査セッション)。
- スライド内の要素が除去の検査を通る。`show` が、`focus` に関係しない要素を含まない(検査セッション)。
- 項目をまとめるスライドが、分類の軸の検査を通る(検査セッション)。
- 見出しの復元: 検査セッションに見出しを隠して `show`、`focus`、`facts`、`view` だけを見せ、見出しを書かせる。元の見出しと意味が一致する(検査セッション)。
- 仮置きの資料を見て、見せ方に同意する(ユーザー)。
