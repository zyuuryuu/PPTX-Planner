# 工程3 章立て設計

[目次に戻る](../README.md)

主張の骨子を章に割り当て、章を節に分け、読み手に伝える順序に並べ替える。主張の骨子は調べた順に並んでおり、そのままでは伝わりにくい。章は話題の区分ではなく、主張の区分とする。章、節、項の3段の決まりは、[語彙と区分](../vocabulary.md)に定める。

## 成果物

`03-chapters.yaml`(章構成):

```yaml
order:
  conclusion: first          # first(結論を先に述べる) / last(証拠を積んで結論に至る)
  basis: importance          # 章の並べ方の基準。time(時間の順) / structure(構造の順) / importance(重要度の順)
chapters:
  - id: ch1
    kind: intro              # intro(導入) / body(本論) / closing(結び)
    title: この提案の結論        # 題
    question: 〇〇事業を続けるべきか   # この章で答える問い。章扉に載せる
    point: 〇〇事業は、△△に絞って継続すべきである   # 要点
    sections:
      - id: ch1-1
        title: 結論と理由
        point_from: chapter  # 節が1つだけの章では、章の要点を引く
    slides: 2                # 本編の中身のあるスライドの数
    slides_reason: 結論だけを先に示すため、少なく充てる
  - id: ch2
    kind: body
    title: 市場の現状
    question: 市場に伸びる余地はあるのか
    point: 市場全体は縮小するが、△△の領域だけは伸びている
    qualifiers: [国内, 過去5年の実績]   # 要点の文に入れきれない限定
    claims: [C1]             # 本論の章で必須
    sections:
      - id: ch2-1
        title: 市場全体の規模
        point: 市場全体の規模は、過去5年で縮小した
        qualifiers: [国内]
        from: [Q1.4]         # 要点の素材にした、問いごとの答え
      - id: ch2-2
        title: △△領域の伸び
        point: △△の領域の市場規模は、過去5年で1.5倍になった
        qualifiers: [国内]
        from: [Q1.1]
      - id: ch2-3
        title: 伸びの地域差
        point: 伸びは都市部に限られ、地方では年率2%にとどまる
        from: [Q1.3]
    slides: 6
    slides_reason: 読み手が最も疑う点であるため、多く充てる
omitted:                     # どの章にも入れない答えと、その行き先
  - question: Q3.2
    to: appendix             # appendix(付録) / drop(載せない)
    reason: 読み手が既に知っている
contradictions:              # 結論を否定する事実に、どの章で触れるか
  - fact: F033
    chapter: ch2
objections:                  # 主張の骨子の反論の置き場
  - claim: C1
    index: 0
    to: appendix             # body(本論で答える) / appendix(付録の想定問答)
```

## 作り方

### 1. 結論の位置を決める

担当: 設計セッション。

ブリーフの「読み手の立場と懸念」で決める。

| 読み手の立場 | 結論の位置 |
|---|---|
| 賛成、中立 | 先に述べ、理由を続ける |
| 反対 | 共有できる問題意識から始め、証拠を積んで結論に至る |

### 2. 章を並べる

担当: 設計セッション。

読み手が次に抱く問いの順に並べる。結論を聞いた読み手は、なぜか、どうやるのか、うまくいかなかったらどうするか、と順に考える。

並べ方の基準を、時間の順、構造の順、重要度の順から1つ選び、`order.basis` に書く。

出発点として、[資料の型](../deck-types.md)の定義が定める章の並びの定型(`chapter_order`)を使う。合わなければ変えてよい。

### 3. 節を決める

担当: 設計セッション。

章ごとに、その章で答える問いを `question` に書く。導入と結びの章にも書く。

章を節に分け、節ごとに題と要点を書く。本論の章では、章に割り当てた主張の問いの、子の問いへの答えを、節の要点の素材にする。素材にした答えを `from` に書く。主張の問いに子の問いがない章は、節を1つとし、章の要点を引く。節は、問いの木の順のままにせず、読み手に伝える順に並べ替えてよい。節の分け方には、分類の軸を定める。

要点の文に入れきれない限定は、`qualifiers` に書く([文章の書き方](../writing.md))。

### 4. 枚数を配分する

担当: 設計セッション。

集まった素材の量ではなく、読み手の必要で配分する。読み手が疑いそうな主張に多く、既に知っている内容に少なく充てる。配分の理由を、章ごとに `slides_reason` に1行で書く。

### 5. 載せないものを決める

担当: 設計セッション。

問いごとの答えのうち、どの章にも入れないものを `omitted` に書き、付録に回すか、載せないかを決める。主張の骨子の反論を、本論で答えるか、付録の想定問答に回すかを `objections` に書く。

### 6. 目次と章扉の資料をビルドする

担当: 機械。

目次と章扉だけの資料をビルドする。確認のため、この資料の章扉には、章の要点と、節の題と要点も載せる。完成形の章扉の中身は、[語彙と区分](../vocabulary.md)に定める。

### 7. 承認する

担当: ユーザー。

ユーザーは、目次と章扉の資料を見て承認する。

- 全ての主張が、いずれかの本論の章に割り当てられている(機械)。 `K03-01`
- 本論の章の全てに `claims` がある。導入と結びの章には `claims` がない(機械)。 `K03-02`
- `omitted` の全てに、行き先と理由がある(機械)。 `K03-03`
- 全ての章に、題、問い、要点、1つ以上の節がある。全ての節に、題と要点がある。節が1つだけの章の節は、章の要点を引いている(機械)。 `K03-04`
- 本論の章のうち、割り当てた主張の問いに子の問いがある章では、全ての節に `from` がある。その答えは、主張の問いの下にある。子の問いがない章の節は、章の要点を引いている(機械)。 `K03-05`
- 章の要点の中の数値が、割り当てた主張の数値と一致する。節の要点の中の数値が、`from` の答えの数値と一致する(機械。単位と表記を正規化して照合する)。 `K03-06`
- 章の問いに、章の要点が答えている(検査セッション)。 `K03-07`
- 章の要点が、割り当てた主張より強いこと、広いことを述べていない。`qualifiers` と合わせて、主張の限定を落としていない(検査セッション。重大な検査)。 `K03-08`
- 節の要点が、`from` の答えより強いこと、広いことを述べていない。`qualifiers` と合わせて、答えの限定を落としていない(検査セッション。重大な検査)。 `K03-09`
- 主張の骨子の `contradictions` のうち、扱いが反駁または条件付きのものの全てに、どの章で触れるかが決まっている(機械)。 `K03-10`
- 章と節の題と要点が、[文章の書き方](../writing.md)の機械で測る検査と、[使う語彙](../terms.md)の検査を通る(機械)。 `K03-11`
- 主張の骨子の全ての反論が、`objections` にある(機械)。 `K03-12`
- 枚数の合計がブリーフの制約に収まる(機械)。 `K03-13`
- 全ての章に `slides_reason` がある(機械)。 `K03-14`
- 結びの章の要点が、読み手に求めることを、誰が、何を、いつまでにするかの形で述べている。決まっていない項目は、未定として記録する(検査セッション)。 `K03-15`
- `order.conclusion` が、ブリーフの読み手の立場と上の表に合う。合わない場合は、理由が設計の判断の記録にある(検査セッション)。 `K03-16`
- [題と要点の通読](../checks.md)の1段目と2段目を通る(検査セッション)。 `K03-17`
- 章と節の要点が、否定の検査と具体性の検査を通る(検査セッション)。 `K03-18` [定義](../checks.md#意味の検査)
- 全ての章と節が除去の検査を通る(検査セッション)。 `K03-19` [定義](../checks.md#意味の検査)
- 章の分け方と、章ごとの節の分け方が、分類の軸の検査を通る(検査セッション)。 `K03-20` [定義](../checks.md#意味の検査)
- 目次と章扉の資料を見て、章構成に同意する(ユーザー)。 `K03-21`
