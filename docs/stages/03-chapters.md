# 工程3 章立て設計

[目次に戻る](../README.md)

主張の骨子を章に割り当て、読み手に伝える順序に並べ替える。主張の骨子は調べた順に並んでおり、そのままでは伝わりにくい。章は話題の区分ではなく、主張の区分とする。

## 成果物

`03-chapters.yaml`(章構成):

```yaml
order:
  conclusion: first          # first(結論を先に述べる) / last(証拠を積んで結論に至る)
  basis: importance          # 章の並べ方の基準。time(時間の順) / structure(構造の順) / importance(重要度の順)
chapters:
  - id: ch1
    kind: intro              # intro(導入) / body(本論) / closing(結び)
    title: この提案の結論
    message: 〇〇事業は、△△に絞って継続すべきである
    slides: 2
  - id: ch2
    kind: body
    title: 市場の現状
    message: 市場全体は縮小するが、△△の領域だけは伸びている
    claims: [C1]             # 本論の章で必須
    slides: 6
    slides_reason: 読み手が最も疑う点であるため、多く充てる
omitted:                     # どの章にも入れない答えと、その行き先
  - question: Q3.2
    to: appendix             # appendix(付録) / drop(載せない)
    reason: 読み手が既に知っている
objections:                  # 主張の骨子の反論の置き場
  - claim: C1
    index: 0
    to: body                 # body(本論で答える) / appendix(付録の想定問答)
```

この時点で、目次と章扉だけの資料をビルドする。章扉には、章の `message` を載せる。ユーザーはこの資料を見て承認する。

## 作り方

### 1. 結論の位置を決める

ブリーフの「読み手の立場と懸念」で決める。

| 読み手の立場 | 結論の位置 |
|---|---|
| 賛成、中立 | 先に述べ、理由を続ける |
| 反対、懐疑的 | 共有できる問題意識から始め、証拠を積んで結論に至る |

### 2. 章を並べる

読み手が次に抱く問いの順に並べる。結論を聞いた読み手は、なぜか、どうやるのか、うまくいかなかったらどうするか、と順に考える。

並べ方の基準を、時間の順、構造の順、重要度の順から1つ選び、`order.basis` に書く。

出発点として、[資料の型](../deck-types.md)の定義が定める章の並びの定型(`chapter_order`)を使う。合わなければ変えてよい。

### 3. 枚数を配分する

集まった素材の量ではなく、読み手の必要で配分する。読み手が疑いそうな主張に多く、既に知っている内容に少なく充てる。配分の理由を、章ごとに `slides_reason` に1行で書く。

### 4. 載せないものを決める

問いごとの答えのうち、どの章にも入れないものを `omitted` に書き、付録に回すか、載せないかを決める。主張の骨子の反論を、本論で答えるか、付録の想定問答に回すかを `objections` に書く。

## 合格条件

- 全ての主張が、いずれかの本論の章に割り当てられている(機械)。
- 本論の章の全てに `claims` がある。導入と結びの章には `claims` がない(機械)。
- 問いの木で主張と同じ階層にある問いの答えが、いずれかの章か `omitted` にある(機械)。
- 主張の骨子の全ての反論が、`objections` にある(機械)。
- 枚数の合計がブリーフの制約に収まる(機械)。
- 全ての章に `slides_reason` がある(機械)。
- `order.conclusion` が、ブリーフの読み手の立場と上の表に合う。合わない場合は、理由が設計の判断の記録にある(検査セッション)。
- 章の `message` を順に読むと `answer` が導ける(検査セッション)。
- 章の `message` が、否定の検査と具体性の検査を通る(検査セッション)。
- 全ての章が除去の検査を通る(検査セッション)。
- 章の分け方が、分類の軸の検査を通る(検査セッション)。
- 目次と章扉の資料を見て、章構成に同意する(ユーザー)。
