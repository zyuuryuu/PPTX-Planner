# 工程4 ストーリーライン

[目次に戻る](../README.md)

全ての章のスライドの題と要点を、1つのセッションで決める。題は話題を示し、要点は読み手に理解してほしいことを述べる。2つを別の項目として持つ。全体を一度に扱うことで、章をまたぐ要点の重複と矛盾をこの段階で防ぐ。

題と要点の書き方は[文章の書き方](../writing.md)に、要点のないスライド、節の要点を載せるスライド、スライドの区分は[語彙と区分](../vocabulary.md)に定める。

## 成果物

`04-storyline.yaml`(スライドの題と要点の一覧):

```yaml
- id: ch2-s1
  chapter: ch2
  section: ch2-2               # 章構成で決めた節
  question: 伸びは続いているのか                 # 読み手が抱く問い
  title: △△領域の年ごとの市場規模               # 題
  point: △△の領域の市場規模は、5年続けて前の年を上回った   # 要点。問いへの答え
  qualifiers: [国内]           # 要点の文に入れきれない限定
  provenance: cited            # 出どころ。資料の型の定義が区別を求める資料だけに書く。cited(出典のある事実) / proposal(案) / practice(今の運用)
  from: [Q1.1]                 # 要点の素材にした、問いごとの答え
  evidence: [F015]
- id: ch2-s2
  chapter: ch2
  section: ch2-2
  title: △△領域の範囲と集計の方法
  point: null                  # 要点のないスライド
  role: detail                 # 役割。detail(詳しい説明) / exercise(演習の問題) / reference(参照用)
- id: ch2-s3
  chapter: ch2
  section: ch2-2
  question: 5年間でどれだけ大きくなったか
  title: 5年間の規模の変化
  point_from: section          # 節の要点を引く。自分の要点は書かない
  from: [Q1.1]
  evidence: [F015, F016]
- id: ch2-s4
  chapter: ch2
  section: ch2-3
  question: 伸びはどの地域でも同じか
  title: 地域ごとの伸び
  point_from: section          # スライドが1枚だけの節
  from: [Q1.3]
  evidence: [F033]
  contradiction: F033          # 結論を否定する事実に触れるスライドでは、その事実
- id: ap-s1
  chapter: appendix
  appendix_of: ch2-s1          # 付録のスライドでは、本編のどのスライドを補うか
  question: 伸びているのは大手だけではないか
  title: 新規参入の件数
  point: 新規参入の件数も3年で2倍に増えている
  from: [Q1.2]
  evidence: [F021]
  objection: {claim: C1, index: 0}   # 主張の骨子の反論に答えるスライドでは、その反論
```

以下では、`point` を書いたスライドと、節の要点を引くスライドを、要点を持つスライドと呼ぶ。

資料の型の定義が必ず置くと定めるスライド(`required_slides`)には、`required` にその `id` を書く。

この一覧に書くのは、本編と付録の、中身のあるスライドである。自動で作るスライドは書かない。

章の中は、次の順になる。

1. 章扉。
2. 節ごとに、本編のスライド。節のまとめを置く節では、節の最後に置く。
3. 章のまとめ。

この時点で骨組みの資料をビルドする。各スライドには、題、要点(要点のないスライドでは役割)、根拠の事実の `statement` だけが載る。章のまとめと節のまとめも、この資料に含める。ユーザーは、全体の流れを見たうえで、章ごとに承認する。承認は、題と要点の両方に及ぶ。骨組みの資料は、工程7と8で、章を実物に差し替えていく土台になる。

`04-chapter-states.yaml`(章の前提と到達点)。章ごとに、読み手が何を知った状態で入り、何を知った状態で出るかを定める。書式は[工程8](08-integration.md)に示す。

`04-scenarios.yaml`(テストの場面と、期待する結果)。工程8の結合テストで使う。作った後に、出来上がりに合わせて期待を決めないために、ここで書く。場面の種類は[工程8](08-integration.md)に示す。

## 作り方

### 1. 読み手の問いを書き出す

節ごとに、節の要点を読んだ読み手が抱く問いを、抱く順に書き出す。ブリーフの「読み手が既に知っていること」に答えがある問いは、書かない。ブリーフの「読み手の立場と懸念」にある懸念は、問いとして含める。

### 2. 問いに、題と要点で答える

1つの問いに、1枚のスライドで答える。要点は、その問いへの答えの文とする。題は、そのスライドの話題とする。

要点の素材は、工程2の問いごとの答えから取る。節の要点の素材にした答えと、その下にある答えが候補になる。白紙から要点を考えない。素材にした答えを `from` に書く。

該当する答えがない問いは、探索が足りていない。調査依頼を出して工程1に戻るか、その問いを外す。

要点の文に入れきれない限定は、`qualifiers` に書く。

資料の型の定義の `annotation` が出どころの区別を求める資料では、スライドごとに、出どころを `provenance` に書く。値は機械で導かない。設計セッションが書き、ユーザーが骨組みの資料で確かめる。骨組みの資料には、`qualifiers` と `provenance` を、`annotation` が定める置き場に載せる。

### 3. 要点のないスライドを足す

節の要点を理解するために要る説明、演習の問題、参照用の一覧は、要点のないスライドとして足し、役割を書く。

### 4. 節の要点を載せるスライドを決める

[語彙と区分](../vocabulary.md)の表に当てはめる。節の最後のスライドが載せる節では、そのスライドに `point_from: section` を書く。

### 5. 必ず置くスライドを入れる

資料の型の定義の `required_slides` のスライドを、合う節に入れる。

### 6. 枚数を章構成の配分に合わせる

章の枚数が章構成の配分を超えたら、除去の検査で残す根拠の弱いスライドから、付録に回すか捨てる。配分を増やす場合と、節を足す、分ける、まとめる場合は、工程3に戻ってユーザーの承認を取り直す。

### 7. 章の前提と到達点を書く

要点の並びから、章ごとに、入る時点で読み手が得ているもの(語、納得した主張、抱いている疑問)と、出る時点で得ているもの(新しい語、納得した主張、答えを得た疑問、残る疑問)を書き出す。

ブリーフの読み手の懸念の1つ1つを、どの章で答えるかを決め、その章の到達点に書く。答えない懸念は、答えないと決めた理由とあわせて、設計の判断の記録に残す。

### 8. テストの場面と、期待する結果を書く

読み方の種類ごとに、読み終えたときに読み手が得ているはずの理解を書く。

構造:

- 全てのスライドに、題がある(機械)。 `K04-01`
- 資料の型の定義の `annotation` が出どころの区別を求める資料では、全てのスライドに `provenance` がある。`cited` とした、要点を持つスライドに、`evidence` がある(機械)。 `K04-02`
- 全てのスライドが、要点を書く、節の要点を引く、要点を持たずに役割を書く、のいずれか1つの形である(機械)。 `K04-03`
- 本編の全てのスライドが、章構成にある節に入っている。章構成の全ての節に、スライドが1枚以上ある(機械)。 `K04-04`
- 節の項の数が、資料の表現規約の `section_max_slides` 以下である(機械)。 `K04-05`
- 節の要点を載せるスライドが、[語彙と区分](../vocabulary.md)の表の通りである。節の要点を引くスライドは、節の最後のスライドだけである(機械)。 `K04-06`
- 資料の型の定義の `required_slides` の全てに、`required` でそれを参照するスライドがある(機械)。 `K04-07`
- 書き方(`form`)の定めがあるスライドは、その通りに書かれている(検査セッション)。 `K04-08`
- 章ごとの枚数が、章構成の配分以下である。自動で作るスライドの枚数は、別に数えてユーザーに示す(機械)。 `K04-09`
- 付録の全てのスライドに `appendix_of` がある(機械)。 `K04-10`
- 章構成で付録に回すとした答えの全てに、`from` でそれを参照する付録のスライドがある。章構成の `objections` の全てに、`objection` でそれを参照するスライドが、決めた置き場(本編または付録)にある(機械)。 `K04-11`
- 章構成の `contradictions` の全てに、`contradiction` でそれを参照するスライドが、章構成が決めた章にある。そのスライドの `evidence` が、その事実を含む(機械)。 `K04-12`

題と要点:

- 要点を持つスライドに、問いが1つある(機械)。 `K04-13`
- 本論の章の、要点を持つ全てのスライドに、`from` と `evidence` がある(機械)。 `K04-14`
- 題と要点が、[文章の書き方](../writing.md)の機械で測る検査と、[使う語彙](../terms.md)の検査を通る。新しい語は、語彙表に登録されている(機械)。 `K04-15`
- 要点の中の数値が、そのスライドの `evidence` の事実の値と一致する(機械。単位と表記を正規化して照合する)。 `K04-16`
- 要点が、2つの主張をつないでいない。機械が「また」「および」などの接続を含む要点を挙げ、検査セッションが判定する(機械と検査セッション)。 `K04-17`
- 要点どうしが矛盾していない。同じ事実、同じ対象を扱う要点の組を機械が挙げ、検査セッションが確かめる(検査セッション)。 `K04-18`
- 要点が、`qualifiers` と合わせて、根拠の事実の限定を落としていない(検査セッション。重大な検査)。 `K04-19`
- 要点が、そのスライドの問いに答えている(検査セッション)。 `K04-20`
- 題が、そのスライドの話題を示している。要点の言い換えになっていない(検査セッション)。 `K04-21`
- [題と要点の通読](../checks.md)の3段目を通る(検査セッション)。 `K04-22`
- 同じことを述べる要点が複数ない(検査セッション)。 `K04-23`
- 全ての要点が、否定の検査と具体性の検査を通る(検査セッション)。 `K04-24` [定義](../checks.md#意味の検査)
- 本編の全てのスライドが除去の検査を通る。通らないスライドは、付録に回すか捨てる(検査セッション)。 `K04-25` [定義](../checks.md#意味の検査)

章の前提と到達点、テストの場面:

- 全ての章の入口の状態が、それより前の章の出口の状態で満たされている(機械)。 `K04-26`
- 最後の章の出口で、残る疑問がない(機械)。 `K04-27`
- ブリーフの読み手の懸念の全てが、いずれかの章の到達点にあるか、答えないと決めた記録がある(機械)。 `K04-28`
- [工程8](08-integration.md)が定める全ての場面に、期待する結果が書かれている。該当しない場面は、該当しないと記録する(機械)。 `K04-29`

承認:
