# 工程4 ストーリーライン

[目次に戻る](../README.md)

全ての章のスライドの見出しを、1つのセッションで決める。見出しは体言止めの題名ではなく、主張を述べる文とする。全体を一度に扱うことで、章をまたぐ主張の重複と矛盾をこの段階で防ぐ。

## 成果物

`04-storyline.yaml`(スライド見出しの一覧):

```yaml
- id: ch2-s1
  chapter: ch2
  section: null                # 章を節に分けた場合は、節の名前
  question: △△の領域は本当に伸びているのか     # 読み手が抱く問い
  headline: △△の領域は過去5年、年率8%で伸びている   # 問いへの答え
  from: [Q1.1]                 # 見出しの素材にした、問いごとの答え
  evidence: [F015]
- id: ch2-s4
  chapter: ch2
  question: 伸びはどの地域でも同じか
  headline: 伸びは都市部に限られ、地方では年率2%にとどまる
  from: [Q1.3]
  evidence: [F033]
  contradiction: F033          # 結論を否定する事実に触れるスライドでは、その事実
- id: ap-s1
  chapter: appendix
  appendix_of: ch2-s1          # 付録のスライドでは、本編のどのスライドを補うか
  question: 伸びているのは大手だけではないか
  headline: 新規参入の件数も3年で2倍に増えている
  from: [Q1.2]
  evidence: [F021]
  objection: {claim: C1, index: 0}   # 主張の骨子の反論に答えるスライドでは、その反論
```

この一覧に書くのは、本編と付録のスライドである。章扉、目次、章のまとめなど、[語彙と区分](../vocabulary.md)が導出または半導出とするスライドは書かない。それらの枚数は章構成から機械的に決まり、枚数の検査では合算する。

章の中は、次の順になる。

1. 章扉(導出)。章の題と、この章で答える問いを載せる。
2. 本編のスライド。読み手の問いに順に答える。
3. 章のまとめ(半導出)。章の主張を確かめる。

この時点で骨組みの資料をビルドする。各スライドには見出しと、根拠の事実の `statement` だけが載る。ユーザーは、全体の流れを見たうえで、章ごとに承認する。骨組みの資料は、工程7と8で、章を実物に差し替えていく土台になる。

`04-chapter-states.yaml`(章の前提と到達点)。章ごとに、読み手が何を知った状態で入り、何を知った状態で出るかを定める。書式は[工程8](08-integration.md)に示す。

`04-scenarios.yaml`(テストの場面と、期待する結果)。工程8の結合テストで使う。作った後に、出来上がりに合わせて期待を決めないために、ここで書く。場面の種類は[工程8](08-integration.md)に示す。

## 作り方

### 1. 読み手の問いを書き出す

章ごとに、章の主張を読んだ読み手が抱く問いを、抱く順に書き出す。ブリーフの「読み手が既に知っていること」に答えがある問いは、書かない。ブリーフの「読み手の立場と懸念」にある懸念は、問いとして含める。

### 2. 問いに見出しで答える

1つの問いに、1枚のスライドで答える。見出しは、その問いへの答えの文とする。

見出しの素材は、工程2の問いごとの答えから取る。章に割り当てた主張の下にある答えが候補になる。白紙から見出しを考えない。素材にした答えを `from` に書く。

該当する答えがない問いは、探索が足りていない。調査依頼を出して工程1に戻るか、その問いを外す。

### 3. 枚数を章構成の配分に合わせる

章の枚数が章構成の配分を超えたら、除去の検査で残す根拠の弱いスライドから、付録に回すか捨てる。配分を増やす場合は、工程3に戻ってユーザーの承認を取り直す。

### 4. 章の前提と到達点を書く

見出しの並びから、章ごとに、入る時点で読み手が得ているもの(語、納得した主張、抱いている疑問)と、出る時点で得ているもの(新しい語、納得した主張、答えを得た疑問、残る疑問)を書き出す。

ブリーフの読み手の懸念の1つ1つを、どの章で答えるかを決め、その章の到達点に書く。答えない懸念は、答えないと決めた理由とあわせて、設計の判断の記録に残す。

### 5. テストの場面と、期待する結果を書く

読み方の種類ごとに、読み終えたときに読み手が得ているはずの理解を書く。

### 6. 長い章を節に分ける

章の本編のスライドが、資料の表現規約が定める1節あたりの枚数の上限を超える場合は、節に分ける。節の分け方にも、分類の軸を定める。

## 合格条件

- 1スライドに、問いと見出しが1つずつある(機械)。
- 見出しが、2つの主張をつないでいない。機械が「また」「および」などの接続を含む見出しを挙げ、検査セッションが判定する。
- 見出しの字数が、資料の表現規約が定める上限以下である(機械)。
- 本論の章の全てのスライドに、`from` と `evidence` がある(機械)。
- 章ごとの枚数が、導出と半導出のスライドを合算して、章構成の配分以下である(機械)。
- 付録の全てのスライドに `appendix_of` がある(機械)。
- 章構成で付録に回すとした答えの全てに、`from` でそれを参照する付録のスライドがある。章構成の `objections` の全てに、`objection` でそれを参照するスライドが、決めた置き場(本編または付録)にある(機械)。
- 見出しが、[文章の書き方](../writing.md)の機械で測る検査と、[使う語彙](../terms.md)の検査を通る。新しい語は、語彙表に登録されている(機械)。
- 章構成の `contradictions` の全てに、`contradiction` でそれを参照するスライドが、章構成が決めた章にある。そのスライドの `evidence` が、その事実を含む(機械)。
- 見出しどうしが矛盾していない。同じ事実、同じ対象を扱う見出しの組を機械が挙げ、検査セッションが確かめる(検査セッション)。
- 見出しが、根拠の事実の限定を落としていない(検査セッション。重大な検査)。
- 見出しが、そのスライドの問いに答えている(検査セッション)。
- 章内の見出しを順に読むと、章の `message` が導ける(検査セッション)。
- 同じ主張を述べる見出しが複数ない(検査セッション)。
- 全ての見出しが、否定の検査と具体性の検査を通る(検査セッション)。
- 見出しの中の数値が、そのスライドの `evidence` の事実の値と一致する(機械。単位と表記を正規化して照合する)。
- 本編の全てのスライドが除去の検査を通る。通らないスライドは、付録に回すか捨てる(検査セッション)。
- 節に分けた章の分け方が、分類の軸の検査を通る(検査セッション)。
- 全ての章の入口の状態が、それより前の章の出口の状態で満たされている(機械)。
- 最後の章の出口で、残る疑問がない(機械)。
- ブリーフの読み手の懸念の全てが、いずれかの章の到達点にあるか、答えないと決めた記録がある(機械)。
- [工程8](08-integration.md)が定める全ての場面に、期待する結果が書かれている。該当しない場面は、該当しないと記録する(機械)。
- 骨組みの資料を見て、章ごとに同意する(ユーザー)。
