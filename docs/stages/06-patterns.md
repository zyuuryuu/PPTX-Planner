# 工程6 表現設計

[目次に戻る](../README.md)

資料全体の見た目を、スライドを量産する前に確定する。主張の種類と型の対応、要点の位置、資料に共通の規則、型の見本を決める。同じ種類の主張には同じ型を、違う種類の主張には違う型を使う。

形の選び方の根拠は、[形が伝える意味](../visual-grammar.md)に定める。型の定義は、[型の定義](../patterns.md)に定める。

## 成果物

### 表現の対応表 `06-patterns.yaml`

```yaml
- relation: trend          # 推移
  size: any                # 量の区分。any(問わない) / within(型の収容量以内) / over(収容量を超える)
  base: none               # 土台。none(なし) / image(画像の素材の上に描く)
  pattern: line-chart
- relation: list           # 並列の列挙
  size: within
  base: none
  pattern: plain-list
- relation: list
  size: over
  base: none
  pattern: table
```

量の区分(`size`)は、立証の設計の中身と型の収容量から、機械が決める。土台(`base`)は、立証の設計に書く。

### 要点の位置

要点を置く位置を、型ごとに1つ決め、資料の中で揃える。認める位置は、次の3つである。

| 位置 | 識別子 | 使う場合 |
|---|---|---|
| 題の直下 | `below-title` | 基本。下の2つに当たらない場合 |
| 中身の下 | `below-body` | 中身を追った結果として、結論に至る場合 |
| 中身そのもの | `body` | 要点を中身として描く場合。別の行に繰り返さない |

型ごとの既定は、[型の定義](../patterns.md)にある。資料で使う型と位置の対応を、資料の表現規約に置く。

```yaml
point_position:
  default: below-title
  line-chart: below-body
  cause-chain: below-body
  statement: body
```

要点のないスライドには、要点を描かない。「中身の下」の位置を認めるかどうかは、未確定である([未検証の前提と未決定の事項](../open-items.md))。

### 資料に共通の規則

資料の表現規約に、次を加える。

| 規則 | 内容 |
|---|---|
| 文字の大きさの下限 | 本文、図の中の文字、注のそれぞれについて定める |
| 色の割り当て | 同じ対象は、全ての図で同じ色にする。割り当てた色を、別の対象に使わない。対象と色の対応を表にする |
| 強調の方法 | 注目させる点を示す色と、その使い方を1通りに決める。強調は、1枚に1か所までとする([形が伝える意味](../visual-grammar.md)) |
| 矢印と図形の意味 | 矢印の種類ごとの意味、図形の形ごとの意味を1通りに決める |
| 流れの向き | 時間と因果を流す向きを、左から右、または上から下のどちらかに決める |
| 定位置 | 題、凡例、単位、出典、限定と出どころの脚注、注を置く位置を決める。要点の位置は、上の「要点の位置」で決める |
| 色相の数の上限 | 1枚で使う色相の数の上限を決める |
| 要約の形 | 要約の文だけにするか、根拠を短く添えるかを決める。既定は要約の文だけとする。読み手に求めることを要約に載せるかどうかも決める |
| 付帯情報 | 出力するファイルの作成者などの付帯情報に、何を入れるかを決める |

### 語彙表の凍結

設計の時期に登録してきた語彙表を、ここで承認して凍結する([使う語彙](../terms.md))。

### 型の見本 `06-samples/`

資料で使う型ごとに、実際の中身で作った見本のスライド1枚と、そのスライド仕様。

## 作り方

### 1. 主張の種類を集計する

全スライドの立証設計から、主張の種類と、項目の数などの量を集計する。

### 2. 種類ごとに主な型を選ぶ

型の定義から、次を満たす型を選ぶ。

- その主張の種類に対応する。
- 型の `implies` が、その種類のスライドの `holds` に全て含まれる。
- スライドの `holds` の主な関係(先頭の項目)が、型の `expresses` に含まれる。

候補が複数ある場合は、伝えたい含意が強く出て、伝えたくない含意が出ないものを選ぶ。

### 3. 収容量を超えるスライドを扱う

型の収容量を超えるスライドは、すぐに別の型へ切り替えない。次の順で対処する。

1. 中身を見直す。項目を分類の軸でまとめられないか、除去の検査で減らせないかを確かめる。直す場合は、工程5またはそれより前に戻る。
2. それでも超える場合に限り、型の `overflow_to` の型を使い、対応表に `size: over` の行を加える。

収容量を超えた場合の型は、主な型と、配色、題と要点の位置を揃える。

### 4. 要点の位置と、資料に共通の規則を決める

要点の位置は、型の定義の既定を出発点にする。

テンプレートが定めている項目は、テンプレートに従う。定めていない項目を、ここで決める。色の割り当てでは、仕組みの定義の要素と、複数の図に出る対象を先に割り当てる。

### 5. 型の見本を作る

資料で使う型ごとに、見本のスライドを1枚作る。その型を使うスライドのうち、量が最も多いものを選ぶ。文字が小さくなる、詰まるといった問題を、最も厳しい条件で確かめるためである。

設計セッションが、見本の分だけスライド仕様を先に書き、ビルドする。見本にしたスライドの仕様は、工程7でそのまま使う([体制とセッション](../organization.md))。

### 6. 見本を検査し、承認を得る

承認された見本とそのスライド仕様は、製造の時期に、執筆の子セッションに手本として渡す。

対応表:

- 立証設計に現れる全ての主張の種類、量の区分、土台の組が、対応表にある(機械)。 `K06-01`
- 主な型(`size` が `any` または `within`)が、同じ土台の中で、複数の主張の種類に使われていない(機械)。収容量を超えた場合の型は、複数の種類での共用を認める。 `K06-02` [定義](../visual-grammar.md#c-一貫性)
- 全てのスライドについて、型の `implies` がスライドの `holds` に含まれる。`holds` が空でない場合は、その主な関係が型の `expresses` に含まれる(機械)。`emphasized` は項目の間の関係ではないため、照合の対象から外す。 `K06-03` [定義](../visual-grammar.md#a-と-b-含意の照合)
- 型の `implies` に、まとまりや分割を伝える含意(`grouped`、`partition`)がある場合は、そのスライドの立証の設計の `axis` が空でない(機械)。 `K06-04`
- `size: over` の行に対応する全てのスライドに、中身を見直しても収容量を超える理由がある(機械)。 `K06-05`
- 全ての型が、選んだ描画の実装とテンプレートで実現できる。実現できない型は、代わりの型を選ぶか、描画の実装への要望として記録する(機械。型の一覧を返せない実装ではユーザー)。 `K06-06`

共通の規則:

- 資料で使う全ての型に、要点の位置が1つ決まっている。位置は、認める3つのいずれかである(機械)。 `K06-07`
- 成果物の表の全ての規則が、資料の表現規約にある(機械)。 `K06-08`
- 複数の図に出る対象の全てに、色が割り当てられている(機械)。 `K06-09` [定義](../visual-grammar.md#c-一貫性)

見本:

- 資料で使う全ての型に、見本がある(機械)。 `K06-10`
- 見本の描画上の診断が0件である。文字の大きさが下限以上である。色の差と、1枚で使う色相の数が、基準を満たす(機械)。 `K06-11` [定義](../visual-grammar.md#d-知覚の限界)
- 形からの読み取り: 検査セッションに見本の画像だけを見せ、項目の間に読み取れる関係を含意の語彙で答えさせる。答えが型の `implies` と合う(検査セッション)。 `K06-12` [定義](../visual-grammar.md#形からの読み取り)
- 見本の画像で最初に目が行く場所が、立証設計の `focus` と合う(検査セッション)。 `K06-13` [定義](../visual-grammar.md#e-注目)
- 見本の画像に、消しても情報が失われない要素がない(検査セッション)。 `K06-14` [定義](../visual-grammar.md#g-飾り)
- 見本で、要点が決めた位置にある。同じ文が、1枚の中に2回出ていない(検査セッション)。 `K06-15`
- 見本を見て、型の選び方と見た目に同意する(ユーザー)。 `K06-16`

語彙表:

- 同じ概念を指していそうな語と、2つの意味で使われていそうな語の候補の全てに、ユーザーの判断が記録されている(機械)。 `K06-17`
- 対象を指す語の全てに、`defined_in` か、定義が要らない理由がある(機械)。 `K06-18` [定義](../terms.md)
- 対象を指す語の全てについて、同じ対象を指しうる別の語を挙げ、`banned` に入れるかどうかを決めている(機械)。 `K06-19`
- 語彙表の内容に同意する(ユーザー)。 `K06-20`
