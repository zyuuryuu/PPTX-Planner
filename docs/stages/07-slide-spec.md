# 工程7 スライド仕様

[目次に戻る](../README.md)

スライドごとに、載せる内容を確定する。章ごと(長い章は節ごと)に1ファイルに分け、それぞれ別の執筆のセッションが書く。進め方は[体制とセッション](../organization.md)に定める。

上流の工程で、題、要点、役割、限定、出どころ、主張の種類、見せるもの、注目させる点、使う事実、型、見本が決まっている。この工程で書くのは、型のデータ、説明、ノートである。文の書き方と検査は、[文章の書き方](../writing.md)に定める。

## 成果物

`07-slides/ch2.yaml`(章ごとのスライド仕様):

```yaml
- id: ch2-s1
  status: done               # done(書き終えた) / blocked(保留。Issueの番号を添える)
  title: △△領域の年ごとの市場規模               # 題
  point: △△の領域の市場規模は、5年続けて前の年を上回った   # 要点
  qualifiers: [国内]         # 限定
  provenance: cited          # 出どころ。ストーリーラインにある場合
  body:
    type: line-chart
    data: {...}
    highlight: series-target  # 強調する要素。立証設計の注目させる点に対応する
  text: 国内市場の{F040}を占めるまでに拡大した。集計の方法は「{ch2-s2}」に示す   # 数値は事実のID、別のスライドはスライドのIDで参照する
  sources: [F015, F016, F040]
  notes: 口頭で補う説明
```

`title`、`point`、`point_from`、`role`、`qualifiers`、`provenance` は、ストーリーラインの通りに写す。

`text`、`body.data`、`notes` の数値は直接書かず、事実のIDで参照する。ビルドの際に台帳の値に置き換える。`point` は、ストーリーラインを人が読めるように数値を直接書いてよい。その数値は、そのスライドの `sources` の事実と一致させる。別のスライドへの言及は、スライドのIDで書く。ビルドの際に、そのスライドの題に置き換える([文章の書き方](../writing.md))。

要点は、ビルドが、資料の表現規約が型ごとに定める位置に1回だけ描く。`qualifiers` と `provenance` は、ビルドが、資料の型の定義の `annotation` が定める場所に描く。執筆のセッションは、これらを `text` や `body` に書き写さない。

画像の型のスライドでは、画像の素材と、注釈を付ける `regions` を参照する。位置は書かない。

```yaml
- id: ch5-s2
  status: done
  title: 納期の入力と保存
  point: 納期が空のまま保存すると、発注が止まる
  body:
    type: annotated-image-steps
    asset: A003
    crop: [due-date-field, save-button]   # この範囲が入るように切り抜く
    scenario: S-order-entry               # 番号は、場面の順から決まる
    captions:                             # 注釈の説明。スライドのノート(`notes`)とは別の項目
      due-date-field: 納期を入力する
      save-button: 保存を押す
  sources: [A003, F120]
```

### スライドの文

読み戻しの検査で、検査セッションに渡す写し。スライドごとに、読み手が目にする文面の項目だけを持つ。

| 含めるもの | 項目 |
|---|---|
| 題 | `title` |
| 要点 | `point` |
| 説明 | `text` |
| 中身の文 | `body`。型の名前(`type`)と、要素や素材を指す項目(`highlight`、`asset`、`crop`、`scenario`)は除く |

- スライドを見分けるために、`id` を残す。
- 限定(`qualifiers`)、出どころ(`provenance`)、根拠の一覧(`sources`)、ノート(`notes`)、状態(`status`)、役割(`role`)は含めない。節の要点を引くスライドでは、要点を含めない。
- 文の中の参照は、ビルドと同じく置き換える。事実への参照は台帳の値に、別のスライドへの言及はそのスライドの題にする。

## 作り方

### 1. 章を割り振る

担当: PM。

章または節ごとに執筆のセッションを起こし、章の作業票を渡す。型の見本にしたスライドの仕様を、該当する章のファイルに入れる。進め方は、[体制とセッション](../organization.md)の「PM」と「章の作業票」に定める。

### 2. スライド仕様を書く

担当: 執筆のセッション。

1. 章の作業票と、型の見本を読む。作業票には、その章の前提と到達点が含まれる。前提にある語と主張は、説明済みとして使ってよい。到達点にある語と主張は、この章の中で説明し、示す。
2. スライドごとに、型のデータ、説明、ノートを書く。素材台帳にある事実のうち、立証設計がそのスライドに割り当てたものだけを使う。
3. 字数の上限に収まらないときは、[文章の書き方](../writing.md)の「収まらないときの順序」に従う。
4. 上流の成果物の問題に気づいたら、推測で埋めない。[体制とセッション](../organization.md)の「上流の問題の戻し方」に従う。
5. 書き終えたら、検査のコマンドを実行し、完了の報告を返す。

### 3. 章を受け入れる

担当: PM。

PMが章を受け入れるのは、保留のスライドがなくなり、合格条件(機械の検査、検査セッションの検査、章の受け入れの条件)を全て満たしたときである。

## 検査の手順

### 読み戻しとの比較

担当: 検査セッション。

スライドの文だけから書き直された意味を、スライドごとに、そのスライドの `sources` の事実(`statement`、`qualifiers`、`source`)と比べる。

- 事実にある条件、範囲、数量の幅、不確かさが、書き直された意味にない場合を、食い違いとする。スライドの `qualifiers` にある限定は、落としたものとしない。
- 動作の主体が、事実と違う場合を、食い違いとする。
- 事実が述べていないことを、書き直された意味が述べている場合を、食い違いとする。出典が述べたことを、書き手の主張として読める場合を含む。

上流との一致:

- `title`、`point`、`point_from`、`role`、`qualifiers`、`provenance` が、ストーリーラインと一致する(機械)。 `K07-02`
- `body.type` が、表現の対応表が定める型と一致する(機械)。 `K07-03` [定義](../visual-grammar.md#c-一貫性)
- `sources` が立証設計の `facts` に含まれる(機械)。 `K07-04`
- ストーリーラインで `contradiction` を持つスライドの `sources` が、その事実を含み、中身の文がその事実を述べている(機械と検査セッション)。 `K07-05`
- 立証設計の `real` が true のスライドが、立証設計の `view` にある要素、つながり、場面だけを使う(機械)。 `K07-06`
- 図や表を載せるスライドに、強調する要素(`highlight`)の指定がある(機械)。 `K07-07`
- 強調が、1枚に1か所までである。数え方は[形が伝える意味](../visual-grammar.md)による(機械)。 `K07-08`
- 強調する要素が、立証設計の注目させる点に対応する(検査セッション)。 `K07-09` [定義](../visual-grammar.md#e-注目)
- 章のブランチが、その章のスライド仕様以外のファイルを変えていない(機械)。 `K07-10`

事実:

- `text`、`body.data`、`notes` に、事実のIDによらない数値がない(機械)。 `K07-11`
- `point` の数値が、`sources` の事実の値と一致する(機械。単位と表記を正規化して照合する)。 `K07-12`
- 裏付けのない文がない(検査セッション。重大な検査)。 `K07-13` [定義](../writing.md#検査セッションが判断するもの)
- 限定の残存の検査を通る(検査セッション。重大な検査)。 `K07-14` [定義](../writing.md#検査セッションが判断するもの)
- 読み戻しの検査を通る。対象のスライドに限る(検査セッション)。 `K07-15` [定義](../writing.md#検査セッションが判断するもの)

画像:

- 画像の型のスライドが参照する `regions` が、全て画像の素材にある(機械)。 `K07-16`
- 位置の出どころが `estimated` の `regions` に付けた注釈について、描いた印の周辺を切り出した画像を見て、印が `label` の対象を指している(検査セッション)。 `K07-17`
- 注釈の印と説明が、指す対象に重なっていない(機械。`regions` の位置から判定する)。 `K07-18` [定義](../visual-grammar.md#d-知覚の限界)
- 画像の型ごとに、最初に描いたスライド1枚について、描いた結果の画像を見て、印と引き出しの線が `regions` の位置に合っていることを確かめる。描画の実装による位置のずれを拾うためである(検査セッション)。 `K07-19`
- 画像の中で読ませる文字が、載せた大きさで読める(検査セッション)。 `K07-20` [定義](../visual-grammar.md#d-知覚の限界)

文:

- [文章の書き方](../writing.md)の機械で測る検査を通る(機械)。 `K07-21`
- [使う語彙](../terms.md)の検査を通る(機械)。 `K07-22`
- 型の項目ごとの収容量に収まる(機械)。 `K07-23` [定義](../visual-grammar.md#d-知覚の限界)
- `{}` で囲んだ参照が、全て、実在する事実かスライドを指す(機械)。 `K07-24`
- 削る検査、重複の検査、主体の検査を通る(検査セッション)。 `K07-25` [定義](../writing.md#検査セッションが判断するもの)
- 言い直しの検査で挙がったスライドの全てに、前後のスライドに統合するか、残すかの判断がある(検査セッションが挙げ、設計セッションが決める)。統合する場合は、工程4に戻す。 `K07-26` [定義](../writing.md#検査セッションが判断するもの)
- ブリーフに「読み手が既に知っている」と書かれた内容の説明を含まない(検査セッション)。 `K07-27`
- 型の `implies` が成り立つ中身になっている。立証設計の `holds` と食い違う中身を書いていない(検査セッション)。 `K07-28`
- `defined_in` が示すスライドが、その語を実際に説明している。定義が要らない理由が、ブリーフの読み手の水準に合っている(検査セッション)。 `K07-29` [定義](../terms.md)

図と表([形が伝える意味](../visual-grammar.md)の検査):

- 複数のスライドに出る対象が、資料の表現規約の色の割り当ての通りに、同じ色と同じ名前で指定されている。図や表のデータは、対象を語彙表または仕組みの定義のIDで参照する(機械)。 `K07-30`
- 色の割り当てのある色を、別の対象に使っていない。強調の色を、対象の色に使っていない(機械)。 `K07-31`
- 並べて比べる、同じ種類の量を表す複数のグラフが、同じ軸の範囲を使う(機械)。 `K07-32`
- 棒グラフの量の軸が0から始まる。軸を2本持つグラフに理由がある。構成比の合計が100%になる(機械)。 `K07-33`
- 立体のグラフを使わない(機械。型の定義に置かない)。 `K07-34`
- 構成比を円で表すのは、項目が少ない場合に限る。項目の数の上限は型の収容量で定める(機械)。 `K07-35`
- アイコンが、仕組みの定義の要素に対応するものだけである(機械)。 `K07-36`
- 図の要素とつながりの数が型の収容量を超える場合は、警告とする(機械。警告)。 `K07-37`

状態:

- 保留のスライドの全てに、Issueの番号がある(機械)。 `K07-38`

章の受け入れ:

- 受け入れ済みの章とあわせて、同じ言い回しと同じ文型の出現回数を集計する。資料の表現規約の目安を超えた場合は、設計セッションが直し方を決め、章の執筆のセッションに渡す(機械が集計する)。 `K07-39`
- 描画上の診断に、文字と背景の色の差、隣り合う色の差、1枚で使う色相の数を含める(機械)。 `K07-40` [定義](../visual-grammar.md#d-知覚の限界)
- その章をビルドし、描画上の診断(文字のあふれ、要素の重なり、描かれなかった内容、文字の大きさの下限)が0件である(機械)。 `K07-41` [定義](../visual-grammar.md#d-知覚の限界)
- 骨組みの資料の該当する章を実物に差し替え、主な読み手の通読をその章について実行する。前の章が未完成の場合は、入口の状態を章の前提と到達点から与える。重大度が高のエラーがなく、章の出口の状態が到達点と合う(読み手の役のセッションが読み、PMが出口の状態と到達点を機械的に照合する)。 `K07-42` [定義](08-integration.md#実行の方法)
