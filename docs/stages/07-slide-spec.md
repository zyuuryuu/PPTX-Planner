# 工程7 スライド仕様

[目次に戻る](../README.md)

スライドごとに、載せる内容を確定する。章ごと(長い章は節ごと)に1ファイルに分け、それぞれ別の執筆のセッションが書く。進め方は[体制とセッション](../organization.md)に定める。

上流の工程で、題、要点、役割、限定、出どころ、主張の種類、見せるもの、注目させる点、使う事実、型、見本が決まっている。この工程で書くのは、型のデータ、説明、ノートである。文の書き方と検査は、[文章の書き方](../writing.md)に定める。

## 成果物

`07-slides/ch2.yaml`(章ごとのスライド仕様):

```yaml
- id: ch2-s1
  status: done               # done(書き終えた) / blocked(保留。Issueの番号を添える)
  title: △△領域の年ごとの市場規模               # 題
  point: △△の領域の市場規模は、5年続けて前の年を上回った   # 要点
  qualifiers: [国内]         # 限定
  provenance: cited          # 出どころ。ストーリーラインにある場合
  body:
    type: line-chart
    data: {...}
    highlight: series-target  # 強調する要素。立証設計の注目させる点に対応する
  text: 国内市場の{F040}を占めるまでに拡大した。集計の方法は「{ch2-s2}」に示す   # 数値は事実のID、別のスライドはスライドのIDで参照する
  sources: [F015, F016, F040]
  notes: 口頭で補う説明
```

`title`、`point`、`point_from`、`role`、`qualifiers`、`provenance` は、ストーリーラインの通りに写す。

`text`、`body.data`、`notes` の数値は直接書かず、事実のIDで参照する。ビルドの際に台帳の値に置き換える。`point` は、ストーリーラインを人が読めるように数値を直接書いてよい。その数値は、そのスライドの `sources` の事実と一致させる。別のスライドへの言及は、スライドのIDで書く。ビルドの際に、そのスライドの題に置き換える([文章の書き方](../writing.md))。

要点は、ビルドが、資料の表現規約が型ごとに定める位置に1回だけ描く。`qualifiers` と `provenance` は、ビルドが、資料の型の定義の `annotation` が定める場所に描く。執筆のセッションは、これらを `text` や `body` に書き写さない。

画像の型のスライドでは、画像の素材と、注釈を付ける `regions` を参照する。位置は書かない。

```yaml
- id: ch5-s2
  status: done
  title: 納期の入力と保存
  point: 納期が空のまま保存すると、発注が止まる
  body:
    type: annotated-image-steps
    asset: A003
    crop: [due-date-field, save-button]   # この範囲が入るように切り抜く
    scenario: S-order-entry               # 番号は、場面の順から決まる
    captions:                             # 注釈の説明。スライドのノート(`notes`)とは別の項目
      due-date-field: 納期を入力する
      save-button: 保存を押す
  sources: [A003, F120]
```

## 開始の条件

- 引き継ぎの検査([体制とセッション](../organization.md))に通っている。

## 作り方

1. 執筆のセッションは、章の作業票と、型の見本を読む。作業票には、その章の前提と到達点が含まれる。前提にある語と主張は、説明済みとして使ってよい。到達点にある語と主張は、この章の中で説明し、示す。
2. スライドごとに、型のデータ、説明、ノートを書く。素材台帳にある事実のうち、立証設計がそのスライドに割り当てたものだけを使う。
3. 字数の上限に収まらないときは、[文章の書き方](../writing.md)の「収まらないときの順序」に従う。
4. 上流の成果物の問題に気づいたら、Issueを立て、そのスライドを保留にして、ほかのスライドを進める。推測で埋めない。上流の成果物を自分で直さない。
5. 書き終えたら、検査のコマンドを実行し、完了の報告を返す。

## 合格条件

上流との一致:

- `title`、`point`、`point_from`、`role`、`qualifiers`、`provenance` が、ストーリーラインと一致する(機械)。
- `body.type` が、表現の対応表が定める型と一致する(機械)。
- `sources` が立証設計の `facts` に含まれる(機械)。
- ストーリーラインで `contradiction` を持つスライドの `sources` が、その事実を含み、中身の文がその事実を述べている(機械と検査セッション)。
- 立証設計の `real` が true のスライドが、立証設計の `view` にある要素、つながり、場面だけを使う(機械)。
- 図や表を載せるスライドに、強調する要素(`highlight`)の指定がある(機械)。
- 強調が、1枚に1か所までである。数え方は[形が伝える意味](../visual-grammar.md)による(機械)。
- 強調する要素が、立証設計の注目させる点に対応する(検査セッション)。
- 章のブランチが、その章のスライド仕様以外のファイルを変えていない(機械)。

事実:

- `text`、`body.data`、`notes` に、事実のIDによらない数値がない(機械)。
- `point` の数値が、`sources` の事実の値と一致する(機械。単位と表記を正規化して照合する)。
- 裏付けのない文がない(検査セッション。重大な検査)。
- 限定の残存の検査を通る(検査セッション。重大な検査)。
- 読み戻しの検査を通る。対象のスライドに限る(検査セッション)。

画像:

- 画像の型のスライドが参照する `regions` が、全て画像の素材にある(機械)。
- 位置の出どころが `estimated` の `regions` に付けた注釈について、描いた印の周辺を切り出した画像を見て、印が `label` の対象を指している(検査セッション)。
- 注釈の印と説明が、指す対象に重なっていない(機械。`regions` の位置から判定する)。
- 画像の型ごとに、最初に描いたスライド1枚について、描いた結果の画像を見て、印と引き出しの線が `regions` の位置に合っていることを確かめる。描画の実装による位置のずれを拾うためである(検査セッション)。
- 画像の中で読ませる文字が、載せた大きさで読める(検査セッション)。

文:

- [文章の書き方](../writing.md)の機械で測る検査を通る(機械)。
- [使う語彙](../terms.md)の検査を通る(機械)。
- 型の項目ごとの収容量に収まる(機械)。
- 読み手に見せる文に、内部のIDがない。`{}` で囲んだ参照が、全て、実在する事実かスライドを指す(機械)。
- 削る検査、重複の検査、主体の検査を通る(検査セッション)。
- 言い直しの検査で挙がったスライドの全てに、前後のスライドに統合するか、残すかの判断がある(検査セッションが挙げ、設計セッションが決める)。統合する場合は、工程4に戻す。
- ブリーフに「読み手が既に知っている」と書かれた内容の説明を含まない(検査セッション)。
- 型の `implies` が成り立つ中身になっている。立証設計の `holds` と食い違う中身を書いていない(検査セッション)。

図と表([形が伝える意味](../visual-grammar.md)の検査):

- 複数のスライドに出る対象が、資料の表現規約の色の割り当ての通りに、同じ色と同じ名前で指定されている。図や表のデータは、対象を語彙表または仕組みの定義のIDで参照する(機械)。
- 色の割り当てのある色を、別の対象に使っていない。強調の色を、対象の色に使っていない(機械)。
- 並べて比べる、同じ種類の量を表す複数のグラフが、同じ軸の範囲を使う(機械)。
- 棒グラフの量の軸が0から始まる。軸を2本持つグラフに理由がある。構成比の合計が100%になる(機械)。
- アイコンが、仕組みの定義の要素に対応するものだけである(機械)。
- 図の要素とつながりの数が型の収容量を超える場合は、警告とする(機械)。

状態:

- 保留のスライドの全てに、Issueの番号がある(機械)。
- PMが章を受け入れるのは、保留のスライドがなくなり、上の条件(機械の検査と、検査セッションの検査の両方)と、下の「章の受け入れ」の条件を全て満たしたときである。

章の受け入れ:

- 受け入れ済みの章とあわせて、同じ言い回しと同じ文型の出現回数を集計する。資料の表現規約の目安を超えた場合は、設計セッションが直し方を決め、章の執筆のセッションに渡す(機械が集計する)。
- 描画上の診断に、文字と背景の色の差、隣り合う色の差、1枚で使う色相の数を含める(機械)。
- その章をビルドし、描画上の診断(文字のあふれ、要素の重なり、描かれなかった内容、文字の大きさの下限)が0件である(機械)。
- 骨組みの資料の該当する章を実物に差し替え、主な読み手の通読をその章について実行する。前の章が未完成の場合は、入口の状態を章の前提と到達点から与える。重大度が高のエラーがなく、章の出口の状態が到達点と合う([工程8](08-integration.md))。
