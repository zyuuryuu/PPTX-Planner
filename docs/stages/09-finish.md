最終のビルドを行い、出力を検査し、ユーザーの承認を得て引き渡す。

## この工程でやらないこと

- 調査の追加、スライドの追加、見出しの変更をしない。必要なら、[フィードバックと修正](../feedback.md)の反映先の範囲に従って上流に戻すか、次の版に回す。
- ユーザーに、全スライドの通読や、1枚ごとの承認を求めない。
- ユーザーに、誤字や数値の確認を求めない。機械で確かめる。
- ユーザーに「資料がブリーフの問いに答えているか」を白紙で問わない。答えは工程2で承認済みである。
- 警告を0件にするために直さない。警告は一覧にして、判断をユーザーに渡す。
- 人がPowerPointで直した内容を、仕様に同期しない。

## 作り方

### 1. 最終のビルドを行う

### 2. 出力を機械的に検査する

描画上の診断は、工程7の章の受け入れで既に通っている。ここでは最終のビルドで再実行する。加えて、最終の出力でしか確かめられないことを確かめる。

### 3. 検査の報告を作る

機械が、判断が要る箇所を集めて1ページにまとめる。全スライドではなく、見るべき箇所を、理由を添えて先に示すためのものである。

| 載せるもの | 理由 |
|---|---|
| 要約と、章のまとめ | 最も読まれるスライドである |
| 骨組みの承認の後に、見出しや順序が変わった箇所 | 承認済みのものが変わっている |
| 証言だけに頼る主張、見解が割れている主張 | 根拠が弱い |
| 図の中で不明のまま残した箇所、位置を推定した注釈 | 正確さが確かめきれていない |
| 収容量を超えた型を使ったスライド、表現規約の例外 | 規則から外れている |
| 警告、受け入れた指摘、閉じていないIssue | 問題が残っている |
| 結論の復元の結果と、ブリーフの問い | 並べて示し、合っているかを見る |

読み手側の指標(章ごとの枚数、型の分布、1枚あたりの字数の分布、同じ型の連続、発表時間の見積もり)は、資料の表現規約の目安を超えたものだけを載せる。

### 4. 抜き取りで確かめる

無作為に選んだスライドについて、ユーザーが、中身と、出典の引用箇所を見比べる。検査の報告は、危ないと分かっている箇所しか示せない。誰も気づいていない誤りがどの程度残っているかを知るために行う。結果は集計の記録に残す。

### 5. ユーザーが承認する

ユーザーには、検査の報告と抜き取りの結果を示し、次の2つを問う。

- 承認した骨組みから、意図せず変わった箇所はないか。
- 残っている問題を承知のうえで、このまま出せるか。

### 6. 引き渡す

承認をGitのタグとして記録する。以後のPowerPointでの手直しは自由とし、作り直すと手直しが消えることを伝える。

発表の準備などでユーザーが全スライドを見たときの指摘は、[フィードバックと修正](../feedback.md)の流れでまとめて扱う。

### 7. 集計する

次の資料のための材料として、次を集計する。合格条件にはしない。

- 守らせる方法ごとの、検査で見つかった違反の数。
- 全ての検査を通った後に、ユーザーの指摘と抜き取りで見つかった問題の数。
- 語の登録の申請の数、検査と執筆の往復の回数。

表現規約、型の定義、資料の型の定義への書き戻しは、引き渡しの後に、規則の追加と整理の手順([表現規約](../style-rules.md))で行う。

## 合格条件

出力:

- 描画上の診断(文字のあふれ、要素の重なり、描かれなかった内容、文字の大きさの下限、禁則と不自然な改行)が0件である(機械)。
- スライドの枚数と見出しが、ストーリーライン、および導出したスライドと一致する(機械)。
- 目次、ページ番号、他のスライドへの言及が、全て解決している(機械)。
- 出力から抜き出した文字の中の数値が、全て素材台帳の値と一致する(機械)。
- 出典の一覧が、使った事実を全て含む(機械)。
- 置き換えられずに残った事実のIDがない(機械)。
- 配布する資料のノートが空である。口頭の資料のノートに、内部向けの記述(Issueの番号、作業の覚え書き)がない(機械)。
- ファイルの作成者などの付帯情報が、表現規約の定めの通りである(機械)。
- 過去の指摘のうち、機械の規則になったものに違反がない(機械)。

警告(合否にしない):

- 口頭の資料で、ノートの字数から見積もった発表時間が、ブリーフの制約を超える。
- 読み手側の指標が、資料の表現規約の目安を超える。

承認:

- 検査の報告に、作り方の3の表の全ての項目が載っている(機械)。
- 抜き取りを行い、結果を記録している(ユーザー)。
- 2つの問いに、ユーザーが答えている(ユーザー)。

## 未決の点

- 全スライドの通読を、承認の条件から外してよいか。
- 抜き取りの枚数。誤りが見つかったときに、どこまで検査をやり直すか。
- 描画の実装が、文字の折り返しの位置を報告できるか。報告できない実装では、字数が収容量に近いスライドに限って、検査セッションが画像を見て、語の途中で改行していないかを確かめる。
- 発表時間の見積もりに使う、話す速さの値。

## ほかの工程に及ぶ変更

- 描画の実装によるあふれの自動分割を禁じ、診断で止めることを、描画の実装の条件にする。
- 文字の折り返しの位置を報告することを、描画の実装の条件にする。
