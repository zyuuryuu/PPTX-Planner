# 工程2 主張の整理

[目次に戻る](../README.md)

集めた事実から、問いへの答えを組み立てる。組み立ては探索の計画の問いの木に沿って行う。読み手に伝える順序への並べ替えは、工程3で行う。

## 成果物

### 問いごとの答え `02-answers.yaml`

探索の計画の全ての問いに、答えを1文で書いたもの。

```yaml
- question: Q1.1
  answer: △△の領域の市場規模は、過去5年で1.5倍になった
  evidence: [F015, F016]
- question: Q1
  answer: △△の領域の市場は、今後も伸びる見込みが高い
  from: [Q1.1, Q1.2, Q1.3]     # 子の問いの答えから導いた
  assumes: [△△の領域の伸びを支える規制が続く]   # 導くときに置いた前提
```

### 主張の骨子 `02-claims.yaml`

```yaml
answer: 〇〇事業は、△△に絞って継続すべきである
hypothesis: H1                 # 採った仮説。どの仮説とも違う答えになった場合はnull
axis: 市場、自社の強み、採算   # 主張を何の基準で分けたか。問いの木の最上位の分け方を引き継ぐ
claims:
  - id: C1
    statement: 市場全体は縮小するが、△△の領域だけは伸びている
    question: Q1               # 問いの木のどの問いへの答えか
    evidence: [F012, F015, F021]
    assumes: [△△の領域の伸びを支える規制が続く]
    objections:                # 反論と、それへの答え
      - objection: 伸びているのは大手の寡占による一時的な現象ではないか
        response: 新規参入の件数も増えている
        evidence: [F021]
  - id: C2
    statement: ...
    question: Q2
    evidence: [F030]
contradictions:                # 採った仮説を否定する事実と、その扱い
  - fact: F033
    handling: qualify          # rebut(反駁する) / qualify(結論に条件を付ける) / change(結論を変える)
    note: 地方では伸びが鈍い。対象を都市部に限る条件を結論に加えた
```

## 作り方

### 1. 末端の問いに答える

探索の計画の末端の問いごとに、集まった事実から答えを1文で書く。探索の結果が `not-found` の問いは「分からない」と書く。`disputed` の問いは、割れている見解をそのまま書く。

### 2. 親の問いに答える

親の問いの答えを、子の問いの答えから導く。導くときに置いた前提は `assumes` に書く。これを問いの木の根まで繰り返す。

仮の結論から書き始めない。仮の結論を先に書いて事実を当てはめると、探索で偏りを防いだ意味が薄れる。

### 3. 仮説と比べる

問いの木の根の答えを、仮説の一覧と比べる。あわせて、仮説ごとに、重要度が `high` の問いに答える事実のうち、その仮説を否定するものの数を一覧にする(機械)。

支持する事実が多い仮説ではなく、否定する事実が少ない仮説を有力とみる。支持する事実は複数の仮説を同時に支持することが多く、決め手になりにくい。

この一覧と根の答えをユーザーに示し、どの答えを採るかをユーザーが決める。

### 4. 主張の骨子を書く

採った答えを `answer` とする。問いの木で根の直下にある問いの答えを、支える主張とする。同じ階層から取ることで、主張の水準が揃う。

主張の数が上限を超える場合は、問いの木の最上位の分け方を見直す。工程1の探索の計画を直すことになるため、ユーザーの承認を取り直す。

### 5. 否定する事実と反論を扱う

採った仮説を否定する事実の全てについて、扱いを `contradictions` に書く。検査セッションが組み立てた反論のうち、答えるべきものを `objections` に書く。

## 合格条件

問いごとの答え:

- 探索の計画の全ての問いに答えがある(機械)。
- 末端の問いの答えに、`verified: true` の事実が紐づく。答えが「分からない」の場合を除く(機械)。
- 親の問いの答えが、子の問いの答えと `assumes` から導ける(検査セッション)。

主張の骨子:

- 全ての主張が、問いの木の同じ階層の問いに対応する(機械)。
- 主張の数が、資料の表現規約が定める上限以下である(機械)。
- `answer` と各主張が、否定の検査と具体性の検査を通る(検査セッション)。
- 主張の分け方が、分類の軸の検査を通る(検査セッション)。
- 全ての主張に、`verified: true` の事実が1件以上紐づく(機械)。
- 1つの `origin` だけに頼る主張がない。ある場合は、そのことを主張に明記する(機械)。
- `testimony` だけに頼る主張を、承認の際にユーザーに示す(機械)。
- 探索の結果が `disputed` の問いに関わる主張が、見解が割れていることを述べている(検査セッション)。
- 探索の限界として残った問いに関わる主張が、その限界を述べている(検査セッション)。
- 採った仮説を否定する事実(`stance` が `contradicts`)の全てが、`contradictions` にある(機械)。
- 独立した導出: 仮説の一覧を読んでいない検査セッションに、ブリーフの問いと素材台帳だけを渡して答えを書かせる。`answer` と食い違う場合は、違いをユーザーに示す(検査セッション)。
- 反論の検査: 検査セッションが、素材台帳を使って `answer` への最も強い反論を組み立てる。その反論が `objections` にあるか、付録の想定問答に入っている(検査セッション)。
- `answer` がブリーフの問いに答えている(ユーザー)。

最後に決めるのはユーザーである。証拠と食い違う点を承知のうえで結論を維持する場合は、その判断を設計の判断の記録に残す。
