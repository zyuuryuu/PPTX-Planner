# 工程0 依頼の確定

[目次に戻る](../README.md)

資料が答える問いを固定する。問いが決まらないと、探索の範囲が決まらない。

成果物 `00-brief.md` の項目:

- 聴衆(誰が読むか、何を既に知っているか)
- 目的(読んだ人に何を決めて、あるいは何をしてほしいか)
- 答えるべき問い(1文)
- 資料の種類([語彙と区分](../vocabulary.md)が定める目的と伝え方)
- 制約(枚数の目安、発表時間、テンプレート、言語、期限)
- 手元の資料の一覧

この段階では結論を書かない。結論は工程2で決まる。ユーザーが既に持っている結論は、仮説として工程1の仮説の一覧に書く。

作り方:

- 設計セッションが、上の項目を順に1つずつ聞く。選択肢があるものは選択肢を示す。
- 答えるべき問いは、聞かずに案を出す。ほかの項目の答えをもとに問いの文を2つか3つ作り、ユーザーが選ぶか直す。
- 「未定」を答えとして認める。未定の項目は、誰がいつ決めるかを添えて記録する。推測で埋めない。
- 目的ごとに、次を追加で聞く。

  | 目的 | 追加で聞くこと |
  |---|---|
  | 提案書 | 最終的に決める人は誰か。現状維持や他の案との比較になるか |
  | 調査報告 | 調査の範囲と、範囲に含めないもの |
  | 製品紹介 | 相手が今使っている手段と、その不満 |
  | 研修資料 | 受講者の今の水準。受講後に何で習得を確かめるか |

合格条件:

- 全ての項目に、答えか「未定」の記録がある(機械)。
- 検査セッションがブリーフだけを読んで書いた「誰に、何のために、何の問いに答える資料か」が、設計セッションの理解と一致する(検査セッション)。
- ブリーフの内容に同意する(ユーザー)。
