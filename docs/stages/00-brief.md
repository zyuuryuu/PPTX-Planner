# 工程0 依頼の確定

[目次に戻る](../README.md)

資料が答える問いを固定する。問いが決まらないと、探索の範囲が決まらない。

## 成果物

`00-brief.md`(ブリーフ)。項目は次の通り。

| 項目 | 内容 |
|---|---|
| 資料の型 | [資料の型](../deck-types.md)の定義から選ぶ。合う型がなければ、この資料用の定義を作る |
| 伝え方 | 口頭で説明する、配布して読ませる、のいずれか |
| 主な読み手 | 立場。1人、または1つの立場に定める |
| 副次的な読み手 | 主な読み手のほかに読む人と、その立場 |
| 読み手が既に知っていること | 資料で説明しなくてよい内容 |
| 読み手の立場と懸念 | 賛成、反対、中立のいずれか。気にしそうな点、反対しそうな点 |
| 目的 | 読み手の今の状態と、読んだ後の状態。読んだ人に何を決めて、あるいは何をしてほしいか |
| 答えるべき問い | 1文 |
| 扱わない範囲 | この資料で答えないこと |
| 使われる場面 | 会議で映す、事前に配る、質疑がある、など |
| 書き手の立場 | 読み手から見た書き手(部下、外部の業者、専門家など) |
| 制約 | 枚数の目安、発表時間、テンプレート、言語、文体、期限。枚数の数え方は、[語彙と区分](../vocabulary.md)による |
| 外に出せない情報 | 資料に載せてはいけない名前や情報(顧客の名前、個人の名前、社内だけの名称など)。写り込みの検査の材料にする |
| 手元の資料 | 一覧 |
| 型ごとの追加の項目 | 資料の型の定義が定める追加の質問(`brief_questions`)への答え |

各項目には、状態を付ける。

| 状態 | 意味 |
|---|---|
| 確定 | ユーザーが答えた、または推定をユーザーが確認した |
| 推定 | 設計セッションが依頼文や手元の資料から読み取った。ユーザーは未確認 |
| 未定 | まだ決まっていない。誰がいつ決めるかを添える |

この段階では結論を書かない。結論は工程2で決まる。ユーザーが既に持っている結論は、仮説として工程1の仮説の一覧に書く。

## 資料の表現規約の作成

この工程で、資料の表現規約 `style.yaml` を作る。資料の型の定義の `limits` と、個人の表現規約を写す([不合格と修正の手順](../rework.md))。

## 受け入れの問い

ブリーフの項目は、工程9で、出来上がった資料を受け入れるかどうかを判断する基準になる。ブリーフを承認するときに、次の問いで最後に判断することを、ユーザーに示す。

| ブリーフの項目 | 受け入れの問い |
|---|---|
| 目的 | 読み終えた読み手は、求めた判断や行動に進めるか |
| 答えるべき問い | 資料の結論は、問いへの答えになっているか |
| 読み手の懸念 | 懸念の1つ1つに、答えがあるか |
| 扱わない範囲 | 範囲の外の内容が入っていないか |
| 制約 | 枚数、時間、テンプレート、期限を守っているか |

この資料に固有の受け入れの条件があれば、ここで加える。

## 作り方

1. 設計セッションが、ユーザーの最初の依頼文と手元の資料から読み取れる項目を埋め、状態を推定とする。
2. 推定の項目を、ユーザーに確認する。
3. 残りの項目を、1つずつ聞く。選択肢があるものは選択肢を示す。
4. 答えるべき問いは、聞かずに案を出す。ほかの項目の答えをもとに問いの文を2つか3つ作り、ユーザーが選ぶか直す。
5. 資料の型の定義が定める追加の質問(`brief_questions`)を聞く。


分からない項目は、推測で確定にせず、未定として記録する。

## 合格条件

<!-- checks:begin -->
<!-- この区間は tools/checks_table.py が checks.yaml から作る。直接は直さない -->

- 全ての項目が、確定または未定である。推定のまま残る項目がない(機械)。 `K00-01`
- 主な読み手、目的、答えるべき問いが確定である。この3つは未定を認めない(機械)。 `K00-02`
- 答えるべき問いが1つである(検査セッション)。 `K00-03`
- 答えるべき問いの、答えの形が決まっている。はいかいいえ、どれを選ぶか、どれだけか、どうやるか、のいずれかである(検査セッション)。 `K00-04`
- 答えるべき問いの答えが、目的に書いた行動につながる(検査セッション)。 `K00-05`
- 検査セッションがブリーフだけを読んで、「誰に、何のために、何の問いに答える資料か」を要約する。その要約が自分の意図と合っている(ユーザー)。 `K00-06`
- 資料の表現規約 `style.yaml` があり、資料の型の定義の `limits` と個人の表現規約を写している(機械)。 `K00-07`
- 「外に出せない情報」が確定である。画像を使う資料では、未定を認めない(機械)。 `K00-08`
- ブリーフの内容に同意する(ユーザー)。 `K00-09`

<!-- checks:end -->

## 後から変える場合

探索や主張の整理の結果、問いの立て方が違っていたと分かることがある。その場合はブリーフを直し、ユーザーの承認を取り直す。波及する範囲は[不合格と修正の手順](../rework.md)に定める。
