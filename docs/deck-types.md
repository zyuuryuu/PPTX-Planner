# 資料の型

[目次に戻る](README.md)

資料の目的による違いは、工程の定義には書かず、資料の型の定義としてデータで持つ。工程は、ブリーフで選んだ型の定義を参照する。

## 型の根にあるもの

型は、読み手を今の状態からどの状態に動かすかで決まる。

| 型 | 今の状態 | 動かしたい先 |
|---|---|---|
| 調査報告 | 知らない | 知っている |
| 製品紹介 | 関心がない | 関心がある |
| 提案書 | 迷っている | 決めた |
| 研修資料 | できない | できる |

## 定義の項目

| 項目 | 使う工程 | 内容 |
|---|---|---|
| `change` | 0 | 読み手の今の状態と、動かしたい先。合う型がない資料で、資料用の定義を起案するときの手がかりにする |
| `apex` | 2 | 主張の骨子の頂点に置くもの。`answer` の形を決める |
| `brief_questions` | 0 | ブリーフで追加で聞くこと |
| `perspectives` | 1 | 探索で必ず調べる観点 |
| `decomposition` | 1 | 問いの最初の分解 |
| `chapter_order` | 3 | 章の並びの定型 |
| `limits` | 0 | 合格条件の初期値(主張の数の上限、字数の上限、集計の目安、往復の上限など)。工程0で資料の表現規約に写し、以後の工程はそこから読む |

`decomposition` と `chapter_order` は出発点であり、資料に合わなければ変えてよい。`perspectives` は必須で、探索の計画に全て含める。

定義の中身は、その種類の資料の経験則を具体的に書く。「読み手に合わせる」のような一般論は書かない。

## 置き場と追加

Plannerに付属する定義、個人の定義、資料の定義の3層で持つ。下の層が上の層を上書きする。

合う型がない資料では、設計セッションがブリーフの読み手の今の状態と動かしたい先から、その資料用の定義を起案する。ユーザーが承認して使う。繰り返し使う見込みがあれば、個人の定義として保存する。

フィードバックで得た知見のうち、型に関わるものは、型の定義に書き戻す。規則の追加と同じく、足すたびに既存の内容と整理する([表現規約](style-rules.md))。

伝え方(口頭で説明する、配布して読ませる)は型とは別に、ブリーフで指定する。伝え方によって `limits` の初期値を変える。

## 付属する定義

`limits` の値は未確定である。

### 提案書

```yaml
id: proposal
change: {from: 迷っている, to: 決めた}
apex: 提案とその理由
brief_questions:
  - 最終的に決める人は誰か
  - 現状維持や他の案との比較になるか
perspectives: [何もしない場合, 他の案, 費用, リスク, 反対する立場の論点]
decomposition: [問題はあるか, 原因は何か, 提案は効くか, 実行できるか, 費用に見合うか]
chapter_order: [結論, 問題, 解決策, 効果, 実行の計画, 費用とリスク, 依頼したいこと]
limits: null
```

### 調査報告

```yaml
id: research-report
change: {from: 知らない, to: 知っている}
apex: 問いへの答え
brief_questions:
  - 調査の対象とする期間、地域、分野は何か
perspectives: [範囲の定義, 対立する見解, データの限界]
decomposition: [現状はどうか, なぜそうなったか, 今後どうなるか, 何を意味するか]
chapter_order: [要約, 目的と方法, 結果, 考察, 示唆]
limits: null
```

### 製品紹介

```yaml
id: product-introduction
change: {from: 関心がない, to: 関心がある}
apex: 相手にとっての価値
brief_questions:
  - 相手が今使っている手段は何か。その不満は何か
perspectives: [競合する手段, 向かない用途]
decomposition: [相手は何に困っているか, どう解決するか, 他の手段と何が違うか, 導入できるか]
chapter_order: [相手の課題, 解決の方法, 特長, 事例, 導入の進め方]
limits: null
```

### 研修資料

```yaml
id: training
change: {from: できない, to: できる}
apex: 受講後にできること
brief_questions:
  - 受講者の今の水準はどの程度か
  - 受講後に何で習得を確かめるか
perspectives: [受講者が陥りやすい誤り]
decomposition: [何ができるようになるか, 前提となる知識は何か, 手順は何か, どこで誤りやすいか]
chapter_order: [目標, 全体像, 単元ごとの説明と演習, まとめ]
limits: null
```

研修資料では、主張の骨子の `answer` が学習の目標に、主張が習得する項目に替わる。この読み替えで工程がそのまま使えるかは未検証である。
