# 形が伝える意味

[目次に戻る](README.md)

状態: 草案。枠組みも細部も、ユーザーとの合意の前である。

スライドの形(配置、囲み、線、色、大きさ)は、中身とは別に、それ自体が意味を伝える。読み手は形から関係を読み取る。形が伝える関係と、中身の実際の関係が食い違うと、読み手は誤解するか、理解に余計な時間を使う。

この文書は、形の手がかりごとに読み手が受け取る意味を定め、起きる問題を類型に分け、検査の方法を定める。[工程6](stages/06-patterns.md)の表現設計と、型の定義が、この文書を参照する。

## 含意の語彙

形が伝える関係を、次の語彙で表す。型の定義と、スライドごとの立証の設計が、この語彙を使う。

| 識別子 | 意味 |
|---|---|
| `grouped` | 同じ仲間である |
| `partition` | 全体を、1つの基準で漏れなく重なりなく分けている |
| `equal-weight` | 互いに同じ重みである |
| `comparable` | 同じ観点で比べられる |
| `ordered` | 順序がある(時間、手順、優先) |
| `causal` | 一方が他方の原因である |
| `hierarchical` | 上位と下位の関係がある |
| `cyclic` | 最後から最初に戻る |
| `connected` | 何らかの関係がある |
| `proportional` | 見た目の量が、数値に比例する |
| `independent-axes` | 2つの軸が互いに独立している |
| `distinct-kinds` | 種類が違う |
| `emphasized` | ほかより重要である |
| `opposed` | 2つが対立している、または対になっている |
| `contained` | 一方が他方に含まれる |
| `shared` | 共通する部分がある |
| `ascending` | 段階を追って高まる |
| `main-and-sub` | 一方が主で、他方が補足である |

## 形の手がかりと、読み手が受け取る意味

手がかりは単独でも働くが、重なると強まる。同じ大きさの箱を横に並べると、囲み、整列、横並びの3つが重なり、「比べられる」「全体を分けている」が強く伝わる。同じ項目を、囲まずに縦に並べると、列挙として読まれる。

含意の強さは、強、中、弱で示す。強さは慣習と書き手の経験に基づく見立てで、実験で確かめたものではない。型の見本を使った「形からの読み取り」の検査と、フィードバックで直していく。

### 配置

| 手がかり | 読み手が受け取る意味 | 規則 |
|---|---|---|
| 横に並べる | `comparable`(強)、`equal-weight`(強)、`ordered`(弱。左が先) | 比べさせたい場合に使う。比べる意図がない並列の項目は、横に並べない |
| 縦に並べる | `ordered`(中。上が先、上が重要)、`comparable`(弱) | 列挙に使う。並べる順に理由を持たせる(重要度、時間、階層のいずれか) |
| 格子に並べる | `partition`(強)、`equal-weight`(強)。順序は伝わらない | 全体を分けた項目に使う。行と列に意味がある場合は、見出しを付ける |
| 左右に2つを対称に置く | `opposed`(強)、`comparable`(強) | 2つを対比させる場合に限る |
| 左右に大小をつけて置く | `main-and-sub`(強) | 主と補足の関係がある場合に限る。大きいほうを主とする |
| 中心と周りに置く | 中心が周りの全てと `connected`(強)。周りは `equal-weight`(中) | 中心に置くのは、周りの全てと関係を持つものに限る |
| 入れ子にする | `contained`(強)、`hierarchical`(強) | 内側が外側の一部である場合に限る |
| 重ねる | `shared`(強) | 共通する部分が実際にある場合に限る。重なりの部分に、何が共通するかを書く |
| 字下げする | `hierarchical`(強) | 下げた項目が、上の項目の一部または詳細である場合に限る。字下げは2段までとする |
| 階段状に上げていく | `ascending`(強)、`ordered`(強) | 段階を追って水準が上がる場合に限る |
| 環状に並べる | `cyclic`(強)、`ordered`(強) | 最後から最初に実際に戻る場合に限る |
| 積み上げる、ピラミッドにする | `hierarchical`(強。下が上を支える) | 下の層が上の層の前提になっている場合に限る |
| 2つの軸の上に置く | `independent-axes`(強)、`comparable`(強) | 2つの軸が独立で、全ての対象を両方の軸で測れる場合に限る |
| 表にする | 行が `comparable`(強)。列が同じ観点 | 全ての行を、全ての列の観点で述べられる場合に限る。空欄が多い表は、表にしない |
| 近くに置く | `grouped`(強) | 関係のあるものだけを近づける。グループの間の余白を、グループの中の余白より広くとる |
| 離して置く | 別のものである(中) | 関係のあるものを離さない。図とその説明は近くに置く |
| 端を揃える | 同じ水準である(中) | 同じ水準のものは揃える。水準が違うものは、揃えずにずらす |
| 上に置く、下に置く | 上が結論や見出し(中)。下が補足や出典(中) | スライドごとの結論は上に置く。出典と注は下に置く |

時間と因果は左から右に、または上から下に流す。逆向きにしない。資料の中で、流れの向きを1通りに決める。

### 囲みと線

| 手がかり | 読み手が受け取る意味 | 規則 |
|---|---|---|
| 箱や背景で囲う | `grouped`(強) | 囲うのは、まとまりに名前を付けられる場合に限る |
| 囲んだ箱を並べる | `partition`(強)、`distinct-kinds`(中) | 分類の軸を明示できる場合に限る |
| 線でつなぐ | `connected`(強) | 全ての線に、関係の種類を言える。言えない線を引かない |
| 矢印でつなぐ | `ordered`(強)または `causal`(強) | 矢印の意味(順序、因果、データの流れなど)を資料の中で1通りに決める。意味の違う矢印は、線の種類を変える |
| 線で区切る | 別のものである(中) | 余白で足りる場合は、線を引かない |
| 番号を振る | `ordered`(強) | 順序がある場合に限る |

### 色、大きさ、形

| 手がかり | 読み手が受け取る意味 | 規則 |
|---|---|---|
| 同じ色、形、大きさにする | 同じ種類である(強) | 同じ種類のものは同じ見た目にする。違う種類のものは違う見た目にする |
| 同じ大きさにする | `equal-weight`(強) | 重みが違うものを、同じ大きさにしない |
| 大きくする | `emphasized`(強)、または量が大きい | 大きさを変えるのは、重要さか量の違いを示す場合に限る。量を示す場合は比例させる |
| 濃くする、鮮やかにする | `emphasized`(強)、または量が大きい | 強調の色は、スライドごとに注目させる点の1か所だけに使う |
| 色相を変える | `distinct-kinds`(強)。順序は伝わらない | 順序や量の大小を、色相の違いで表さない。濃淡で表す |
| 図形の形を変える | `distinct-kinds`(強) | 形の意味(判断はひし形、など)を資料の中で1通りに決める |
| 面積、長さ、角度で量を表す | `proportional`(強) | 量は、位置か長さで表すのを優先する。面積と角度は読み取りが不正確になる |
| 絵やアイコンを添える | その対象そのものを指す(中) | 実在の対象を識別する場合に限る。飾りとして使わない |

### スライドをまたぐ手がかり

| 手がかり | 読み手が受け取る意味 | 規則 |
|---|---|---|
| 前のスライドと同じ形にする | 同じ種類の話である(強) | 同じ種類の主張には同じ型を使う |
| 前のスライドと形を変える | 何かが変わった(強) | 見た目の変化には、必ず意味を持たせる |
| 同じ対象を同じ位置に置く | 同じ対象である(強) | 全体図と詳細図、前後の比較では、同じ対象の位置を保つ |
| 同じ対象を同じ色にする | 同じ対象である(強) | 色の割り当てを資料の中で固定する |

### 画像と注釈

| 手がかり | 読み手が受け取る意味 | 規則 |
|---|---|---|
| 画像を載せる | 実物である(強) | 実物を写した画像だけを載せる。作り物の画面を実物として見せない |
| 画像の上に番号の印を置く | `ordered`(強) | 順序がある場合に限る。番号の並びを、目の動き(左上から右下)にできるだけ合わせる |
| 画像の一部を枠や色で示す | `emphasized`(強) | 注目させる点に対応する箇所に限る |
| 画像の一部から線を引き出して説明を置く | 説明がその箇所を指す(強) | 線の先が、指す箇所に届いている。線どうしを交差させない |
| 画像の周りを暗くする | 明るい部分が `emphasized`(強) | 注目させる範囲が1か所の場合に使う |

- 画像は、注目させる範囲に切り抜く。画面全体を縮めて、文字が読めない大きさにしない。位置関係を示す必要がある場合は、全体と拡大を組にする。
- 印と説明で、指す対象を隠さない。
- 1枚の画像に付ける注釈の数は、型の収容量以下とする。
- 同じ画面を複数のスライドで使う場合は、切り抜く範囲と大きさを揃える。
- 注釈の印の形と色を、資料の中で1通りに決める。

### 含意を弱める、強める

型を選ぶときは、伝えたい含意が強く出て、伝えたくない含意が出ない組み合わせを選ぶ。

| したいこと | 方法 |
|---|---|
| 比べさせずに並列の項目を示す | 囲まずに縦に並べる |
| 順序を感じさせずに並べる | 番号と矢印を付けない。格子に並べる |
| 比べさせる | 横に並べ、対応する項目の高さを揃える。または表にする |
| 対立を際立たせる | 左右に対称に置き、間に余白か区切りを入れる |
| 主と補足を分ける | 大きさと位置に差をつける |

### 根拠

- 近くに置く、同じ見た目にする、囲う、つなぐ: ゲシュタルトの法則(近接、類同、共通領域、連結)。
- 中央に置く: 図と地。
- 大きさ、濃さ、色相、形の使い分け: Bertinの視覚変数。
- 強調が探さなくても目に入ること: 前注意的な知覚。
- 量を位置や長さで表すのを優先すること: ClevelandとMcGillの実験。
- 絵やアイコンを飾りに使わないこと、図と説明を近くに置くこと: Mayerの一貫性の原理と、近くに置く原理。
- 見た目の変化に意味を持たせること: Kosslynの原理。
- 並べる向き、対称、階段、字下げなどの配置の含意: 資料作成の慣習に基づく。対応する実験は確認していない。

## 問題の類型

| 類型 | 内容 | 例 |
|---|---|---|
| A. 偽の含意 | 形が、中身にない関係を伝える | 単なる論点の列挙をカードで並べる。順序のないものを矢印でつなぐ。前提の関係がないものをピラミッドにする |
| B. 含意の欠落 | 中身にある関係を、形が伝えない | 因果の連鎖を箇条書きにする。2案の比較を、別々の段落に書く |
| C. 不一致 | 同じものが違う見た目になる。違うものが同じ見た目になる | 同じ対象が図によって違う色になる。意味の違うスライドが同じ型になる |
| D. 知覚の限界の超過 | 見分けられない、読めない | 文字が小さい。色の差が小さい。要素が多すぎる |
| E. 注目の誤り | 目を引く場所が、注目させる点と違う | 全てを強調する。飾りが最も目立つ。注目させる点に強調がない |
| F. 量の歪み | 見た目の量が、数値と合わない | 棒グラフの軸が0から始まらない。立体のグラフ。面積で長さの比を表す |
| G. 飾り | 情報を運ばない要素がある | 意味のないアイコン、囲み、区切り線、影、グラデーション |

類型は、フィードバックで新しい種類の問題が見つかるたびに見直す。追加の際は、既存の類型に入らないことを確かめる。

## 検査

### A と B: 含意の照合

型の定義に、その型が伝える含意(`implies`)と、表せる関係(`expresses`)を書く。スライドごとの立証の設計に、項目の間に実際に成り立つ関係(`holds`)を書く。

- 型の `implies` が、全てスライドの `holds` に含まれる(機械)。含まれないものがあれば、偽の含意である。
- スライドの `holds` のうち主な関係が、型の `expresses` に含まれる(機械)。含まれなければ、含意の欠落である。
- `holds` の申告が正しい(検査セッション)。語彙ごとに、はいかいいえで答えられる問いで確かめる。

  | 含意 | 問い |
  |---|---|
  | `partition` | 分けた基準を一言で言えるか。どの項目にも入らないものはないか。2つの項目に入るものはないか |
  | `equal-weight` | 1つだけ重要な項目、1つだけ補足にすぎない項目はないか |
  | `comparable` | 全ての項目を、同じ観点で述べているか |
  | `ordered` | 項目を入れ替えると、意味が変わるか |
  | `causal` | 前の項目がなければ、後の項目は起きないか |
  | `hierarchical` | 下位の項目は、上位の項目の一部または前提か |
  | `cyclic` | 最後の項目の結果が、最初の項目の入力になるか |
  | `independent-axes` | 一方の軸の値が決まっても、他方の軸の値は決まらないか |

### 形からの読み取り

型の見本を作った段階で、検査セッションに見本の画像だけを見せ、項目の間にどんな関係があると読み取れるかを含意の語彙で答えさせる。答えが型の `implies` と合わなければ、型の定義か描画の実装を直す。これは型ごとに1回行う。スライドごとには行わない。

### C: 一貫性

- 同じ主張の種類で同じ量の区分のスライドが、同じ型を使う(機械)。
- 主な型が、複数の主張の種類に使われていない(機械)。収容量を超えた場合の型は、共用を認める。
- 同じ対象が、全ての図で同じ色と同じ名前になる。色の割り当ては資料の表現規約に置く(機械)。
- 矢印と図形の形の意味が、資料の中で1通りである(機械。型の定義と表現規約から決まる)。

### D: 知覚の限界

- 文字の大きさが、資料の表現規約が定める下限以上である。例外を認めない(機械。描画の実装が報告する)。
- 文字と背景、隣り合う色の差が、基準以上である(機械)。
- 型の項目ごとの字数が、収容量以下である。超える場合は不合格とする(機械)。
- 項目の数が型の収容量を超える場合は、工程6で、中身を見直すか、収容量を超えた場合の型に切り替える(機械)。
- 図の要素とつながりの数が型の収容量を超える場合は、警告とする(機械)。
- 1枚で使う色相の数が、資料の表現規約が定める上限以下である(機械)。
- 画像の中で読ませる文字が、載せた大きさで読める(検査セッション)。
- 注釈の印と説明が、指す対象に重なっていない(機械。`regions` の位置から判定する)。

### E: 注目

- 強調の色が、スライド仕様で指定した要素にだけ付く(構造。描画の実装が付ける)。
- 指定した要素が、立証の設計の `focus` に対応する(検査セッション)。
- 強調する要素が、スライドに1か所である。複数の場合は理由がある(機械)。
- 見本の画像で最初に目が行く場所が、`focus` と合う(検査セッション。型ごとに1回)。

### F: 量の歪み

- 棒グラフの量の軸が0から始まる(機械)。
- 立体のグラフを使わない(機械。型の定義に置かない)。
- 軸を2本持つグラフは、理由がある場合に限る(機械)。
- 構成比のグラフの合計が100%になる(機械)。
- 構成比を円で表すのは、項目が少ない場合に限る。項目の数の上限は型の収容量で定める(機械)。
- 同じ種類の量を表す複数のグラフが、同じ軸の範囲を使う。並べて比べる場合に限る(機械)。

### G: 飾り

- 型の定義に、情報を運ばない要素(影、グラデーション、意味のないアイコン)を置かない。
- 見本の画像で、消しても情報が失われない要素がない(検査セッション。型ごとに1回)。
- アイコンは、仕組みの定義の要素に対応するものだけを使う(機械)。

## 根拠にした文献

書誌の細部は、原典で確認していない。

- ゲシュタルトの法則(近接、類同、連続、図と地): Wertheimer (1923)。共通領域は Palmer (1992)、連結は Palmer と Rock (1994)。
- 視覚変数(位置、大きさ、形、明度、色相など)と、表せるデータの性質: Bertin『Sémiologie graphique』(1967)。
- 量の読み取りの正確さの順位(共通の軸上の位置、長さ、角度、面積の順): Cleveland と McGill (1984)。
- 量の歪みと、情報を運ばない要素: Tufte『The Visual Display of Quantitative Information』(1983)。
- 前注意的な知覚(色や大きさの違いが、探さなくても目に入る): Treisman と Gelade (1980)、Ware『Information Visualization』。
- 一貫性の原理(無関係な要素を除くと理解が上がる)、注目の合図、近くに置く原理: Mayer『Multimedia Learning』。
- 変化は情報を運ぶ、形と意味を合わせる、ほか: Kosslyn『Clear and to the Point』(2007)。
