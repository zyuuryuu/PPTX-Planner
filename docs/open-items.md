# 未検証の前提と未決定の事項

[目次に戻る](README.md)

## 未検証の前提

- 見出しの復元が、中身と見出しの不一致を実際に検出できるか。
- 結合テストで、読み手の役のセッションが状態を持ち越してエラーを挙げる方法が、実際に働くか。見逃しと誤検出がどの程度か。
- 使う語彙を先に決める方法で、用語の揺れを実際に防げるか。一般の語と分野に固有の語の線引きで、誤検出がどの程度出るか。縛りによって文が不自然にならないか。
- 語の登録の審査で、設計セッションが類似の語と誤用を正しく判定できるか。審査を1件ずつ順に行うことが、製造の進みを妨げないか。
- 検査セッションが判断する検査(裏付けのない文、限定の残存、削る検査、読み戻し)の見逃しと誤検出が、どの程度か。
- 含意の照合(型の `implies` とスライドの `holds`)が、形と中身の食い違いを実際に防げるか。`holds` の申告を、検査セッションが正しく確かめられるか。
- LLMが画像から要素の位置を推定する精度と、印の周辺を切り出して確かめる検査で、誤りを拾えるか。
- 写り込みの検査で、隠すべきものを検査セッションが見落とさないか。
- 形の手がかりの含意の強さの見立てが、読み手の実際の受け取り方と合うか。
- 見本の分だけスライド仕様を先に書く進め方が、工程の順序として無理なく回るか。
- 描画の実装によらない型の語彙を、表現力を落とさずに定められるか。
- 見出しと結論1行に直接書いた数値を、単位と表記を正規化して台帳と機械的に照合できるか。丸めや「約」で誤検出がどの程度出るか。
- 全体を扱う成果物(章構成、ストーリーライン、章の前提と到達点、立証設計)が、100枚規模でも1つのセッションで扱える分量に収まるか。
- SlideCraftを使う場合、表現の型をレイアウト固定の記法で制御できるか。SlideCraftは内容の形からレイアウトを自動で選ぶため、同じ種類のスライドが別のレイアウトになる可能性がある。
- SlideCraftの図の種類(12種とMermaid経由の4種)と区切りの記法で、ビジネス文書に必要な型が足りるか。
- Pythonのコードを使う場合、型ごとの関数を使い回す方式で、文字のあふれを画像を見ずに検出できるか。
- 成果物の書式(YAML)が、LLMにとって書きやすく、人にとって読みやすいか。
- 独立した導出と反論の検査が、仮の結論への偏りを実際に見つけられるか。
- 仕組みの定義を挟む方法で、図の捏造と図をまたぐ不整合を実際に防げるか。抜き出しの手間が引き合うか。
- 独立した2回の抜き出しの差分が、誤りの発見に役立つか。
- 意味の検査が、検査セッションによって実際に中身のない主張を落とせるか。検査セッションもLLMで、AIらしい文章を自然だと感じる傾向は同じである。
- 字数による収容量の見積もりに、どの程度の余裕が要るか。文字の幅は一定でない。
- PMを新しく起こす場合と、設計セッションが兼ねる場合とで、読み込み量と判断の質がどう違うか。
- 執筆の子セッションが章を担当し続ける場合、記憶に残った古い前提が、上流の変更の後に悪さをしないか。
- 画像の読み取りが、人の手直しをどの程度の細かさまで拾えるか。
- 規則の数が増えたとき、LLMがどこまで守れるか。数が増えるほど守られにくくなる見込みである。

## 未決定の事項

- 試作で最初に使う資料の型(提案書、調査報告、製品紹介、研修資料のどれか)。
- 複数の型が混ざる資料の扱い。資料全体の型は1つとし、章ごとに別の型の定型を借りる形が候補である。
- 資料の型の定義の `limits` の値。
- 1節あたりの枚数の上限と、見出しの字数の上限。
- 結合テストの集計で使う目安の値と、往復の回数の上限。
- 結合テストで、スライドの画像を読むか、ビルドした実物から抜き出した文字を読むか。
- 抜き取りの枚数と、誤りが見つかったときに検査をやり直す範囲。
- 発表時間の見積もりに使う、話す速さの値。
- 発表の後の反応を、誰がどの形で記録するか。
- 主張の種類の語彙の名前と範囲。付属する型の一覧。
- 型ごとの収容量の値と、文字の大きさの下限の値。
- 文の機械的な検査の上限の値(1文の字数、読点の数など)。良い資料の実測から決めるのが望ましい。
- 検査と執筆の往復の回数の上限。
- 仕組みの定義から生成した図で、配置の調整をどこまで認めるか。
- IssueをGitHubに置くか、リポジトリの中のファイルに置くか。
- 人が作った良い資料を見本として、表現規約の初期値を抽出するか。
- 既存の資料を直す場合の入口。新規に作る場合の工程が固まった後に扱う。
- 提供形態(Claude Codeのスキル群とするか)。
- 最初に対応する描画の実装。
- 機械的な検査を実装する言語と置き場。
