# 検査

[目次に戻る](README.md)

## 検査の台帳

全ての検査を、台帳 [`checks.yaml`](checks.yaml) に1件ずつ置く。工程の文書の合格条件は、道具 `tools/checks_table.py` が台帳から作る。検査を足す、変える、やめるときは、台帳を直して道具を実行する。工程の文書の合格条件は、直接は直さない。

| 項目 | 内容 |
|---|---|
| `count` | 台帳の先頭に1つ置く、検査の件数。項目を足すとき、消すときに、あわせて直す |
| `id` | 検査のID。一度付けたら変えない。`K`、工程の番号、連番で作る。複数の工程で使う検査は `KX` とする |
| `stage` | 実行する工程。複数あれば並べる |
| `group` | 合格条件の中の小見出し |
| `target` | 対象の成果物と項目 |
| `check` | はいかいいえで答えられる条件の文 |
| `judge` | 判定者。`machine`(機械)、`inspector`(検査セッション)、`user`(ユーザー)、`reader`(読み手の役のセッション)、`designer`(設計セッション)、`pm`(PM)。複数あれば並べる |
| `judge_text` | 判定者の括弧の中の書き方。判定者の名前を並べるだけでは足りない場合に書く |
| `critical` | 重大な検査なら true |
| `level` | 合否にしない検査なら `warning`(警告) |
| `refers` | 複数の工程で使う検査を束ねて指す項目で、指す検査のID。束ねる項目は、検査の件数に数えない |
| `note` | 条件に添える決まり |
| `defined_in` | 検査のやり方や、語の定義がある文書 |

検査のやり方と理由は、台帳に書かない。`defined_in` が指す文書に書く。

## 意味の検査

次の検査を、主にスライドの中身を書く前の工程で行う。検査は、はいかいいえで答えられる問いにする。「良い文章か」という問いでは、LLMは見逃すためである。

| 検査 | 問い |
|---|---|
| 否定の検査 | その文を否定した文は、主張として成り立つか |
| 具体性の検査 | 主語と述語があり、対象、数値、条件のいずれかを含むか |
| 除去の検査 | それを抜くと、上位の主張や要点が成り立たなくなるか。要点のないスライドでは、それを抜くと、節の要点を読み手が理解できなくなるか |
| 分類の軸の検査 | 何の基準で分けたかを一言で言えるか。項目は同じ水準か。1つの項目が2つのグループに入らないか。グループの数は軸から決まっているか |
| 語彙と文体の検査 | [文章の書き方](writing.md)と[使う語彙](terms.md)が定める検査を通るか |

それぞれの検査を当てる対象と工程は、台帳に置く。

否定の検査の例: 「品質の向上は重要である」は、否定した「品質の向上は重要でない」が主張として成り立たない。この要点は何も述べていない。

要点への検査は、要点を持つスライドだけに当てる。要点のないスライド([語彙と区分](vocabulary.md))には、否定の検査と具体性の検査を当てない。

## 題と要点の通読

中身を見ずに、題と要点だけを順に読んで、筋を確かめる。次の3段で読む。付録は対象から外す。

| 段 | 読むもの | 確かめること |
|---|---|---|
| 1 | 章の要点だけ | 順に読むと、主張の骨子の `answer` が導ける |
| 2 | 章ごとに、節の要点だけ | 順に読むと、章の要点が導ける |
| 3 | 節ごとに、スライドの題と要点 | 要点を順に読むと、節の要点が導ける。要点のないスライドは、題と役割から、節の要点を支えることが分かる |

どの段でも、題を目次のように並べて読み、同じ話題の題が重複していないこと、話題の順が自然であることを確かめる。

1段目と2段目は工程3の、3段目は工程4の合格条件として、検査セッションが行う。工程8では、「題と要点だけ」の場面([工程8](stages/08-integration.md))として、読み手の役のセッションが3段を通して行う。

## 検査の実行

機械的な検査は、1つのコマンドにまとめる。

| 検査 | 実行する時点 |
|---|---|
| 書式、IDの参照先、使う語彙、文の機械的な検査、数値の参照、分量の上限、担当外のファイルの変更 | コミット前 |
| ビルド、描画上の診断 | 工程の合格判定のとき |
| 検査セッションによる検査 | 工程の合格判定のとき |

工程の合格判定では、機械の検査を先に行い、通ったものを検査セッションが検査する。

コミット前の検査は飛ばすことができる。そのため、工程の合格判定とPMによる受け入れの際に、同じコマンドをもう一度実行する。

### 検査セッションの手順

担当: 検査セッション。

全ての検査に共通の手順である。

1. 作業票が挙げる検査の条件の文を、対象に1件ずつ当てる。条件ごと、対象ごとに判定し、まとめて判定しない。
2. 条件を満たすと言い切れなければ、不合格とする。
3. 合格にも、判定の根拠にした箇所を引用する。不合格に添えるものは、[不合格と修正の手順](rework.md)の「不合格のときの手順」の1による。
4. 直し方を提案しない。対象を直さないことは、[体制とセッション](organization.md)の「セッションの分離」と、[不合格と修正の手順](rework.md)の「原則」による。
5. 結果を、検査の記録に書く。書式は、[不合格と修正の手順](rework.md)の「検査の記録」に定める。

### 独立に書く

担当: 検査セッション。

検査の中には、入力を限ったセッションに独立に書かせ、その答えを元の成果物と比べるものがある。書く作業と比べる作業は、別の検査セッションが行う。元の成果物を書いたセッションは、どちらも行わない。

書く作業は、次の通りに行う。

1. 作業票の入力だけを読む。
2. 検査の条件の文が書かせるとしているものを書く。入力から分からないことは、分からないと書く。推測で埋めない。
3. 答えを `work/answers/<作業のid>.yaml` に置く。章ごとに行う作業では、`work/answers/<作業のid>-<章のID>.yaml` とする。
4. 合否を判定しない。検査の記録を書かない。合否は、比べる作業が判定する。

```yaml
- target: ch2-s1      # 何について書いたか。スライド、型などのID。対象が1つだけの作業では書かない
  answer: △△の領域の市場規模は、5年続けて前の年を上回った   # 書いた答え
```

### 比べる

担当: 検査セッション。

独立に書いたセッションとは別の検査セッションが行う。何と何を比べ、何を食い違いとするかは、各工程の文書の「検査の手順」に定める。

1. 独立に書いた答えと、元の成果物の該当する項目を、対象ごとに並べて読む。
2. 食い違いごとに、答えと元の両方を引用する。
3. どちらが正しいかを決めない。
4. 食い違いを示す相手は、検査の条件の文と、各工程の定めによる。定めがなければ、食い違いを不合格として扱う。

## 守らせる方法の強さ

規則を、守らせる方法で分ける。各規則を、できるだけ強い方法に置く。

| 方法 | 例 | 見込み |
|---|---|---|
| 構造上、破れない | 数値や要素の名前をIDで参照する。図を仕組みの定義から生成する | ほぼ確実 |
| 機械の検査で、通らないと先に進めない | 使う語彙、文の長さ、読点の数、参照先の有無 | 検出できる範囲では確実。検査の文面だけを満たす書き方が起きうる |
| 検査セッションが判断する | 削る検査、裏付けのない文、限定の残存 | 不明。見逃しがある前提で使う |
| 指示するだけ | 「簡潔に書く」 | 弱い。この方法だけに頼る規則を作らない |

機械の検査の規則は、執筆のセッションが覚えている必要がない。検査が違反の箇所を返し、直すまで受け入れられないためである。

順守の程度を測るため、次を記録する。

- 方法ごとに、検査で見つかった違反の数。
- 全ての検査を通った後に、ユーザーの指摘で見つかった問題の数。

## 検査の効力

検査は、台帳に載って初めて有効とする。台帳の1件ごとに、実行する工程と判定者を必ず示す。工程の文書以外(形が伝える意味、使う語彙、仕組みの定義、文章の書き方)には、検査のやり方と理由だけを書く。

不合格の後の扱い、警告の扱い、検査の記録は、[不合格と修正の手順](rework.md)に定める。

## 重大な検査

検査セッションの判定には見逃しがある。見逃したものが外に出ると実害が大きい検査を、重大な検査として指定し、2段で行う。

重大な検査は、台帳の `critical` で指定する。

- 重大な検査は、別のセッションで2回行う。2回目は、1回目と別のモデルで行う。モデルが違うと、見落とす箇所が違うためである。
- 2回の結果が食い違ったものは、設計の時期はユーザーが、製造の時期は設計セッションが見て決める。設計セッションが決められないものと、設計セッションが書いた成果物についてのものは、ユーザーに上げる。
- 工程9の抜き取りで誤りが見つかった場合は、その誤りを拾うはずだった重大な検査を、同じ章の全てのスライドでやり直す。見つかった割合が高い場合は、全ての章に広げる。割合の目安は、資料の表現規約に置く。
