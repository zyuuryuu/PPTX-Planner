# 語彙と区分

[目次に戻る](README.md)

## 主張の種類の語彙

Plannerが固定の核を持ち、資料ごとに追加を許す。機械的な検査と、描画の実装への対応づけが、固定の語彙を前提にするためである。

| 区分 | 種類 | 識別子 |
|---|---|---|
| 数量 | 構成比 | `composition` |
| 数量 | 項目の比較 | `item-comparison` |
| 数量 | 推移 | `trend` |
| 数量 | 分布 | `distribution` |
| 数量 | 相関 | `correlation` |
| 概念 | 手順 | `process` |
| 概念 | 構造・階層 | `structure` |
| 概念 | 2案の対比 | `contrast-options` |
| 概念 | 前後の対比 | `contrast-before-after` |
| 概念 | 因果 | `causality` |
| 概念 | 位置づけ(2つの軸の上に対象を置く) | `positioning` |
| 概念 | 並列の列挙 | `list` |
| 概念 | 言い切り(図表を使わず1文で述べる) | `statement` |
| 仕組みの記述 | 構成(部品と、そのつながりや配置) | `architecture` |
| 仕組みの記述 | 要素の関係(データや概念の間の関係) | `entity-relation` |
| 仕組みの記述 | やり取り(複数の主体の間のやり取りの順序) | `interaction` |
| 仕組みの記述 | 状態の遷移(取りうる状態と、移る条件) | `state-transition` |
| 仕組みの記述 | 分岐のある流れ(条件で分かれる処理の流れ) | `branching-flow` |
| 仕組みの記述 | 日程(作業の期間と前後関係) | `schedule` |
| 実物 | 実物の提示(画面、写真、文書の抜粋などを見せる) | `exhibit` |

数量の5種はZelazny『Say It With Charts』の分類による。「仕組みの記述」の区分は、UMLが図を構造の図と振る舞いの図に分けているのに倣う。実在の仕組み、業務、組織、画面を写す図は、区分によらず、[仕組みの定義](model.md)から作る。語彙の名前と範囲は未確定である。

## 資料の構造

資料は、章、節、項の3段で組む。項はスライド1枚である。4段以上に分けない。

| 段 | 題 | 要点 | 決める工程 |
|---|---|---|---|
| 章 | 必須 | 必須。主張の骨子の主張に対応させる | 3 |
| 節 | 必須 | 必須。問いごとの答えに対応させる。本論の章では、章に割り当てた主張の問いの、子の問いへの答えを使う | 3 |
| 項(スライド) | 必須 | なくてよい。ない場合は、役割を書く | 4 |

題と要点の書き方は、[文章の書き方](writing.md)に定める。

- 章は、1つ以上の節からなる。本編のスライドは、いずれかの節に入る。付録のスライドは、節に入れない。
- 節が1つだけの章では、節の要点を書かず、章の要点を引く(`point_from: chapter`)。

### 要点のないスライド

要点のないスライド(`point: null`)は、節の要点を支えるものとして扱う。役割(`role`)を次から選んで書く。役割を書けないスライドは、資料に入れない。

| 役割 | 識別子 | 内容 |
|---|---|---|
| 詳しい説明 | `detail` | 節の要点を理解するために要る定義、仕組み、手順、内訳 |
| 演習の問題 | `exercise` | 読み手に解かせる問い |
| 参照用 | `reference` | 後で引くための一覧や表 |

### 節の要点を載せるスライド

節の項の数と中身で決める。項の数には、自動で作るスライドを含めない。境目の枚数は、資料の表現規約の `section_summary_min_slides` に置く。

| 節 | 節の要点を載せるスライド |
|---|---|
| 項の数が境目の枚数以上 | 節のまとめ。節の最後に置く |
| 項の数が境目の枚数より少なく、次のいずれかに当たる。要点のないスライドがある。スライドが1枚だけである。章にただ1つの節である | 節の最後のスライド。そのスライドの要点を書かず、節の要点を引く(`point_from: section`) |
| 項の数が境目の枚数より少なく、上のどれにも当たらない | 載せなくてよい |

## スライドの区分

ストーリーラインに書く中身のあるスライド(本編と付録)のほかに、自動で作るスライド(導出と半導出)がある。

| 区分 | 例 | 作り方 | 検査 |
|---|---|---|---|
| 導出 | 表紙、目次、章扉、出典の一覧、出どころの印の説明 | ビルドの際に、上流の成果物から機械的に作る。出どころの印の説明は、[資料の型](deck-types.md)の定義が印を使うと定める資料に置く。目次には、章と節の題を載せる。章扉には、章の題と、その章で答える問い(章構成の `question`)を載せる | 不要 |
| 半導出 | 要約、章のまとめ、節のまとめ | 設計の時期に承認済みの文を、そのまま並べる。新しい文を書かない。要約は、主張の骨子の要約の文を使う。章のまとめは、章の要点と、その章の節の要点を順に並べる。節のまとめは、節の要点と、節内のスライドの要点を順に並べる | 工程8の開始の条件と、要約だけを読む場面 |
| 付録 | 詳細なデータ、本編から外した素材 | 本編と同じ工程で作る。ストーリーラインに、本編のどのスライドを補うかを記録する | [題と要点の通読](checks.md)と除去の検査からは外す。ほかの合格条件は本編と同じ |

節が1つだけの章には、章のまとめを置かない。章の要点は、節の要点を載せるスライドに載る。

枚数は、本編の中身のあるスライドの数で数える。ブリーフの枚数の目安と、章構成の枚数の配分は、この数を指す。自動で作るスライドは、別に数えて示す。
