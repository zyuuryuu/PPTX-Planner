## 主張の種類の語彙

Plannerが固定の核を持ち、資料ごとに追加を許す。機械的な検査と、描画の実装への対応づけが、固定の語彙を前提にするためである。

| 区分 | 種類 | 識別子 |
|---|---|---|
| 数量 | 構成比 | `composition` |
| 数量 | 項目の比較 | `item-comparison` |
| 数量 | 推移 | `trend` |
| 数量 | 分布 | `distribution` |
| 数量 | 相関 | `correlation` |
| 概念 | 手順 | `process` |
| 概念 | 構造・階層 | `structure` |
| 概念 | 対比(2案、前後) | `contrast` |
| 概念 | 因果 | `causality` |
| 概念 | 位置づけ(2つの軸の上に対象を置く) | `positioning` |
| 概念 | 並列の列挙 | `list` |
| 概念 | 言い切り(図表を使わず1文で述べる) | `statement` |
| 仕組みの記述 | 構成(部品と、そのつながりや配置) | `architecture` |
| 仕組みの記述 | 要素の関係(データや概念の間の関係) | `entity-relation` |
| 仕組みの記述 | やり取り(複数の主体の間のやり取りの順序) | `interaction` |
| 仕組みの記述 | 状態の遷移(取りうる状態と、移る条件) | `state-transition` |
| 仕組みの記述 | 分岐のある流れ(条件で分かれる処理の流れ) | `branching-flow` |
| 仕組みの記述 | 日程(作業の期間と前後関係) | `schedule` |
| 実物 | 実物の提示(画面、写真、文書の抜粋などを見せる) | `exhibit` |

数量の5種はZelazny『Say It With Charts』の分類による。「仕組みの記述」の区分は、UMLが図を構造の図と振る舞いの図に分けているのに倣う。この区分のうち実在の仕組みを写す図は、[仕組みの定義](model.md)から作る。語彙の名前と範囲は未確定である。

## スライドの区分

主張の骨子から導かれるスライド(本編)のほかに、次の区分がある。

| 区分 | 例 | 作り方 | 検査 |
|---|---|---|---|
| 導出 | 表紙、目次、章扉、出典の一覧 | ビルドの際に、上流の成果物から機械的に作る | 不要 |
| 半導出 | 要約、章のまとめ | 工程8で、承認済みの文(答え、主張、章の主張、結論1行)を選び、並べ、短くして組み立てる。新しい主張と事実は書かない | 工程8の開始の条件と、要約だけを読む場面 |
| 付録 | 詳細なデータ、本編から外した素材 | 本編と同じ工程で作る。ストーリーラインに、本編のどのスライドを補うかを記録する | 見出しを順に読む検査と除去の検査からは外す。ほかの合格条件は本編と同じ |
