# Claude Code での実現

[目次に戻る](../README.md)

[体制とセッション](../organization.md)の決まりを、Claude Code のクラウドのセッションで実現する方法を定める。

## 子セッションを起こす

- 子セッションは、セッションを起こす道具で、別のセッションとして起こす。
- 同じセッションの内部で動くサブエージェントは、[体制とセッション](../organization.md)の「下請けの処理」に当たる。子セッションにしない。
- 版の指定には、ブランチの名前を使う。短いコミットIDを使わない。短いコミットIDでは、起動に失敗する。
- 作業票を、最初のメッセージにする。

## スキル

- スキルの置き場は、リポジトリの `.claude/skills/<スキルの名前>/` である。コミットしてあれば、子セッションで使える。
- 作業票の1行目に `/スキルの名前` を書いて呼ぶ。
- 会話が要約された後に読み直されるのは、`SKILL.md` の先頭だけである。守ることを `SKILL.md` の先頭に置く。

## 入力を限る作業

元のファイルを作業の場所から外す手段は、必要なフォルダだけを取得する指定である。セッションを起こす道具の `sparse_checkout_paths` に書く。

- 取得するフォルダは、その作業の置き場 `restricted/<作業のid>` と、担当のスキルのフォルダ `.claude/skills/<スキルの名前>` の2つとする。道具 `tools/work_order.py` が、「起こす側の手順」に出す。
- 作業の場所に置かれるのは、指定したフォルダ、その親のフォルダの直下のファイル、リポジトリの根のファイルだけである。`restricted/`、`.claude/`、`.claude/skills/` の直下に、見せてはいけないファイルを置かない。
- 指定しなかったフォルダは、置かれない。読む道具は「ファイルがない」と答え、ファイル名の検索は0件になる。スキルの一覧には、取得したスキルだけが出る。
- 置かれていないファイルも、`git show HEAD:<パス>` で中身を取り出せる。`git ls-tree` で名前も見える。作業票の指示の文で縛る。

## プッシュ

Gitの中継は、ブランチの更新と、新しいブランチの作成を通す。次の2つは拒否する。

- ブランチの削除。
- ブランチ以外のもの(タグなど)のプッシュ。

## 人の許可待ち

- Bash の命令で、人の許可を待つ表示が出て、子セッションが止まることがある。
- 子セッションには、ファイルの読み書きに、シェルの命令ではなく、ファイルを読む道具と書く道具を使わせる。入力を限る作業では、作業票がそう指示する。
- 起こした側は、起こした後に、子セッションの状態と記録を読み、起動したことと、進んでいることを確かめる。止まっていたら、ユーザーに知らせる。

## 道具の前提

次の2つの道具は、Claude Code を前提にしている。ほかの環境で使うときは、道具を直す。

| 道具 | 前提にしていること |
|---|---|
| `tools/build_skills.py` | スキルを `.claude/skills/` に、`SKILL.md` の先頭に `name` と `description` を持つ書式で作る |
| `tools/work_order.py` | 作業票の1行目に `/スキルの名前` を書く。「起こす側の手順」に、取得するフォルダの一覧を出す。作業票で、ファイルを読む道具と書く道具を使うよう指示する |
