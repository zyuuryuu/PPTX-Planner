# スライド作成工程の定義(草案 v0.23)

状態: 草案。細部と書式は未確定である。実物で確かめていない前提は、[未検証の前提と未決定の事項](open-items.md)を参照。

## 目的

LLMによるスライド作成は、枚数が増えると次の問題を起こす。

- 文章が崩れ、スライド間の一貫性が失われる。
- 主張のないスライドが増える。
- 中身のない言い回し、目的に対して多すぎる情報、基準のないグルーピングが混じる。
- 修正のたびにPPTXの座標や書式を読み込み、消費するトークンが膨らむ。

この定義は、スライド作成を工程に分け、工程ごとに成果物と合格条件を定めることで、これらを防ぐ。

## 対象

30枚以上のスライドからなる資料を、新規に作る場合を対象とする。それより少ない枚数の資料は対象としない。工程と承認の回数は、この規模を前提に定める。

## 工程の一覧

| # | 工程 | 範囲 | 成果物 | 最終の承認 |
|---|---|---|---|---|
| 0 | [依頼の確定](stages/00-brief.md) | 全体 | ブリーフ | ユーザー |
| 1 | [探索](stages/01-exploration.md) | 全体 | 探索の計画、仮説の一覧、素材台帳、仕組みの定義 | ユーザー(探索の計画、仕組みの定義)、機械と検査セッション(素材台帳) |
| 2 | [主張の整理](stages/02-claims.md) | 全体 | 問いごとの答え、主張の骨子 | ユーザー |
| 3 | [章立て設計](stages/03-chapters.md) | 全体 | 章構成 | ユーザー(目次と章扉の資料を見て) |
| 4 | [ストーリーライン](stages/04-storyline.md) | 全体 | スライド見出しの一覧 | ユーザー(骨組みの資料を見て) |
| 5 | [立証設計](stages/05-proof.md) | 全体 | スライドごとの立証の設計 | 検査セッションとユーザー(仮置きの資料を見て) |
| 6 | [表現設計](stages/06-patterns.md) | 全体 | 表現の対応表、資料に共通の規則、型の見本、語彙表 | ユーザー(型の見本を見て) |
| 7 | [スライド仕様](stages/07-slide-spec.md) | 章ごと | 章ごとのスライド仕様 | 機械と検査セッション |
| 8 | [全体検査](stages/08-integration.md) | 全体 | 要約版、検査の結果 | 機械と検査セッション |
| 9 | [仕上げ](stages/09-finish.md) | 全体 | PPTX | ユーザー |

最終の承認の前に、各工程の合格条件を全て満たす。合格条件ごとの判定者は、各工程の定義に記す。検査セッションは、執筆とは別に検査だけを行うセッションである([体制とセッション](organization.md))。

工程1と2は往復する。工程2で裏付けのない主張が見つかれば、工程1に戻って調べるか、その主張を捨てる。
