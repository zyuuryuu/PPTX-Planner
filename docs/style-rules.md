# 表現規約

[目次に戻る](README.md)

## 規約の構成

資料の表現技法を一貫させるための規則の集まり。次の2層で持ち、資料の規約は個人の規約を引き継いだうえで上書きできる。

| 層 | 置き場 | 内容 |
|---|---|---|
| 個人の表現規約 | 資料のディレクトリの外 | 資料をまたいで守る規則 |
| 資料の表現規約 | 資料のディレクトリ | 語彙表、表記の規則(単位、日付の書式、文末の形など)、表現の対応表、型ごとの要点の位置、資料に共通の見た目の規則、主張の数と分量の上限(題の字数の上限、1節あたりの枚数の上限 `section_max_slides`、節のまとめを置く境目の枚数 `section_summary_min_slides` を含む)、集計と警告に使う目安の値、往復の上限、その資料だけの規則、規則の例外 |

規則の1件は次の項目を持つ。

```yaml
- id: R007
  rule: 対比の図では、現状を左、提案を右に置く
  reason: 読み手は左から右へ時間が進むと受け取る   # なぜその規則があるか
  check: inspection        # 守らせる方法。structure(構造上、破れない) / mechanical(機械の検査) / inspection(検査セッション)
  issue: "#12"             # 元になった指摘のIssue
  exceptions: []           # 意図して外すスライドと、その理由
```

個人の表現規約の初期値は、次の書き方の禁止と抑制とする。それぞれを上の書式の規則として登録する。機械で検出できるものは、[文章の書き方](writing.md)の辞書に入れて `mechanical` とし、残りを `inspection` とする。

- 禁止: 情報を足さない飾りの形容、読み手が知っている前提の説明、本題の前の前置き、資料自身の狙いや構成を語る文、依頼や検討の経緯を写した文。
- 抑制: 補足のない専門用語と略語、接続詞の代わりに使う矢印や記号。
- 形についての禁止: 意味を持たないアイコン、見た目のために項目の数を揃えること、囲うことに意味のない囲み。根拠は[形が伝える意味](visual-grammar.md)にある。

検査の方法を持たない規則は登録しない。指示するだけの規則は、守られないためである。

規則は、できるだけ強い方法で守らせる。強さの順は `structure`、`mechanical`、`inspection` である。`inspection` の規則は見逃しがあるため、数を絞る。全ての検査を通った後にユーザーの指摘で見つかった問題は、規則を足す前に、より強い方法に上げられないかを検討する。

意図して一貫性を外す場合(最も重要な1枚だけ見た目を変えるなど)は、`exceptions` に理由つきで明示する。明示のない不一致は違反として扱う。

## 規則の追加と整理

規則を足すたびに、既存の規則との整理と統合を行う。

1. **起案**: 指摘から規則の案を作る。
2. **照合**: 既存の全ての規則と比べ、次のいずれかを判定する。

   | 関係 | 対応 |
   |---|---|
   | 重複(同じことを言っている) | 1つにまとめる |
   | 矛盾(両立しない) | どちらを残すかをユーザーが決める |
   | 包含(一方が他方の特殊な場合) | 一般の規則と例外の形に組み直す |
   | 共通の原理がある(個別の規則が複数並ぶ) | 1つの規則に一般化する |

3. **影響の確認**: 整理後の規則を現在の資料に当て、違反になるスライドの一覧を出す。
4. **承認**: ユーザーが、整理後の規則と影響を見て承認する。
5. **反映**: 規則を更新し、違反になったスライドを直す。

整理は規則の数を減らす方向で行う。文章の規則より、表現の対応表や語彙表のような、機械で検査できる構造への組み込みを優先する。

## 語彙表

資料で使う語彙は、語彙表 `terms.yaml` として資料の表現規約に含める。作り方と検査は[使う語彙](terms.md)に定める。
