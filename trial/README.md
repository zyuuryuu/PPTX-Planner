# 試行の記録(第1回)

工程の定義を、実際にLLMに作業させて確かめる。目的は資料の完成ではなく、次の3つである。

1. 工程の定義の欠陥を見つける(書けない成果物、判定できない合格条件、足りない手順)。
2. LLMに作業をさせるときの流れを記録する(誰が誰に何を渡し、どこで止まるか)。
3. 必要な部品を洗い出し、試作する(役割ごとの指示、検査、ビルド、受け渡しの仕組み)。

## 設定

| 項目 | 内容 |
|---|---|
| 題材 | SOCのアナリストによるアラートの解析の方法論 |
| 枚数 | 50枚 |
| 人間役 | Opus 5.5。人物の設定を渡す。設定は、ほかのセッションには見せない |
| 作る側 | Opus 5.5以下のモデル |
| 進行と観察 | このリポジトリの作業をしているセッション。中身は書かない |
| 範囲 | まず設計の時期(工程0から6)。結果をユーザーが見てから、製造の時期に進む |

## 部品の一覧

試行のために必要になった部品を、分かった時点で足していく。

| 部品 | 役割 | 状態 | 置き場 |
|---|---|---|---|
| 機械的な検査 | 合格条件のうち、構造で判定できるものを確かめる | 試作中 | `tools/check.py` |
| 確認用のビルド | 目次、骨組み、仮置きの資料を出す | 試作中 | `tools/build.py` |
| 役割ごとの指示 | 各セッションが読む文書と、守ることを定める | 未着手 | `trial/roles/` |
| セッションの受け渡し | セッションを起こし、成果物と指示をやり取りする | 疎通を確認中 | |
| 人間役の設定 | ユーザーの代わりに答え、承認する人物の定義 | 起案中 | リポジトリには置かない |

## 流れの記録

時系列で、起きたことと、分かったことを書く。

### 準備

- セッションの疎通の確認を開始した。子セッションを Opus 5.5 で起こし、文書の読み取り、ブランチへのプッシュ、親への報告ができるかを確かめる。
