# 描画の道具(tools/render.py)を作る中で見つけた不足

日付: 2026-11-24。担当: 描画の道具の担当。

## スライド仕様の書式、工程の定義に足りない点

1. **1つの事実が複数の値を述べる場合の参照がない。** F207 は value が 0.01 だけで、27%、49%、約24% は statement と qualifiers の文の中にある。工程7は「数値は事実のIDで参照する」とするが、IDだけでは値を選べない。道具では `{fact: F207, as: 27}` とし、数が事実の本文にあるかを照合する形にした。台帳で値を1つずつ事実に分けるか、この書き方を工程7の定義に入れるかを決める必要がある。
2. **図に載せる短い名前が、仕組みの定義にない。** 定義の `name` は原文の語を括弧で添え、つながりの `label`、`condition` は文である(例: 「製品が付けた重大度が High 以上」)。図にはそのまま載らない。道具は、日本語を含まない括弧書きを除いたうえで、スライド仕様の `body.labels` で短い名前を書けるようにした。同じ要素に、スライドごとに違う名前が付きうる(色と名前をそろえる工程7の条件に反しうる)。定義か語彙表に、図に載せる名前の項目を置くことを提案する。
3. **見本の仕様に、描いた内容の一部が書かれていなかった。** 元の見本は手描きで、仕様の `body` にない内容を描いていた(statement の日本語訳、table の調べ方の詳しい説明、tree の当てはめの説明、architecture の群の題と説明、ER の注記、step-flow の説明の改行と色)。`body` の書式を直して全て仕様に書いた(中身の意味は変えていない)。
4. **引用の訳の置き場がない。** F501 の quote は英語で、スライドに載せる日本語訳は台帳にない。仕様の `text` に訳を書いた。訳は裏付けの検査(読み戻しの検査)の対象になるが、工程7の定義は訳を扱っていない。
5. **架空の例の数値の扱いが決まっていない。** ch2-s8 の例「宛先のポートが443」は事実でない数値で、工程7の「事実のIDによらない数値がない」に反する。例外にするかを決める必要がある。
6. **表のセルに、事実の値の言い換えを書く方法が限られる。** ap-s1 の「5,000件未満が45%」は、5,000 が事実の値でないため直接書けない。`{F202:metric}が{F202}` とし、「1日5,000件未満のアラートを受ける回答者の割合が45%」と長くなった。元の見本の「実務者20人」の「20人」(F202 の qualifiers の n=20)も参照できず、「実務者の調査」とした。
7. **章扉の「その章で答える問い」の出どころが決まっていない。** 本論の章は主張の `question`(01-plan の問い)を使った。主張のない章は、章のスライドの `from` の問いを使った(ch1 は Q0)。ch5(演習とまとめ)はどちらもなく、題だけを載せた(診断の警告)。また 01-plan の問いの文は工程の作業用の書き方で、読み手向けではない(Q2.x の「閉じる/調査を続ける/上に上げる」は記号を使い、P007 に反する)。章扉に載せる問いの文の置き場を決める必要がある。
8. **章のまとめを置かない例外(D010)が、機械で読めない。** style.yaml の exceptions は文で書かれている。道具は「章構成の枚数に、扉と中身のほかに1枚の余地があるときだけ章のまとめを置く」と決めた(ch1 は 3枚 = 扉 + 中身2枚で、まとめを置かない)。
9. **出典の一覧の枚数が決まっていない。** 導出のスライドとして、1枚に収まらない分は続きの1枚に送る(今は3枚)。本編の「自動でスライドを分けない」とは別の扱いにした。
10. **表紙、要約のスライドを作っていない。** 表紙の題は style.yaml の metadata の文の中にあり、データとして読めない。要約(02-claims の summary)の置き場所は工程の定義に書かれていない。
11. **flowchart の描き方の範囲。** 道具は「始まりの要素から順に確かめる分かれ目」と、「最後の行き先から出る道2つまで」を描く。それより深い流れは描けない(診断に出る)。資料の流れ図はこの形に収まる。
12. **構成図の向き。** style.yaml は流れを左から右とするが、元の見本の構成図(ch2-s3)は製品の枠からアラートへの「作る」を下向きに描いていた。左から右では横幅に収まらないため、群ごとに `direction: TB` を書けるようにし、見本に書いた。

## 確かめた結果

- 見本10枚を描き直し、元の画像と並べた(`preview/render-check/<型>-compare.png`)。10枚とも同じ情報が読み取れ、診断のエラーは0件。違いは次のとおり。
  - table: 上の6の通り、値の列の文が長くなり、「20人」が落ちた。列の幅はブラウザが決めるため、出典の列が2行になった。
  - er-diagram: 配置が graphviz によるもので、元の見本(分析ルールを集めたデータの上に置く)と違う。つながりとラベルは同じ。
  - architecture-diagram: 製品の枠の題が2行になった。つながりのない記録の注記は「経路は出典にない」の定型にした(元は「製品やアラートとの経路は出典にない」)。
  - flowchart: ひし形を、文字が収まる大きさにした(元の見本は文字がひし形の辺にかかっていた)。調べる段からの2つの道は、元と同じく右(案の基準)と下。
- 収容量は、合成したデータを描いて測った(`tools/patterns-data.md`)。
