# 調査依頼 R5

## 知りたいこと

- Q4.1: 実際の攻撃を誤検知として閉じてしまう誤りは、どんな状況や要因で起きるとされているか
  - 必要な証拠の種類: 事案の調査報告、業界の調査、学術の調査
- Q4.2: 調査を続けたまま上に上げるのが遅れる誤りは、どんな状況や要因で起きるとされているか
  - 必要な証拠の種類: 事案の調査報告、業界の調査、学術の調査
- Q4.3: 上に上げなくてよいアラートまで上げてしまう誤りは、どんな状況や要因で起きるとされているか
  - 必要な証拠の種類: 業界の調査、学術の調査

## 共通の条件

- 返す形式: `docs/stages/01-exploration.md` の素材台帳(`01-sources.yaml`)の書式。`id` から `answers` までを書く。`stance` は書かない。
- 事実のIDは、F500 から始まる連番にする(ほかの依頼と重ならないようにするため)。
- `kind` は、出典のある事実は `fact`。出典を確かめられないものは返さない。
- `quote` は出典の文をそのまま写す。英語の出典は英語のまま写し、`statement` を日本語で書く。
- `metric`(数値を持つ事実で必須)は、まだ語彙表がないため、何の指標かを日本語の短い名詞句で書く(例: 「誤検知の割合」)。後で設計セッションが語彙表の語に置き換える。
- 1つの問いについて、`origin`(元をたどった情報源)が独立した出典を、できるだけ2つ以上集める。公的機関、標準、枠組みの公式の文書などの一次情報を優先する。
- 特定の製品の宣伝を目的とする資料は、一次情報として扱わない。使う場合は、その旨を `qualifiers` に書く。
- 見つからなかった問いは、見つからないと返す。見解が割れている場合は、割れている両方の事実を返す。
- 問いごとの結果(answered / partial / not-found / disputed)を、返事のメッセージに書く。
