5 / 45 ・ ch2-s1 ・ 本編

アラートは、検知の仕組みが探すものを見つけたときの知らせで、本物の攻撃とは限らない

出典: Microsoft Learn(Microsoft Sentinel、Microsoft Defender for Endpoint の文書、2026年)、Yangら(USENIX Security 2024)。1つのSOCのネットワークの検知(Zeek)の2020年12月〜2022年7月のアラート約1,443万件を著者らが分類

  • F709: Microsoft Sentinel は、組織の全体からデータを集めた後、定期的に実行される脅威検知のルール(分析ルール)で、集めたデータに問い合わせて分析する。ルールは探しているものを見つけるとアラートを生成する。アラートは関わる実体(利用者、端末、アドレスなど)を含み、集約と相関によってインシデントにまとめられる
  • F619: Microsoft Defender for Endpoint では、脅威を検知するとアラートが作られ、同じ攻撃の手法や同じ攻撃者によるアラートはインシデントにまとめられる。検知の機能は端末の全ての操作を記録する監査やログの仕組みではなく、センサーには同じ事象の大量の繰り返しを間引く仕組みがある
  • F207: 実SOCの実測では、アラートのうち真の攻撃に関連するのは0.01%。攻撃の試み(侵害に至らなかった攻撃)が27%、正当な業務上の理由がある「良性のトリガー」が49%を占めた

6 / 45 ・ ch2-s2 ・ 本編

SIEMは、最も一般的にはルールで複数のログの記録値を照合し、重要なイベントを特定する

出典: NIST SP 800-92(2006年)。ルール以外の相関もある

  • F100: SIEMは、複数のログ源のデータを分析し、ログ項目間でイベントを相関させ、重要なイベントを特定して優先順位を付ける
  • F101: ログのイベント相関で最も一般的なのは、タイムスタンプ、IPアドレス、イベント種別などの記録値に基づいて複数のログ項目を照合するルールベース相関である

  • F618: Microsoft Defender for Endpoint は、プロセスの情報、ネットワークの活動、カーネルとメモリ管理の深い観測、利用者のログオンの活動、レジストリとファイルシステムの変更などの振る舞いのテレメトリを継続的に集め、6か月保存する
  • F619: Microsoft Defender for Endpoint では、脅威を検知するとアラートが作られ、同じ攻撃の手法や同じ攻撃者によるアラートはインシデントにまとめられる。検知の機能は端末の全ての操作を記録する監査やログの仕組みではなく、センサーには同じ事象の大量の繰り返しを間引く仕組みがある

8 / 45 ・ ch2-s4 ・ 本編

アラートの詳細はOSのログで確かめることが多く、認証のログは通常、接続元と成否を残す

出典: NIST SP 800-92(2006年)。「しばしば」「通常は」の記述

  • F111: OSログは、特定のホストに関する不審な活動の特定と調査に最も役立つ。セキュリティソフトが不審な活動を見つけた後に、詳細を得るために参照されることが多い
  • F108: 認証サーバのログは、認証の試行ごとに、接続元、ユーザー名、成否、日時を記録する
  • F110: OSの監査記録は、認証の成功と失敗、ファイルアクセス、セキュリティポリシーの変更、アカウントの変更、権限の使用などのセキュリティ事象の情報を含む
  • F107: マルウェア対策ソフトの最も一般的な形であるウイルス対策ソフトは、通常、検出した全てのマルウェア、駆除の試み、隔離を記録する

  • F125: ATT&CKでは、技術は、攻撃者が行動を実行して戦術上の目的を達成する「どのように」を表す
  • F610: NIST SP 800-61 Rev.3 は、インシデントのトリアージ、優先度付け、エスカレーション、上位への引き上げ、復旧を始める判断を、一連のリスク評価の要因に基づかせるよう推奨し、要因の例として、資産の重要度、機能への影響、データへの影響、観測された活動の段階、脅威主体の特徴、回復可能性を挙げている

12 / 45 ・ ch2-s8 ・ 本編

誤検知の原因には、弱いルールや緩く書かれたルールなど、検知の条件の誤りがある

出典: NIST の文書(2003年、ネットワーク型の検知)、Alahmadiら(USENIX Security 2022、一部の解析者の認識)。原文の語は signature

  • F208: NISTの文書は、誤検知を『通常の非悪性の背景トラフィックで起きたアラート』と定義し、ネットワークIDSでの原因に、弱いシグネチャ、正当なネットワーク管理ツールのトラフィックを挙げる。誤検知率はネットワーク環境ごとに異なることがある
  • F214: SOC実務者の一部は、シグネチャが『緩く(広く)書かれている』ことで多くの誤検知が出ると述べた

出典: Yangら(USENIX Security 2024)。1つのSOCのネットワークの検知(Zeek)の2020年12月〜2022年7月のアラート約1,443万件を著者らが分類

  • F217: 同SOCで、SSLの弱い鍵・弱い暗号・旧版に関するアラートは、主にレガシーシステムに起因し、変更が難しい、または無視して安全と判断されていた

25 / 45 ・ ch3-s12 ・ 本編
