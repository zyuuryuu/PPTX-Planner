# 型ごとのデータの書式と収容量

スライド仕様(`07-slides/<章>.yaml`、`06-samples/*.yaml`)の `body` に書くデータの書式と、描画の道具 `tools/render.py` の描き方。書式の正本は [工程7](../docs/stages/07-slide-spec.md)である。ここには、正本に定めがなく、道具が決めたことを書く。

```
python3 tools/render.py <資料のディレクトリ> --pdf           全スライドを描く(build/ に deck.html、deck.pdf、slides/*.png、diagnostics.json)
python3 tools/render.py <資料のディレクトリ> --samples       型の見本(06-samples/)だけを描く(build/samples/)
python3 tools/render.py <資料のディレクトリ> --chapter ch2   その章のスライドだけを描き直す(付録は appendix)
python3 tools/render.py <資料のディレクトリ> --only ch2-s3 --no-png   1枚だけ描き直し、診断だけを見る
python3 tools/build.py  <資料のディレクトリ> --level toc|skeleton|placeholder [--pdf]   確認用の資料(build/<level>/)
python3 tools/render.py --patterns                          描ける型の一覧
```

依存: Python 3、PyYAML、Pillow、Node.js と Playwright(Chromium)、フォント IPAPGothic。構成図とER図には graphviz(`dot`)も要る。

## スライドの枠

どのスライドも、同じ枠で描く。大きさは 1280×720px(16:9)。読む順が、題、要点、中身、脚注の順に、位置と大きさで決まる。

| 部分 | 位置 | 大きさ | 描くもの |
|---|---|---|---|
| 題 | 最上部 | 36px、太字、1行 | `title`。2行になると診断に出る |
| 要点 | 型ごとの位置に1か所だけ | 27px、太字、2行まで(中身そのものの位置では 34px) | `point`。`point_from: section` のスライドでは、章構成の節の要点。要点のないスライドでは、場所を空けない |
| 中身 | 題と要点の下 | 本文 24px、図の中 22px、注記 19px | 型のデータ(`body`)と、その下に説明(`text`) |
| 脚注 | 最下部。線で区切る | 19px、灰色 | 限定(`qualifiers`)、出どころ(`provenance`)、出典。右端にページ番号 |

- 要点の位置は、資料の表現規約の `point_position` から、型ごとに決める。型の指定、`default`、型の定義の `point_position`、`below-title` の順に探す。
- 位置が「中身の下」(`below-body`)の要点は、中身と脚注の間に描く。「中身そのもの」(`body`)の要点は、中身として描き、ほかの行に繰り返さない。
- 限定と出どころは、資料の型の定義の `annotation` が定める場所に描く。`footnote` は脚注、`notes` はノート(`deck.html` のスライドの下と `diagnostics.json` に出す。スライドには描かない)、`mark` は題の行の右端の小さな印(出典、案、運用)。`none` の出どころは描かない。資料の型を決められないときは、限定を脚注に描き、出どころは描かない。
- 出典は、スライド仕様の `sources` の事実の `source` を、重複を除いて脚注に並べる。導出した事実(`source` がない事実)は、`formula` に書かれた事実の出典をたどる。出典の位置(`locator`)は載せない。
- 文の中の参照は、描くときに置き換える。`{F016}` は事実の値と単位、`{F016:value}` は値だけ、`{F016:unit}` は単位、`{F016:metric}` は語彙表の語、`{ch1-s2}` はそのスライドの題。先のない参照は、診断に出す。
- スライドのID、事実のIDなどの内部のIDは、スライドにも、`deck.html`、`deck.pdf` にも出さない。残っていれば診断に出す。`--show-ids` を付けたときだけ、`deck.html` のスライドの外の見出しにIDを出す(作業用)。
- 章と節の現在地は描かない。置く位置の定めが docs にないためである。
- 強調は、スライド仕様の `body.highlight` が指す1か所にだけ付ける。太い黒の線(5px)で囲み、文字を太字にする。色の割り当てがない面(円グラフ、棒グラフ)では、強調する面を濃い灰色にする。

## 自動で作るスライド

| スライド | 置く条件と場所 | 載せるもの |
|---|---|---|
| 目次 | 先頭 | 章と節の題。付録と出典の一覧があれば、その行 |
| 出どころの印の説明 | `annotation` の `provenance` が `mark` の資料。目次の次 | 印と、その意味(出典のある事実、案、今の運用) |
| 章扉 | 章の先頭 | 章の題と、その章で答える問い(`question`)。目次と章扉の資料では、章の要点と、節の題と要点も載せる |
| 節のまとめ | 節の項の数が `limits.section_summary_min_slides` 以上の節。節の最後 | 題は節の題。要点は節の要点。中身に、節内のスライドの要点を順に並べる |
| 章のまとめ | 節が2つ以上ある章。章の最後 | 題は章の題。要点は章の要点。中身に、節の要点を順に並べる |
| 付録の扉 | 付録のスライドがある資料。付録の前 | 「付録」 |
| 出典の一覧 | 最後。1枚に収まらなければ、続きの1枚に送る | 出典の名前と、使ったスライドのページ番号 |

- 節の要点を引くスライド(`point_from: section`)は、節の要点を、そのスライドの型の要点の位置に描く。限定は、節の `qualifiers` を使う。
- まとめのスライドは、承認済みの文をそのまま並べる。載せた要点の限定を、置き場(脚注かノート)にまとめる。
- 表紙と要約のスライドは作らない。表紙に載せる資料の題の出どころと、要約を置く位置の定めが docs にないためである。

## 確認用の資料と、スライド仕様のないスライド

| 資料 | 各スライドに載るもの |
|---|---|
| 目次と章扉(`--level toc`) | 目次と、章扉(章の題、問い、章の要点、節の題と要点) |
| 骨組み(`--level skeleton`) | 題、要点、根拠の事実の `statement`。限定と出どころ。目次、章扉、節のまとめ、章のまとめ、出典の一覧 |
| 仮置き(`--level placeholder`) | 題、要点、図の型の仮置き(「ここに円グラフ」、見せるもの、注目させる点)。ほかは骨組みと同じ |

- 骨組みと仮置きでは、節の要点を引くスライドの要点に「節の要点」の札を、要点のないスライドに「要点なし(役割: 詳しい説明)」の札を付ける。完成形には付けない。
- 全スライドを描くとき、スライド仕様がないスライドと、保留(`status: blocked`)のスライドは、立証の設計があれば仮置きを、なければ骨組みを描く。骨組みの資料の章を、実物に差し替えていく形になる。

## 資料の表現規約から読む項目

docs に項目の名前がないものは、道具が決めた。

| 項目 | 内容 | ない場合 |
|---|---|---|
| `point_position` | 型ごとの要点の位置([工程6](../docs/stages/06-patterns.md)の例の通り) | 型の定義の既定 |
| `limits.section_summary_min_slides` | 節のまとめを置く境目の枚数 | 節のまとめを置かない |
| `common.font_min` | 文字の大きさの下限。`title`、`point`、`body`、`figure_text`、`note`、`footnote` | 24pt、18pt、18pt、16pt、14pt、14pt |
| `common.colors` | 色の割り当て。対象の名前から色(`'#2563EB'`)への対応 | 灰色で描く |
| `common.max_hues_per_slide` | 1枚で使う色相の数の上限 | 4 |

## 全ての型に共通

型のデータは `body.data` に書く。型の名前は `body.type`、強調する要素は `body.highlight` に書く。画像の型は、工程7の例の通り、`asset`、`crop`、`scenario`、`captions` を `body` の直下に書く。道具は、項目を `body.data`、`body` の直下の順に探す。

数値は直接書かず、事実を参照する。値を取る項目(`value`)には、事実のID(`F207`)を書く。1つの事実が複数の値を述べるときは、`{fact: F207, as: 27, round: 0}` と書く。`as` の数は、事実の `statement`、`quote`、`qualifiers` にあること。`round` で丸め、値が変われば「約」を付ける。

仕組みの定義を参照する型(`flowchart`、`er-diagram`、`architecture-diagram`、`annotated-image-steps`)は、要素とつながりの名前を定義から引く。順は `labels` の指定、語彙表の `model_labels`、定義の `name`(日本語を含まない括弧書きを除く)。

## 収容量の前提

下の収容量は、題が1行、要点が2行(60字)、脚注が1行、説明(`text`)がない場合(中身に使える高さ約455px)に、合成したデータを描いて、診断のエラーが出なかった最大の値である(字数は全角)。要点が1行なら約38px、要点がなければ約85px、高さが増える。説明が1行あれば約53px減る。収容量の内でも、文によっては診断に出る。最後は診断で確かめる。

## statement(言い切り)

要点の位置は「中身そのもの」(`body`)を既定とする。要点の文を、中身として大きく描く。

| 項目 | 必須 | 内容 |
|---|---|---|
| `value` | 任意 | 大きく示す1つの値。値と単位を 96px で描く |
| `text` | 任意 | `value` の説明。値の下に添える。`value` も要点もないスライドでは、言い切る文として描く |
| `bound` | 任意 | 値の後ろに付ける語(以上など) |
| `quote_of` | 任意 | 引用元の事実のID。事実の `quote`(または `text`)を、引用として「」で囲んで描く |
| `attribution` | 任意 | 引用の下の説明 |
| `caveat` | 任意 | 但し書き |
| `highlight` | 任意 | `value`、`point`、`text`、`caveat` のいずれか |

収容量: 要点は68字まで(2行)。`value` を使う場合、`text` は50字まで、`caveat` は48字まで。

```yaml
body:
  type: statement
  data:
    value: F003
    text: 応答率が前の年度から下がった幅
  highlight: value
```

## plain-list(箇条書き)

枠なしの縦の並び。

| 項目 | 必須 | 内容 |
|---|---|---|
| `items` | 必須 | 項目の並び。項目は文字列、または `{text, sub: [下の項目]}` |
| `title` | 任意 | 一覧の題 |
| `highlight` | 任意 | `title` か `items[番号]` |

収容量: 9項目まで(各1行、42字まで)。2行になる項目(80字まで)なら4項目まで。

## step-flow(段階の流れ)

| 項目 | 必須 | 内容 |
|---|---|---|
| `steps` | 必須 | 段の並び。段は `{name, description, next}` |
| `steps[].name` | 必須 | 段の名前。番号は自動で付く |
| `steps[].description` | 任意 | 文字列、または段落の並び。段落は文字列か `{text, color}`(`color` は色の割り当ての名前) |
| `steps[].next` | 任意 | 次の段への矢印に添える語 |
| `numbering` | 任意 | 番号の始まり。既定は1。`null` で番号なし |
| `highlight` | 任意 | `steps[番号]` |

収容量: 5段まで。説明は、3段で80字、4段で60字、5段で30字まで。名前は16字まで(8字を超えると折り返す)。

## cause-chain(因果の連鎖)

| 項目 | 必須 | 内容 |
|---|---|---|
| `chain` | 必須 | 原因から結果への順の並び(2つ以上) |
| `link` | 任意 | 矢印に添える語。既定は「ので」 |
| `example` | 任意 | 図の下の1行 |
| `highlight` | 任意 | `chain[番号]` |

収容量: 4つまで。1つは60字まで。

## pie-chart(円グラフ)

| 項目 | 必須 | 内容 |
|---|---|---|
| `data` | 必須 | `{label, value, bound}` の並び |
| `highlight` | 任意 | `label` の1つ |

単位が % の場合、合計が100%にならなければ診断に出す。色の割り当てがない項目は、灰色の4段階で描き分ける。

収容量: 5項目まで(強調する1項目と、灰色の4項目。強調がなければ4項目)。ラベルは24字まで。

```yaml
body:
  type: pie-chart
  data:
    - {label: 応答した着信, value: F001}
    - {label: 応答できなかった着信, value: F015}
  highlight: 応答できなかった着信
```

## bar-chart(棒グラフ)

横の棒を、上から並べる。量の軸は0から始める。値は棒の右に書く。

| 項目 | 必須 | 内容 |
|---|---|---|
| `data` | 必須 | `{label, value, bound}` の並び。単位は全て同じにする |
| `highlight` | 任意 | `label` の1つ |

収容量: 6項目まで。ラベルは20字まで(13字を超えると2行になる)。

## before-after(前後の対比)

前を左、後を右に置き、矢印でつなぐ。

| 項目 | 必須 | 内容 |
|---|---|---|
| `before`、`after` | 必須 | `{label, value}` または `{label, text}`。`value` は大きく描く値、`text` は文 |
| `highlight` | 任意 | `before` か `after` |

収容量: ラベルは40字まで。`value` は5桁と単位1字まで(「99,999件」)。`text` は98字まで。

## table(表)

| 項目 | 必須 | 内容 |
|---|---|---|
| `columns` | 必須 | 列の名前の並び。列は文字列か `{name, align}`(`left`、`right`) |
| `rows` | 必須 | 行の並び。行はセルの並び(列と同じ数)。セルは文字列(`{F...}` の参照を含めてよい)か、事実のIDだけ |
| `highlight` | 任意 | `columns[番号]`、`rows[番号]`、`cells[行][列]` |

全てのセルが事実の参照で始まる列は、右に寄せる。

収容量(行の数。見出しの行を除く):

| 列の数 | セルが6字 | 10字 | 16字 | 24字 | 40字 |
|---|---|---|---|---|---|
| 2 | 8 | 8 | 8 | 8 | 5 |
| 3 | 8 | 8 | 5 | 5 | 3 |
| 4 | 8 | 8 | 5 | 4 | 描けない |
| 5 | 8 | 5 | 4 | 3 | 描けない |
| 6 | 8 | 5 | 3 | 描けない | 描けない |

## tree(階層の木)

| 項目 | 必須 | 内容 |
|---|---|---|
| `root` | 必須 | 根の名前 |
| `children` | 必須 | 子の並び。子は文字列か `{name, children}` |
| `levels` | 任意 | 階層ごとの見出し(1つ目が根の子の列) |
| `aside` | 任意 | 木の右に置く説明 `{text}`。破線の枠で描く |
| `highlight` | 任意 | 節の名前(木の中で1つだけのもの) |

収容量: 葉(子のない節)が6つまで。名前は20字まで。階層は3段まで(根を含む)。

## annotated-image-steps(注釈つきの画像、番号の印)

画像の素材を、`crop` の範囲が入るように切り抜いて左に置き、`regions` の位置に枠と番号の印を重ねる。説明は、画像の右に番号の順で並べる。印は、指す範囲の外に置く。

| 項目 | 必須 | 内容 |
|---|---|---|
| `asset` | 必須 | 画像の素材のID |
| `crop` | 任意 | 切り抜く範囲に入れる `regions` の `id` の並び。省くと画像の全体 |
| `scenario` | 任意 | 仕組みの定義の場面。番号は、場面のつながりが指す要素の順から決まる。省くと `captions` に書いた順 |
| `captions` | 必須 | `regions` の `id` から説明への対応 |

収容量: 説明は、17字まで(1行)なら8件、20字なら5件、34字なら4件、51字なら3件まで。

## flowchart(分岐のある流れ)

仕組みの定義の場面(`route` のつながり)から描く。

| 項目 | 必須 | 内容 |
|---|---|---|
| `scenario` | 必須 | 場面のID |
| `start` | 任意 | 始まりの要素。既定は場面の最初のつながりの `from` |
| `labels` | 任意 | 図に載せる短い名前。要素は `ID: 名前`。つながりは `ID: {condition: 分かれ目の問い, label: 行き先の札}` |
| `proposal_parts` | 任意 | 案の部分のつながり。破線で描く |
| `highlight` | 任意 | つながりか要素のID、または `{ids: [ID, ...], label: 枠の上の語}`(隣り合う分かれ目をまとめて1つの枠で囲む。1か所と数える) |

描き方: 始まりから出る道を `order` の順に、分かれ目(ひし形)として左から右に並べる。「はい」の行き先は下に出す。最後の道は「いいえ」として次の要素に進む。その要素から出る道は2つまで描ける。これより深い流れは描けない(診断に出る)。

収容量(前の配置で測った値。今の配置では測り直していない): 始まりから出る道は、分かれ目の問いが約10字、行き先の札が約18字なら4つまで。

## er-diagram(要素の関係)、architecture-diagram(構成図)

仕組みの定義の要素とつながりを引き、graphviz で置く。

| 項目 | 必須 | 内容 |
|---|---|---|
| `elements` | 必須 | 要素のID。立証設計の `view` にあるものだけ |
| `relations` | 必須 | つながりのID。両端が `elements` にあること |
| `labels` | 任意 | 短い名前(要素、つながり)。つながりを `''` にするとラベルなし |
| `annotations` | 任意 | `要素ID: 文`。要素のすぐ下に添える |
| `details` | 任意 | `要素ID: [項目]`。要素の箱の中に、名前の下に一覧で描く |
| `direction` | 任意 | `LR`(既定、左から右)か `TB`(上から下) |
| `groups` | 任意(構成図だけ) | `{title, elements, caption, direction}` の並び |
| `highlight` | 任意 | 要素かつながりのID。構成図では `groups[番号]` も |

流れのつながり(send、produce、notify、aggregate、route、retrieve)は矢印で、そのほかは矢印のない線で描く。構成図では、contain は含む側を枠にする。どのつながりにも出ない要素は、図から離して右に置き、「経路は出典にない」と添える。

収容量(前の配置で測った値。今の配置では測り直していない): 左から右に1列につなぐ場合、名前が約4字なら4つ、約8字以上なら3つまで。

## まとめ、目次、出典の一覧

- 節のまとめと章のまとめ: 並べる要点が1行(48字まで)なら10件、2行(60字)なら6件まで。
- 目次: 章と節の行が1段に収まらなければ、2段にする。1段で約13行、2段で約26行が目安である(測っていない)。
- 出典の一覧: 収まらない分は、続きの1枚に送る。

## 描画上の診断

`diagnostics.json` と標準出力に、スライドごとに出す。エラーが1件でもあれば、終了コードは1になる。

| 種類 | 重大度 | 内容 |
|---|---|---|
| `overflow` | エラー | 中身が中身の領域に収まらない。枠に文字が収まらない。左右の余白を越える。図の幅や高さの超過 |
| `title-lines` | エラー | 題が1行に収まらない |
| `point-lines` | エラー | 要点が2行を超える |
| `font-too-small` | エラー | 文字の大きさが下限より小さい |
| `overlap` | エラー | 図形どうし、図形と文字の重なり。注釈の印を、指す対象の外に置けない |
| `unrendered` | エラー | 描けなかった内容(参照先がない、書式の誤り、型の描画がない、題がない) |
| `emphasis` | エラー | 強調が1枚に2か所以上ある(`highlight` の指定の数と、描いた強調の数) |
| `duplicate` | エラー | 要点が2か所に描かれている。要点の文が1枚の中に2回出ている |
| `internal-id` | エラー | 読み手に見える文に、内部のIDか、置き換えていない参照が残っている |
| `contrast` | エラー | 文字と背景の色の差が小さい(コントラスト比が 4.5 未満。24px 以上か、太字で 18.7px 以上の文字は 3.0 未満) |
| `adjacent-contrast` | エラー | 隣り合う面の色の差が小さい(コントラスト比が 1.3 未満) |
| `hue-count` | エラー | 1枚で使う色相の数が上限を超える |
| `data` | エラー | 構成比の合計が100%にならない。単位の違う値を1つの軸に並べている |
| `word-break` | 警告 | 語の途中での折り返し(語の区切りは Chromium の Intl.Segmenter で判定する) |
| `footnote-lines` | 警告 | 脚注が2行を超える |
| `reference` | 警告 | 参照した事実が、スライドの `sources` にない |
| `layout`、`role` | 警告 | 図の配置を変えた。役割のない文字がある(道具の誤り) |
| `placeholder`、`image-scale` | 情報 | スライド仕様がなく仮置きか骨組みを描いた。画像を拡大して描いた |

色の差と色相の数の基準は、docs に値がないため、道具が決めた。

### diagnostics.json

`tools/check.py` が読む。

| 項目 | 内容 |
|---|---|
| `level` | 描いた資料。`full`、`samples`、`toc`、`skeleton`、`placeholder` |
| `inputs_hash` | 描画が読んだ成果物の要約値。`check.py` が、診断が今の成果物のものかを確かめる |
| `count` | 全体の枚数 |
| `measures` | 診断に含めた測定(`text-contrast`、`adjacent-contrast`、`hue-count`) |
| `patterns` | 描ける型の一覧 |
| `slides[]` | スライドごとに、`id`、`no`(ページ番号)、`kind`(区分)、`chapter`、`mode`(`spec`、`placeholder`、`skeleton`、`auto`)、`type`、`title` と `point`(描いた結果から抜き出した文)、`colors`(文字と背景の色の差の最小、隣り合う面の色の差の最小、色相の数)、`emphasis`、`notes`、`inputs_hash`、`diagnostics`、`wraps`(図の中の文字を折り返した位置) |

| 検査 | 読むもの | 不合格にするもの |
|---|---|---|
| `K06-06` | `build/samples/diagnostics.json` の `patterns` | 表現の対応表の型が、描ける型の一覧にない |
| `K06-11` | `build/samples/diagnostics.json` | 見本のスライドに、エラーの診断がある |
